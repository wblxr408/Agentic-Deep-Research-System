# 工作台评价与分层权重

组织研究模式下的“研究偏好与评价”面板复用已有评价、权重与个人预设 API。主维度、成果表现子组、指标组内比例和等级偏好分别配置；选择对象和信息渠道仍独立。比例用于表达偏好，不修改硬条件或证据事实，也不表示已经对本次成果完成评价或评分。

## 编辑与生效值

初始值从 `GET /api/v1/research/weights/catalog` 读取，返回同一版本的操作员预设及归一化预览，避免界面复制一套默认数字。研究发展与合作发现可选择、编辑并恢复。六个维度、载体／论文指标子组与各评价体系提供数值和启停，停用保留原值。清空指标配置表示尚未选择指标，与配置后全部停用不同。

界面检查空值、负数、非有限值及活动层全零；随后调用原 `POST /weights/preview` 校验完整契约和各层归一化。连续输入合并约 250 毫秒，取消过期请求，只有与当前输入一致的响应可以显示为生效值。正在校验、请求失败或非法配置都阻止创建研究；不会沿用上一份合法配置提交。

主维度比例、成果表现内子组比例、指标组内比例分别显示，不把组内 75% 当成全报告贡献 75%。等级映射可编辑原体系的各档分值与映射版本，仍须保持档位顺序及 0–1 范围；它是版本化产品偏好，不是不同体系之间的官方换算。

## 个人预设

个人预设列表来自认证 owner 的既有 `/presets` API。保存为新预设创建 v1；编辑已选择方案后可保存新版本，使用 `expected_version` 拒绝过期覆盖。恢复所选方案回到读取的该版本。未保存编辑作为直接配置提交，不修改原方案；选择已保存方案时向研究请求传递精确 `preset_id` 和 `version`，不同时发送 `weights`。

运行中的“已选个人预设”标识显示实际固定版本；保存不会改写旧研究。读取／保存失败保留当前编辑，显示错误和允许的重试动作，不自动切换到别人的方案或覆盖新版本。底层隔离、版本和冻结规则见[个人预设 ACI](personal-research-presets.md)与[运行契约](organization-research-runtime.md)。

## 适用性与精确查询

`POST /api/v1/research/evaluation/applicability` 输入 1–20 个学科及一个合法成果类型，返回 20 项体系的适用性、原因、部分公开来源版本和授权导入要求。该操作没有成果身份，不查具体载体，也不虚构 ID；`exact_identity_checked: false`。`computer_science` 与 `computer science` 以同一计算机学科别名处理。

指定载体／论文时，可填规范 ID、发表年和评价年，通过原 `POST /evaluation/preview` 查询已保存的部分目录样本。界面区分“不适用”“来源不可用”“样本未覆盖”“明确未收录”“记录冲突”和“有匹配记录”，保留原值、类别、来源及版本。修改输入后，旧查询结果不再作为当前结果显示。

没有授权数据时显示导入要求；有部分公开样本也不表示任意成果都有指标。当前评价查询单独预览，不直接把查询目标的等级套给本次研究取得的其他成果。跨情境的指标偏好可保留，但不适用时明确说明；真正的匹配计算仍须检查成果类型、学科及共同口径。

## ACI 与执行边界

新增两个接口由原认证依赖保护，输入非法返回 422；使用固定服务端配置路径，不接受本地路径、owner 或网络授权覆盖。它们只做本地计算和目录读取，不联网、不调用模型、不新增表。权重预览、保存与研究创建仍是各自明确动作；模型和工具费用只在实际研究中产生，按原预算处理。来源故障不触发隐式出站重试。

沿用 A2ABreak 基线 v1.0 的既有 11 项适用性评估，无新增 Agent／A2A 拓扑。相关方案及“工程解决方案／验收办法”引用仍为 **A2AB-03／上下文归属与跨租户隔离**、**A2AB-06／并发状态版本与审批绑定**、**A2AB-08／结构化授权请求与权限不放大**：owner 由服务端绑定、更新比较已有版本、选择偏好不扩大权限。详细出处与已验证／未验证范围见[运行 ACI](organization-research-runtime.md#a2abreak-引用与本次边界)，不将方案引用视为整套安全验证通过。
