## 1. 采用的结构

续作进度：指定来源的完整成员投影已接原质量接口、phase范围关联和报告结构化corpus，来源／作品、原范围判断与字段导读分别显示。缺失或未筛选成员不会被已纳入成果覆盖，见[ACI的成员状态合同](rag-corpus-api.md#全部成员与范围阅读状态的关联)。专用界面、报告清单及完整成员交付裁决、问题所需分级合同、补窗／私有定位和自动补源／跨绑定增量仍待后续接合，不能把状态展示当作100篇已完成。

现有RAG资料库承接论文目录和证据材料，目录视图、来源原文及检索片段共享当前PostgreSQL。筛选／阅读／补证状态复用原任务与版本化产物记录，按来源引用接合，不以另一个本地JSON目录作为执行权威。JSON／CSV保留为导入、导出或历史原件。

处理顺序为：公开检索或本人提供材料 → 原资料接入／来源版本 → RAG资料库中的论文目录与原文 → 逐项筛选与分级导读 → 缺字段补证 → 问题／主题深度综合 → 内容与图需求计划 → 正文、附录、模块图／事件时间轴／数据图及论文图块 → 当前必要审核与实际交付。

指定语料集合需要按确定的成员与状态逐项枚举，同时按需检索其中的证据。检索top-k只提供当前相关片段，不能证明指定100篇已全部处理。普通公开研究继续按当前联网默认和可选内部检索合同；本次由用户选择采用RAG管理的语料集合在原范围内接合，不把所有研究强制变成先查内部资料。

## 3. RAG中存什么，状态放在哪里

下列是拟议逻辑合同，不是已存在的全部字段或新DDL。优先在原来源metadata、任务运行JSONB和产物记录扩展；关系／查询确有要求时才补最小索引或结构，不增加新数据库。

| 数据 | 现有承载与内容 | 关键边界 |
|---|---|---|
| 目录／语料成员 | 原来源与metadata关联作品、DOI／URL别名、题名、作者／机构、日期类型、会刊、采集请求／页、来源版本；任务快照保存所需成员及研究范围 | 一篇作品可有多个来源／正式版本；合并须有身份依据，目录行不冒充全文 |
| 摘要／原文／图文 | 原来源文本、解析版本、章节／页／字符范围、图注、原件／图资产及索引代际 | metadata-only、abstract、fulltext分别标注，原件可用与实际阅读分别记录 |
| 筛选判断 | 逐作品＋问题／政策版本的纳入、排除、待定、理由、依据类型和引用位置 | 未纳入项仍有目录记录和原因；相关性不等于事实支持，过时规则不自动适用新问题 |
| 阅读／补证 | 原phase／技术卡／根运行记录保存所需层级、实际层级、已完字段、缺字段、定位、尝试／消费、后续动作和完成原因 | 已入库、已索引、已筛选、已导读、已核验独立；摘要导读不升为全文精读，未知派发不当成未执行 |
| 分析卡／主题判断 | 原技术卡、研究判断与依赖作为派生产物；需要检索时通过现有索引适配，标记派生类型与实际来源引用 | 模型卡可供导航／综合，最终来源核验仍读取原文；卡片不能作为独立原始事实来源给自身作证 |

原`list_sources`已有按本人／分组列资料和summary元数据投影，现新增同一资料API下的`sources/catalog`受控分页，过滤作品、记录类型和来源状态；任务筛选／阅读状态仍待接合。原`retrieval_filters`新增work_id／record_kind的固定表达式，其余逻辑字段不能冒充已经可用，不允许任意客户端SQL条件。目录枚举按本人，任务证据检索继续复核owner／范围／权限；目录可见不直接授予任务读取权。

原始API分页响应或旧JSON可保存为溯源输入，索引优先论文级题名／摘要等可定位材料，不把整个目录响应当作单篇论文事实。更新筛选状态不反复切块／嵌入未变全文；目录、原文和派生卡分别保留版本及依赖。

论文目录条目可以作为实际题名／书目／已取得摘要构成的来源记录进入现有资料库，再关联原稿版本；不要求先有PDF才可入目录，也不填造全文。目录视图可枚举排除／待定／未索引项，任务检索使用当前问题及所选材料范围，两者共享来源身份。

旧字段适配：`inventory.reading_id`只保留为历史ID；`title`／DOI／来源链接按原身份合同关联作品及来源版本；旧TSV“编号、结论、研究类型、主要贡献、复核理由”保存历史政策下的判断；packet的`pages[].page/text`与`figures[].caption/page`提供原文／图注线索。`reading_packets.py`的`figures[].bbox`来自图注文字块，不能当作目标图区域；图块定位仍由原R8／12.9补齐。旧本地路径只作溯源，不替代实际资产接入。

## 4. 接入、缓存与后续工作

目录获取复用键绑定实际供应方、查询／对象／时间范围、分页位置、采集版本和时效；旧脚本“文件存在即复用”只保留为历史方法，不用于新任务有效性判断。已有有效来源按当前生命周期复用，变更才增新版本；目录分页失败保留已完成部分，不能用缺页目录推断全部检索完成。

先沿现有入口读取RAG集合的目录状态，再对缺失或变更的论文补摘要／全文／字段；补证返回同一作品对应的版本化来源，失效只传播至依赖的卡片、主题、结论、图及必要审核。图块失败不重写正文，摘要补成全文也不直接把旧判断改成supported。

用户指定100篇全部精读时，先冻结100个作品／成员快照，逐项调度且保存字段状态；RAG检索只帮助选证据窗口。不同主题综合保留必要条件与反例；报告主文推进判断，逐篇证据进入可追溯附录。所需模块图、事件时间轴、数据图与论文独立图块按[可视化计划](REPORT_VISUALIZATION_PLAN.md)覆盖，不能被目录规模或top-k选择静默省略。

跨研究复用使用现有task／group／owner范围和当前授权；本次确认用RAG承接目录，不等于把所有任务资料自动公开、复制到所有分组或给旧分析授予新任务的审核批准。原来源撤销／版本更新时检索和依赖产物同步失效，已有历史仍保留。普通公开研究的联网默认与内部检索可选性保持原合同。
