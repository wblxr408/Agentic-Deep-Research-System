# 研究执行控制与实时反馈

工作流顶部显示任务状态、停止原因和可执行操作；画布下方默认展开 SSE 执行反馈。画布呈现依赖关系，执行反馈呈现实际角色、子问题、工具输入、返回摘要和错误。

## 页面操作

| 当前状态 | 操作与结果 |
| --- | --- |
| 正在运行 | 点击“暂停”，当前图步骤结束并保存后停止后续调度；期间显示“暂停中” |
| 由你暂停 | 点击“继续研究”，从保存的下一图节点继续，沿用原资料、已用额度和起始期限 |
| 系统停止 | 显示具体原因；符合原恢复条件时显示“继续分析／生成报告”，其他情况可“调整后重新开始” |
| 等待／运行／暂停 | “终止”停止本次任务；再次研究通过独立配置创建新任务 |
| 已结束 | “调整后重新开始”打开原请求配置；预览并确认后才创建新研究 |

手动暂停以图步骤为边界；一个步骤内部可能包含多次模型或工具调用。这轮没有实现中断单个远端请求并在其中间字符位置继续。暂停后原总期限仍计时；已到期限或用完额度时，继续会返回明确错误，用户可调整配置另起任务。

截图中的历史任务 `5f001131-0143-47a7-af9d-74c04549b286`，记录为 `report_paused / final_report_needs_revision`，用量 20,423／60,000。它是报告检查要求修订后的系统停止，并非用户按下暂停，也不是总 Token 已耗尽。该任务未满足旧报告原位续作条件，因此展示原因及调整后重启入口；没有绕过原恢复规则自动重跑。

## 系统主动排查停止原因

系统停止后自动整理已有证据，页面直接显示：停止在哪个阶段、发现了哪些具体问题、已经采取的恢复动作，以及需要用户决定的事项。诊断不调用模型，不要求用户翻运行记录。历史任务读取时也会得到诊断；缺少结构化错误的旧任务明确标为排查未完成，不猜测根因。

- 报告未通过核对：直接列出主张及补证／修订要求，前三项默认展开，其余按需展开，单次最多展示 100 项。说明原流程是否已尝试修订，不把核对失败说成总 Token 用完。
- 上下文问题：区分没有原文片段进入当前问题、阶段份额不足、模型上下文容量不足、总额度耗尽。输入加预留输出超过阶段份额时直接给出所需和可用数额，不能建议靠更换大上下文模型增加份额。
- 配置或访问问题：明确需要更新本账号模型凭证、选择模型、选择可访问资料或作出操作授权；系统不自动扩大权限。
- 明确的临时分析服务错误：仅对已保存的 APIConnectionError、APITimeoutError、InternalServerError、RateLimitError，且仍有合法分析检查点的当前图执行，自动恢复至多一次。原阶段最多两次、总额度、模型绑定、起始时间及资料范围保持。
- 自动恢复前再次核对下一次输入预估和 8192 Token 输出需求、原分析份额、原期限、在途用量、owner/execution 和用户暂停请求。条件不足时不派发，直接显示具体缺口。读取历史任务不会启动恢复，也不会声称恢复正在执行。

自动恢复是现有图中的确定性步骤 `automatic_recovery`，不是新增 Agent；只重新进入 Analyst 的既有检查点流程。`session.automatic_recovery_attempts` 随手动继续保留，不能通过继续按钮清零。用户主动暂停、认证／权限拒绝、报告质量问题和硬额度限制不会进入该自动重试。

运行快照和失败记录保存诊断，任务 GET 返回 `pause_diagnosis`；SSE `state_update` 推送诊断与恢复动作，前端据此更新运行状态和事件列表。具体主张／错误仍经原公开投影；新字段不进入报告正文。

此增量沿用 A2ABreak v1.0：A2AB-03《上下文归属与跨租户隔离》工程1—3，A2AB-04《长连接撤权与事件出口鉴权》工程1—3，A2AB-06《并发状态版本与审批绑定》工程1／3，A2AB-10《委派环路检测与全链预算》工程1／3，A2AB-11《中断任务租约与有界资源回收》工程1／4。知识库精确条目和原11项适用性见下方表格。新执行点为 `research_recovery.automatic_recovery_node`：可信 owner/execution 行锁、资料及输入绑定复核、原额度准入、根尝试次数保留、用户暂停优先；事件出口继续走既有 gate。

实际证据见[自动诊断与有限恢复操作](acceptance/stop-diagnosis-20261026.md)。它证明本次局部业务路径，未重跑完整安全／撤权攻击或付费研究。

## 实时反馈

- 原生 EventSource 继续连接原 `/api/v1/research/stream/{session_id}`；界面区分在线推送、重连和已结束记录。
- Agent 开始／结束、工具调用／返回／错误、分析子阶段、工作流开始和真实终态直接显示。分析阶段名称使用研究布局、研究演进等实际业务名称。
- 工具节点使用具体搜索词或网页名称。点击节点仍可读完整输入；实时节点状态沿事件中的节点绑定更新。
- 角色筛选和“停止跟随”只控制事件列表呈现；“暂停”控制任务执行。较早事件按需展开。
- 报告正文仍由报告阅读器接收 `report_chunk`；默认反馈区不重复打印完整正文。通用状态快照中的预算、版本等内部字段不转成日志正文。
- 事件 ID 用于合并即时推送与步骤结束后的持久记录；执行版本过滤继续生效。暂停、失败及终止不显示成“研究完成”。

## 接口契约

所有操作要求登录并拥有该任务，管理员也不能替其他用户操作私有研究。

| 接口 | 输入／输出 | 执行边界 |
| --- | --- | --- |
| `POST /api/v1/research/{id}/pause` | `request_id`、当前 `execution_id`；返回请求状态和 `user_control` | 仅运行中任务；重复同一暂停请求返回原记录；其他 owner 为 404，旧 execution 为 409 |
| `POST /api/v1/research/{id}/resume` | 同上；成功返回新的 `execution_id` | 仅本人手动暂停检查点；重查资料、用量、期限，锁定检查点和当前执行；并发继续最多一次成功 |
| 原 `/cancel`、`/analysis/resume`、`/report/resume` | 沿用已有契约 | 终止与系统停止的既有恢复规则继续生效 |
| `GET /api/v1/research/{id}` | 新增 `user_control`、`stop_reason` | 页面据持久结果展示操作，不靠 SSE 连接状态推定运行成功 |
| 原 SSE 接口 | 增加 `control_update`；事件带执行绑定及稳定 ID | 保留原订阅／补发授权和公开投影；SSE 路径不压缩，避免当前运行库缓冲事件 |

没有新增数据库表、依赖、自治 Agent 或 A2A 协议。暂停请求保存在任务 `review_status`；图快照保存下一阶段；继续通过现有后台图执行。
