## 执行与上下文

2026-10-24写作衔接补全：技术卡通过字面定位的proof进入Report原文选择器前再次对照当前保留文字，匹配的位置用于召回同源相邻条件窗口；卡片摘要不作为新的原文。报告上下文记录逐proof实际选中／遗漏，保留字段与原始偏移，通用选段、引用号及原请求预算不变。跨段条件是否实质完整仍待完整真实旅程和最终主张审核，不能以新增位置接线提前勾选FLOW.10.4b2。

一个既有Analyst先抽取成果题名、日期和署名记录，可信代码按既有引用与范围规则判定采纳，再逐个回答用户选择的研究模块。单个问题只加载该模块的结构化要求；成果深读按采纳记录每组两项继续分组。此分解不增加自主Agent、出站工具、依赖或独立预算。

身份抽取也按来源分组：取得的全文与显式链接到该文件的已保留出版页放在同一阅读组，每次两个组，其余出版页另行分组。分组仅决定上下文，不证明两页就是同一成果。模型仍使用原引用编号，开头两页／有限HTML开头保留真实字符和实际截断；不同批次的模型局部成果／候选对象ID由可信代码隔离，引用及所选对象ID不变，合并后沿原题名、日期、署名和去重规则判定。避免所有论文同时挤进一个窗口后漏掉作者区，也不据分组自动转移归属或日期依据。

前置抽取不构成额外报告章节。问题阶段沿用服务器采纳的成果ID，不能重写成果归属；合并时只接收该模块允许的关系、技术、趋势或行动字段。取得但未采纳的来源仍可作为有级别和位置的研究材料，不能把它们补进采纳发表计数。问题回答和最终语义支持分别记录。

模型上下文保持原始引用编号，优先本组成果关联的证据，再保留机构背景及其他材料。深读检索使用通用方法／实验／测量词，计算机问题才补入GPU、负载和SLO术语。成果身份种子按完整记录预算裁减，并记录遗漏，避免把大型JSON从中间截断。

最终写作的样本、关系、技术条件和行动依据也改为分节的独立记录；机制等字段分别装配，实验设计／基线／条件／结果整体保留，与已有段落装配器共同工作。这样，整块JSON过大时不会连同所有实验条件一并被丢弃，也避免单独选择结果而遗漏实验背景。模型仍须按实际进入的材料写作，不据窗口存在声称已读全文。

深读上下文进一步按实验设计、基线、条件和结果分别检索相邻段落，并保留重叠窗口承担的多个用途。深读组优先取得本组完整正文的实质窗口；完整JSON窗口放不下就明确遗漏，不把所有窗口平均切成零碎片段。`reading_facets`仅记录哪些检索角色进入上下文，不能当作语义覆盖认证。

首次深读后，可信代码检查字面定位通过的技术字段，对缺少的四类实验信息最多追加一个条件补读阶段。补读仍由同一Analyst、同一根预算与原期限运行并保存检查点，不额外开放网页或工具。只有本组成果ID且通过原文定位的字段可合并，已有合格字段优先保留；没有取得的值继续缺失，不把前后论文的不同实验拼成一组。写作的`experiment_context_bundle`把实验设计、基线、条件和结果保留为一个记录，缺失字段同时传递，避免只装入最高性能数字而丢掉适用条件。该路径仍需最后统一端到端验证。

## 检查点与边界

`analysis_workflow` v2保存输入绑定、已完成阶段、当前阶段、尝试次数和未完成回复。绑定含研究配置、问题、Skill约束及实际证据内容／解析身份；输入变化后旧阶段不自动沿用。v1恢复入口明确拒绝跨契约混用，不把旧单次抽取结果当新分组阶段。已完成阶段可以在后续同根执行中复用，未完成阶段最多两次尝试；抽取上限8192，问题首轮4096、后续最多8192，均可能被原根预算拒绝。没有任何可用上下文时不派发空内容分析；截断、缺少结构或问题回答为空不算完成。

每次阶段进度进入现有运行状态与原生用量账本，`RuntimePersistence.persist_analysis_checkpoint`只更新当前会话的分析／预算字段。写入事务检查实际owner、execution、运行状态及当前计划版本，不用任务ID充当授权；原证据账本不被阶段结果替换。检查点序号单调递增，防止阶段更新后的根快照写回较小序号。

根图的较早值可能与阶段保存交错。完整快照落库在同一根事务中比较已完成阶段、尝试次数和暂停／完成状态；迟到的旧值保留更新的阶段结果与已计量用量，不能仅把序号取最大后仍覆盖新数据。阶段相同或更新的最终根结果仍可正常替换，以免反过来阻止分析完成状态保存。

每次新阶段调度前重查私有证据当前可用性；来源被撤销时停止下一次模型调用并保留访问缺口，后续绑定变化不能重用原私有上下文。写入失败或绑定冲突停止继续分析；进度事件只报告阶段与完成步骤数，不改变根任务为完成状态。

所有调用复用同一个Analyst的计量器，审核和报告仍由原根预留。检查点保存累计用量，继续不重置Tokens、原创建时间或截止时间。自动处理止于原阶段／根边界，不能通过生成新根绕过。

## 界面与恢复范围

既有研究查询API在owner检查后返回简明分析进度，实时事件与重开历史均可显示问题名、分组和保留步骤数。分析进度在研究工作区展示，不进入报告正文或离线正常报告。

工作区对可恢复阶段提供“继续本次分析”，调用`POST /api/v1/research/{session_id}/analysis/resume`。请求不接收替换查询、配置、来源或预算。仅响应中断、无效结构和输出截断可继续，阶段最多两次尝试；已达上限、资料变化、输入绑定变化、审批未结束、原根额度或期限不足均拒绝。入口返回可操作的失败原因。

服务器先核对owner、任务／会话、当前execution、冻结Skill与查询以及阶段输入绑定，并重查私有资料权限。事务锁定根记录和检查点，比较原execution及序号，防止重复点击与并发恢复。新execution只隔离迟到写入，保留同一根ID、原创建时间及累计用量；起点取原状态与数据库创建时间中较早者，不能因恢复延长截止时间。恢复经独立`analysis_resume → analyst`边继续，避免回到工具执行器重复采集。下一阶段前仍再次检查权限。

可恢复的分析中断使用`analysis_paused`运行状态，公开状态为paused；不冒充预算耗尽或让后台把它当仍在运行。这里的中断指已记录的模型服务失败、无效结构或长度截断，尚不包含强杀进程的自动接管。SSE开始新的事件段，前端用execution标识重连，避免重放旧完成事件。进度只在工作区显示。恢复入口的源码接通不等于已验证：中断／截断、重复恢复、跨owner、资料撤销、原期限及完整报告引用均留待最后统一端到端场景。
