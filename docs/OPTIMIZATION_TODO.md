## 推进约定

- 遵循[系统核心思想](DESIGN_PRINCIPLES.md)：结构简洁、规划透明、ACI 可靠。18 个模块是逻辑能力目录，可以由已有组件承载。
- 公开研究默认联网；内部资料检索按需启用，命中不关闭联网。01–06 按实际需要承载内部资料准备或网上资料的任务级证据处理，保存资料不自动要求分块、向量化或建图。
- 搜索、浏览器、检索默认提供明确的取证工具契约；工具内部可以按需调用模型。独立工具请求、检索通道及研究子任务均可并行，按依赖、数据权限与预算调度；需要根据结果持续调整行动的子任务，才配置有界自主循环。
- 资料存储、证据定位和检索增强分别选型。单次任务可使用 JSON 或普通数据库保存原文及引用关系；优先直接定位和关键词／全文检索，再根据上下文容量、召回缺口与实际收益决定向量 RAG、GraphRAG 或其他图增强方法。
- 默认隔离每次任务的证据集；项目级沿用和跨任务检索明确选择范围。任务不同不预设长期积累收益，历史资料命中仍需检查适用性、来源范围、权限、版本与时效。
- 模块设计回答“需要什么能力”，方法设计回答“有哪些实现选择”，执行计划回答“本次查询调用什么、顺序如何”。分别记录这三类决定。
- 每个子项先核对现有代码、文档与已知证据，再判断保留、简化、修复或新增。未勾选表示尚未完成本轮优化，不表示现有系统没有该能力。
- 后续按当前讨论项推进，不预先锁定所有算法。具体变更沿用 OpenSpec 记录方案和实现任务。
- 本次更新规划 TODO。新增设计方向与子项均待细化、实施及验证，已有能力仍以代码和专项交付记录为准。评估方法和工具验证的候选清单不构成执行授权；继续遵守用户禁止回归测试的要求，文档整理采用内容与一致性审阅。

### 跨对象、跨学科的研究深度与分析链

本节抽取用户提供的科研情报方案思想，保留“成果数据 → 学科问题／方法分类 → 组织与人员关系 → 研究路线演进 → 代表成果深读与外部验证 → 有依据的行动建议”。适用对象为高校、科研实验室、企业及其组合；对象、学科、时间、来源及分析目的由任务确定。原材料中关于腾讯、网络技术、两份外部报告及其数值的陈述是参考线索，本轮未逐项事实核验，不能直接写入实际研究结果。

研究目的可选“布局与演进分析”“合作资源发现”“综合研究”。第一种允许独立高校／实验室研究且不要求合作名单；第二种需要明确当前研究需求，输出有证据的候选与切入点；第三种组合两者。目的用于选择分析能力和页面，不等同于评价权重、视觉模板或绘图 Skill 的选择。缺少己方需求时，可给出方向与待补条件，不宣称已经完成精准合作匹配。

分析质量约定：

- **样本与分类**：不把已检索样本宣称为现实全集；“完整”只能相对于声明的范围和已覆盖来源。载体／等级默认作为标签，用户显式硬筛选时说明遗漏范围。分类口径更新产生新版本，跨年比较保持可比口径或展示映射差异。
- **关系与地域**：共著、资助、正式合作、交流及当前可联系状态互不替代；高校所在地不等于企业研发中心，历史署名不等于当前任职。频次、持续性、贡献与角色分别解释，次数多不能直接推出主导或战略关系。
- **事实与推断**：公开成果数量不直接代表经费、人力投入、内部战略或技术成熟度；专利与相关产品文档也不自动证明成果已部署。高校／实验室改用学术问题、方法、平台或社会应用语境，不强制产品关联。
- **趋势与预测**：区分数量变化、分类／覆盖变化和研究路线变化；缺失年份不自动补零。未来方向表达为带时间范围、依据、反证／替代解释和待验证信号的情景，不当作已知计划。
- **统计与审计**：计数、占比、变化率和权重由确定性代码计算，记录分子、分母、去重单位、缺失及多标签规则。研究家族与发表记录分开；多标签占比可超过 100% 时明确说明。图表、正文和导出共用同一数据与口径版本，冲突先解释再交付。
- **行动与交付**：合作分析按需提供，排序复用已规划的权重、硬条件、分项与缺失区间；区分潜在线索、已核关系与可行性待核。公开联系入口只有取得来源才展示，报告生成不触发对外联系。交付可复核数据、分类／关系表、深读卡、推断与行动依据及交互报告；无需图数据库即可保存关系。

报告按目的选择“研究全景、领域／路线、组织与人员关系、演进及驱动、代表成果专题、应用／学术价值、合作或研究行动、方法与证据”页面，延续下节预设／自定义模板和绘图 Skill 选择。代表成果深读为案例页提供内容深度，宏观／微观分析共同绑定证据；具体图表和可比指标按学科适配，不复制某家企业的章节、篇幅或数值。
