# 固定证据重排与独立新研究

组织研究完成后，结果页提供“固定证据重排”。它把本会话已经保存的成果、原文引用位置与采集时间转换为匹配快照，复用现有确定性评分函数和权重编辑器。准备快照与重排均不调用模型、不读取新网页、不修改原研究；“重新取证并研究”才创建独立研究任务。

## 会话快照 ACI

`POST /api/v1/research/{session_id}/matching/snapshot` 无覆盖正文输入。服务端按认证 owner 查询并锁定已有会话，要求会话及报告完成；从保存的运行证据与结构化成果生成快照，不接受客户端替换候选、来源或事实。返回：

- `snapshot_id`：现有 `research_matching_snapshots` 表中的不可覆盖记录。
- `snapshot`：原范围、采集封存日、来源、研究单元、共同口径、计算规则及转换限制。
- `initial_configuration`：原研究冻结的完整权重与映射，供重排初始编辑使用。

相同 owner、会话、完成执行和转换规则版本复用同一记录；会话行事务锁串行化重复准备，不需要新缓存服务或图数据库。每次后续读取还核对快照及绑定会话当前归属。直接提交记录的旧 `/matching/snapshots` 仍可用，但不能冒充 `saved_research` 或自报服务端转换标记。

不存在或他人资源返回 404。会话未完成、没有组织配置／结构化成果、成果无原文位置对应或没有有界样本时返回 409，保留原报告并说明原因；不能生成虚构候选或自动扩大研究。参数类型无效仍由服务端返回 422。数据库故障不返回已保存成功；重试相同准备会复用已提交记录。

## 样本与评分语义

输入来自本会话的 `scope_result` 和 `publication_metadata`，原文引用区间再次与保存正文核对。采集日期来自保存的 `collected_at`，封存日取实际研究完成日；缺少采集时间时不补造。引文定位通过不等于独立语义复核，匹配来源仍标 `unreviewed`，不自动生成“已确认合作”事实。

共同组按请求的学科标签及成果类型组织；尚未逐篇自动分类，不跨组统一排名。每个研究家族在同类型组内取最近一次发表代表，保留全部关联来源，家族等权；版本未关联仍按独立发表单元。指标年份字段在此表示封存计算背景，不将不同年份的学术等级混合赋给成果。

当前自动分项为可解释的标题词面重合与发表时效性；不会把网页导航当作摘要。研究路线、证据完整度、合作互补性以及适用但尚未取得的成果评价保持未知。`performance_applicable` 区分“不适用”和“适用但缺数据”：后者保留成果表现的父级预算及可能区间，不把预算挪给已知项制造确定分。

发表时间有上下界及精度。年／月精度用整个区间计算时效性上下界；覆盖率 100% 仍可能因日期精度不足而没有确定总分。未知分项用其可取区间，确定优先关系只在一方下界严格超过另一方上界时建立。跨组不可比、排除原因、分项来源、缺失维度和规则均显示。

处理日期区间／适用但未知指标时，结果规则标为 `adrs-matching-v2`。旧的纯标量输入继续标 v1。快照结构保留兼容的 `matching-evidence-v1`，新增字段可加；归一化规则仍独立版本化。快照的 `origin` 与匹配预览的 `verification` 明确区分显式输入记录和来自保存研究的记录，均不宣称已独立确认所有科学事实。

## 结果页操作

1. “准备本次证据快照”只封存保存数据；失败时显示原因，原报告保留。
2. 从原研究冻结配置编辑偏好，预设、启停和归一化沿用[权重编辑器](organization-weight-editor.md)。非法／校验中配置不能触发重排或新研究。
3. “重排当前证据”调用原 `POST /matching/preview`。界面显示区间、覆盖率、分项权重／贡献、来源、规则／映射／配置版本、排除项及确定优先关系。修改未重算时，旧表标为上一次结果。
4. 每次显式重排生成独立配置版本，编辑标签作为前缀保留。原快照及报告不改写；当前预览是只读结果，不声称保存为新的研究报告。需要复用可另存个人方案。
5. “重新取证并研究”保留原研究范围、渠道、内部资料选择、技能和预算参数，采用当前偏好创建新会话；不复用旧审批标记。界面切到新会话，旧报告仍可回访。

新研究参数由本人结果返回的 `restart_parameters` 白名单提供，不包含旧 `session_id`、owner、执行 ID 或 `user_confirmed`。仍由原入口重新检查授权、资料、审批和预算。选个人预设时绑定实际版本；直接配置生成独立研究配置版本。准备和重排没有新增外部请求预算；新研究消耗原有任务预算，不能把两种动作混为一谈。

## 数据库与安全边界

复用 `app/db/matching.py` 的共享 PostgreSQL DDL。可空会话参数、UUID、JSONB、时间值在 SQL 中显式定型；不以 SQLite 消费结果代替真实驱动／类型业务证据。没有快照更新或跨 owner 共享接口。转换与计算使用普通函数，不增加 Agent、框架或常驻服务。

沿用 A2ABreak 基线 v1.0 的 11 项既有适用性评估。**A2AB-03／上下文归属与跨租户隔离**对应会话／快照双重 owner 校验；**A2AB-06／并发状态版本与审批绑定**对应完成执行、不可覆盖快照、会话锁及独立配置版本；**A2AB-08／结构化授权请求与权限不放大**对应服务端来源生成、拒绝自报标记、纯计算和新研究重新走原授权。上述引用均指“工程解决方案／验收办法”，出处与原评估见[运行 ACI](organization-research-runtime.md#a2abreak-引用与本次边界)，不是上游官方修复或整套安全验证声明。
