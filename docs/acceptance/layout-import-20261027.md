## 已实现

- ReportLayout只包含通用章节角色、有限组件／图型／绑定类型、颜色、字号、间距及交互枚举，不容纳原文、任意标题、事实、引用或代码。现有DeliveryRequest接受独立布局或旧手填页面，两者不能同时占有结构；没有布局时保留旧序列化表示。
- 独立research_layout_samples按认证owner存原始文件和解析记录，与研究资料表／RAG没有写入交接。HTML不保留正文文本，DOCX不提取正文作为模板；只保存格式值、组件、位置和实际差异。原图片／脚本及外部资源不进入布局。
- HTML支持标题层级、基本选择器／内联样式、分栏、表格、图像／图形和指标槽位。DOCX支持标题、正文／列表／表格／图像角色、基本字体／颜色／字号、分栏和页眉页脚占位。复杂CSS、浮动对象和图片原内容不作精确复刻承诺。
- 个人模板可保存布局，来源样例引用是管理元数据；保存检查来源归本人，不进入报告配置。旧配置及重放表示在无新增字段时保持。
- 新布局还没有报告适配器，预览返回layout_binding_pending并阻止启动；不能忽略用户布局生成报告。当前API进程未部署新界面，后续模块继续接入。

## ACI

| 接口 | 输入／输出与边界 |
| --- | --- |
| POST /api/v1/research/layout-samples | 本人认证、multipart的file与request_id；HTML／HTM需UTF-8，或DOCX。返回source_id、本人文件名、内容清除后的layout及parse。原始字节不出现在返回值。 |
| GET /api/v1/research/layout-samples/{source_id} | 仅本人可取管理元数据、布局、定位与差异；其他主体或缺失均404。 |
| 原delivery-templates保存／修订 | configuration.layout为受控结构；可携带本人layout_source_id作管理引用，沿原request_id／expected_version语义。 |

输入最多2MiB，每人最多50份样例；布局最多24章、96块、12张图，单章32块。HTML最多20000节点、64层和512条简单样式，样式文本最多256000字符；DOCX最多2048个ZIP项、16MiB展开量及8MiB主XML，拒绝DTD／实体声明。解析最长15秒，不调用模型、不执行源脚本或下载远程资源。线程解析不构成OS沙箱；输入与复杂度限制约束其工作，后续取消／作业模块仍需处理迟到结果。

413表示空文件或体积不符，415表示未支持格式；422包括结构、编码、复杂度或解析错误；409包括同一request_id换文件、样例容量或来源归属不符。同一主体、request_id和文件重放返回原source_id。源文件名仅用于本人管理，不能进入研究模型。
