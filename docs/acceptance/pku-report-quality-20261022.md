# 北大报告：面向读者的质量审阅与改进

## 判断

初稿有真实材料和实验条件，已超过摘要拼接，但25页的逐篇表格占据主线，仍更接近研究资料汇编。它不适合作为决策者的默认阅读形式。优化后可以支持第一轮研究方向与合作课题筛选；正式合作排序仍需要用户的业务、设备、数据和预算条件。这是依据读者任务进行的自审，不是实际目标用户试读结果或独立外部评审。

不使用“8/10”等缺少标尺的自评分。检查读者能否回答：团队持续研究什么；哪些机制发生变化；哪些结果在自己的条件下有意义；具体找谁、带什么资料、先形成什么成果。

## 主要问题、依据和处理

| 问题 | 对读者的影响 | 已完成的调整 | 余下工作 |
| --- | --- | --- | --- |
| 8篇论文逐一介绍，主要判断被淹没 | 读完仍不知怎样选题 | 主文改为“业务问题—备选机制—关键条件—研究成果”比较；开头三项判断与合作含义 | 通用生成器还没有自动组织到这个水平 |
| 主文25页，论文/课题表反复出现 | 决策阅读成本高 | 全文细节和完整课题表进入默认收起附录；主文与附录分别打印 | 后续依据真实用户阅读反馈调整篇幅 |
| 固定会议年份容易误写演进 | 把发表时间当作思想提出时间 | FastServe的2023预印本与2026正式会议分开；RAGCache版本分开；前沿预印本明确标识 | 持续跟进新正式版本需新研究，不改写旧材料 |
| 最高性能倍数缺少可比条件 | 容易错选技术和估算收益 | 比较硬件/模型/负载/指标；不画跨论文倍数榜；重点解释DistServe长度截断、RLHFuse自消融与ServeGen配置反转 | 全量主张语义复核仍未完成 |
| 人名由英文猜中文、机构关系被当作现时任职 | 可能找错人或误解资源 | 中文姓名采用北大官方文章核对，其他保留作者英文名；图注明署名关系；联系入口区分PI与公开论文作者 | 联系有效性、合作意愿与可取得资源尚无反馈，没有发消息 |
| 合作建议缺少启动条件 | “建议联系团队”无法执行 | 按只有API、可控GPU、多模型平台、冷启动环境、RL训练栈提供选择；5课题均有资源和首个成果 | 没有用户具体业务时不硬排团队分数 |
| 单靠模型审核容易把选段不足判成事实错误 | 审核分数不能代表质量 | 保存24项原判；对12项关键数字另取明确原文，11项自动支持，1项因果歧义收窄表述并人工核对 | 改造按主张取证、原子化复核与缺口反馈 |
| PDF强制分节换页、手机目录过长 | 页尾大量留白、手机先看到大段导航 | 主文打印连续排版；手机折叠目录、标题分行，图表可横向阅读 | 已实际看导出；不以源码CSS或文字检查代替视觉阅读 |

## 当前结论的使用边界

报告能支撑“先与哪些研究方向交流”和“第一项联合研究如何定义”，不能代替合作尽调、设备实测、报价或团队接单确认。报告没有运行这些论文的GPU实验，性能均归因于原论文。对于当前使用外部模型API的ADRS，优先借鉴负载与完整任务观测；GPU/KV调度课题以取得相应控制权为条件。

## 系统层面的改进顺序

1. 先消除把暂停结果写成失败、把截断JSON当分析的交付缺陷；本次两项已修复并有当前行为证据。
2. 建立按问题的全文阅读与上下文装配：取得全文、选段、进入模型的范围和结论覆盖分别记录。
3. 将主文/技术附录、条件化比较和合作课题纳入可选择的通用模板；绘图Skill仍走受信执行器。
4. 让审核反馈定位具体主张缺失的材料，再有界补证；不能靠增加审核额度或删掉告警让报告显得合格。
5. 用真实研究与目标读者的任务反馈验收内容可用性，然后再调整算法、路由和性能。
