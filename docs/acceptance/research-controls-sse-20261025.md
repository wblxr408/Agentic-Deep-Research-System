# 任务控制与 SSE 实际操作 · 2026-10-25

用户要求能自主暂停／启动，并恢复 Agent 的具体实时反馈。沿用 `redesign-research-workspace`，本轮在本机专用 5181／8011、既有隔离 PostgreSQL 数据库和独立 Edge 中操作；原 5177／8009 数据仅用于查明截图任务状态及部署。

## 发现与修复

1. 截图用量 20,423 的任务为 `report_paused / final_report_needs_revision`，原页面没有解释原因，也没有通用的运行暂停入口。新增顶部控制、手动暂停原因、按适用条件继续及调整后重启入口。
2. 原画布用通用用途覆盖具体 query，详细事件又收在研究记录中。改为具体节点名称，流程视图默认显示 SSE 事件、角色筛选和跟随控制。
3. 部分图事件原先等步骤结束才发送。新增由所属执行循环即时投递的路径，保留持久记录和事件 ID 去重，不新增代理通信层。
4. 本机安装的 Starlette GZip 实现对长连接写入后没有逐事件刷新。实际同一 SSE：默认压缩在六秒观察窗口内没有得到事件；显式 `Accept-Encoding: identity` 立即得到 connected、workflow_start、state_update、agent_complete、done。SSE 路径绕过压缩后，Edge 原生 EventSource 收到了真实事件，其他 API 继续压缩。

## 本次功能的实际路径

| 操作 | 结果 |
| --- | --- |
| 修改前真实暂停 POST | 返回 404，确认目标缺失；不是静态接口存在性检查 |
| 本人暂停、重复同一请求、其他账号暂停 | 请求进入 requested；重复返回原记录；B 操作 A 返回 404 |
| Edge 点击“暂停” | 页面显示“暂停中”；真实图保存边界后显示“由你暂停”及“继续研究” |
| Edge 点击“继续研究” | 新执行从保存的 approval_reviewer 图节点执行；产生真实开始、角色反馈和暂停终态，SSE 面板直接显示 |
| 已用额度与时间 | 专用既有用量样本 37 及数据库创建时间在继续前后保留；未调用模型产生这 37 Token，它是用于非零保留检查的准备数据 |
| 旧执行再次继续 | 返回 409，没有另起一次执行 |
| 角色筛选、停止跟随、重启入口 | 实际列表按角色显示；跟随按钮切换；重启入口打开原请求配置，未提交新付费研究 |
| 其他 owner 继续 | 404 |
| 超过原期限的专用检查点继续 | 409 `resume_original_allowance_exhausted`；原暂停状态、执行身份和用量保持 |
| 同一检查点并发继续两次 | 一个 200、一个 409，只创建一次新执行 |

Edge 最终旅程没有未处理页面异常。早期自动化因角色筛选 option 与正文同名、请求相对 URL、准备数据两个时间字段及 label 定位产生的失败均已修正后重走；不计为功能通过。压缩问题则是实际产品故障，修复后浏览器路径才完成。

操作只走真实服务、数据库、图检查点和无模型调用的授权确认节点；不伪造浏览器 SSE 或替换前端响应。最初暂停的图工作在独立进程执行，因此其最终状态通过数据库轮询进入页面；后续“继续”由 API 本身执行并通过该 API 的真实 SSE 推送。这不是全研究任务、长时间模型生成、所有工具并行暂停或新报告质量的完成证明。

证据保存在本机 `outputs/research-control-20261025/`：`baseline.json`、`browser-results.json`、`resume-boundaries.json`、`user-paused-controls.png`、`continued-real-sse.png`。一次性脚本及凭证仍在忽略目录，不提交账号、Cookie、模型配置或私有运行数据。没有运行回归、单元、构建、类型、lint、schema 或浅层探针。

原工作区部署前实际为 3 个失败、7 个暂停任务，没有运行任务；原任务没有被自动继续。服务升级沿用原数据库、Cookie 和模型配置。操作与安全执行点见[任务控制设计](../RESEARCH_EXECUTION_CONTROLS.md)。

IAB 当前登录的普通账号不拥有截图中的旧管理员任务，实际读取返回 404；关闭了额外预览页并保留其原来的空研究草稿页，没有改变资源归属来展示旧任务。完整控件与实际 SSE 的页面证据来自上述专用账号旅程。
