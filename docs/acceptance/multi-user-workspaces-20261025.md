## 原部署升级与页面

升级前确认原数据库没有运行中的研究。保留原单管理员、9 个任务及资料／配置／Skill 的资源标识与 owner；升级后逐表语义核对相同，原任务仍为 3 个失败、6 个暂停。没有重置额度、期限、会话版本或任务状态。服务接入原本机 API 8009 和前端 5177。

实际浏览器确认 `?view=register` 出现用户名、密码、确认密码、注册并进入和登录切换；在原 Edge 会话进入账号页，原管理员无需重新登录即可显示管理员身份，并进入用户管理页，显示开放注册、原账号列表和禁止修改自身的控件。个人页截图已实际查看。没有输入或修改现有管理员密码，也未在生产工作区建立测试账号。浏览器截图通道随后中断，未将未保存截图冒充交付文件。

客户端退出／身份变化的缓存清理、跨标签通知和失败时遮蔽私有界面已实现；完整浏览器双账号来回切换及弱网过程仍待真人试用，服务端 Cookie 旅程与源码审阅不替代该项。

## 失败及修正

- 旧版本真实注册 POST 返回 401，记录了注册缺失的基线目标失败。
- 本机 Docker 引擎请求阻塞、PostgreSQL 连接超时；通过已配置的原生 `docker desktop restart` 恢复，并启动原数据库／Redis 容器，没有删除卷或重建原数据。
- 独立 E2E 初次服务尚未接受请求，初始化连接被拒；改为只对实际初始化动作的连接拒绝有界重试，不调用健康探针。
- 并行工作线程组的独立进程同时初始化全库，发生旧 DDL 竞争；在该端到端旅程中先建立公共数据库池，再并行执行 owner 绑定，未把历史初始化并发当成通过。
- 最初把宿主权限检查放在通用 CommandRunner，使普通资料解析返回 400；移到渠道外部命令入口后，真实资料写入与宿主登录态拒绝都通过。
- 原日志句柄仍由旧启动进程持有，替换 API 时改用本次独立日志文件，保留旧日志。

没有运行回归、局部 TDD、构建、类型、lint、schema、启动／导入／文件／hash／文字探针或其他非端到端检查。全部 11 组本次功能旅程最终退出码为 0；独立私有运行记录不提交仓库。Basic Memory 同服务查询仍超时，本轮没有声称已完成知识库索引。
