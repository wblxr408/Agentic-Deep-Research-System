## 已实现的变化

按问题选取方法／实验／开头署名窗口，来源之间分配空间，保留字符与页码、解析级别和遗漏；预算不足时兼顾论文及机构背景，不传几个字符冒充全文覆盖。分析／报告不再重复装入完整的规划权重与种子契约，正式接纳和结算仍通过原根预算。

PDF采用原生文字流保留双栏顺序，表格／图像上限与正文完整性分开。原生NUL以可见投影和可恢复原文编码保存，修复真实JSONB写入失败。出版商封面之后的开头页进入身份选段，避免作者单位被封面挤出上下文。

报告增加核心判断、模块主文／附录、分别下载／打印与来源技术字段对照表。概要、主文与附录共用来源、统计绑定和转义。结构或绑定失败不再以空章节冒充完成；保留完整原始回复、验证错误及一次有界修订。局部问题只请求被拒段落的修正，引用数组由服务器保持。历史无效稿的`delivery_complete=false`关闭正常下载。

审核按主张引用共享摘录表，完整原文位置保存在研究记录；减少重复输入不等于事实准确率提升。详见[实现与ACI](../research-context-packing.md)。

## 当前行为验证

`tests/current_change/test_question_context_delivery.py`最终 **9 passed（4.17秒）**。针对这次变化观察实际失败后修复，覆盖：

1. 多篇论文的方法、实验和封面后署名进入分析，保留的摘录可按源位置重取。
2. 大型偏好配置不挤占写作，有限额度保留实验与机构联系资料，并保留审核空间。
3. 主文／附录、核心判断预设和独立稿引用保持一致。
4. 技术对照表使用有定位的字段及来源。
5. 长双栏PDF的文字顺序、后页实验和结构上限分别保留。
6. 有限额度内审核全部指定主张，共享原文而不重复定位负载。
7. 真实PostgreSQL JSONB写入含控制字符的材料，原文可恢复。
8. 结构无效不得生成正常完成稿，也不得正常交付下载。
9. 同一计量器中只修订被拒段落，再进行统一校验。

没有运行历史回归、冒烟、启动／导入／存在性探针、校验和或文字正则检查。前端`npm run build`通过，包含TypeScript；旧权重编辑器重复属性用同义默认分支修正。构建仍提示主包大于500kB，性能工作后置。OpenSpec严格校验通过。以上结果验证当前软件行为，不能替代真实模型内容质量或用户试读。

## 内容审阅与后续重点

最新材料中实际取得DistServe、dLoRA、RLHFuse、HydraServe全文，但确定性采纳成果仅1项。**全文取得与成果归属采纳之间仍有明显断层**；不能用采纳发表数替代取得全文数，也不能把未进入上下文的材料说成不存在。已经修复开头署名选段，尚未在新的完整研究中验证归属覆盖效果。

统计校验目前将部分“所读全文数量”也作为发表样本聚合处理；模型修订又会把取得原文数改成采纳发表数。下一步应分别定义来源、全文文档、发表记录和研究家族的统计单位与上下文，不让模型在不同分母之间替换。末次代码将局部修订收敛为删除无依据的计数子句、保留机制／实验条件，尚无新的真实模型完成证据。

当前生成稿仍反复提材料边界，方法和合作建议部分有价值，但不足以替代先前深入人工稿；问题不是增加装饰图或放松校验。继续优先做身份／成果归属覆盖、按子问题的完整实验条件和正确统计单位，再做新的全链自动研究与目标读者试读。TODO FLOW.3、10、11、12及OpenSpec4.5保留未完成。
