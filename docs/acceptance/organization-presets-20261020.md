## 场景及结果

在独立验收数据库中，由管理员预置第二个实际身份；两个身份均通过原有密码／会话 API 登录，没有替换认证依赖。当前产品仍是单管理员部署，本项没有开放注册、用户管理或新的权限角色。

两个用户各自创建同名个人预设。A 的 v1 为主题／证据 6:4，B 的预设不能在列表中包含 A 的 ID；B 知道 ID 后直接读写 A 的预设均返回 404。历史 v1 保持可读，A 将预设更新为 v2 的 1:9 后，继续持 `expected_version=1` 更新返回 409。

A 用自己的 v1 真实创建 MIT 公开科研组织架构研究 `875adc2c-c01e-4f3d-8d76-34f3587580f4`。研究执行期间更新为 v2 后，研究继续使用已经冻结的 v1 和 60% 主题权重，生成 **9684 字符报告、24 条引用**。报告完成后再更新为 v3 的 9:1，重新读取既有研究，完整结果与修改前一致。

随后在同一业务链的拒绝分支中，B 使用 A 的预设 ID 创建研究，返回 404；B 的研究行数前后均为 0，未创建任务或取证。该步骤使用同一已完成场景的真实身份／资源继续验证，不是另一轮替代输入的研究。

初始场景在个人预设保存接口不存在时返回 405，作为 RED。新增 API、版本表、归属解析和研究快照接入后，双身份路径及真实研究到报告全部通过。执行入口为 [`scripts/organization_presets_e2e.py`](../../scripts/organization_presets_e2e.py)；拒绝跨用户研究引用的追加过程也已并入后续可复用脚本，但未重复执行已经通过的新研究。
