首次完整研究 `cc87e758-7fe6-458f-92c0-a449a2810406` 通过后，界面审阅发现旧提交错误仍显示，以及下拉框需要按版本固定。修复合法输入清除旧错误、个人选项按 ID＋版本标识后，重跑同一目标并增加个人方案切换／恢复行为。没有通过减少预期、模拟服务或替换数据取得通过。

最终真实研究 **`751b95eb-1cbc-43fd-af19-eda9db3a0f99`** 的消费程序 `scripts/organization_weights_ui_e2e.py` 退出 0，没有捕获到浏览器运行错误。

## 实际验证

- 默认研究发展从服务端读取，主题比例 35%；停用时效性为零，恢复预设后回到 10%。
- 主维度全零和负值显示拒绝，未发出研究 POST；纠正输入后旧负值提示消失。
- 设置主题／成果表现／证据完整度为 60／20／20，停用时效性并保留原值 10，生效比例为 60／20／20。
- 设置载体／论文组 3:1；CCF／ICORE 指标 3:1 显示 75%／25%。停用 ICORE 后 CCF 为 100%，重新启用后恢复 75%／25%。
- 将学科改为材料、成果类型改为期刊时，CCF 不适用，JCR JIF 明确需授权导入。回到计算机会议，按规范 ID `dblp:conf/nsdi`、发表／评价年 2022 查询，显示 CCF A、版本 2022 和来源，而非给未知成果猜等级。
- 通过界面创建个人 v1，切回系统预设为 35%，重新选择 v1 为 60%；临时改成 90 后恢复仍为该个人版本的 60%。随后改为 80 并保存 v2。
- 实际新研究只传个人 `preset_id`＋`version: 2`，不同时传直接权重。结果主题生效 2/3，成果表现与证据完整度各 1/6，时效性为零；子组及指标组内比例均为 75%／25%。API 和 PostgreSQL 中完整冻结配置一致，页面显示最终真实报告。
