## 2. 全部纳入适配计划的评价体系

| 类型 | 适配清单 | 规则 |
| --- | --- | --- |
| 数据库收录 | SCIE（常称 SCI）、SSCI、AHCI、ESCI、Scopus | 保存收录和覆盖年份；主要作为标签或用户显式条件 |
| 学科目录 | CCF、ICORE／历史 CORE、ABDC、AJG／常称 ABS | 按学科、载体、轨道和版本判断适用性 |
| 期刊与载体 | JCR JIF／Q1–Q4／JCI、中科院分区、CiteScore／百分位、SJR、SNIP | 保留原始值、类别和年份，多类别不静默取最高值 |
| 论文引用表现 | 引用百分位、CNCI、FWCI | 保留提供方、学科／年份／文献类型及引用截止日 |

各体系独立呈现，不能互相替代为一个“统一等级”。每条记录保存发布版本、指标年份、来源、获取时间和对应依据。适用但缺数据、未收录、不适用、来源不可用及冲突分别显示；无数据不等于低等级。

以上均已纳入实现范围；实际数据通过公开或已授权来源、已授权导入获取。逐项记录来源是否已连通，不以“支持字段”宣称已取得所有指标。计算机可同时使用 CCF 与适用的期刊指标；其他学科不自动套用 CCF。

## 3. 可修改权重与精准匹配

提供研究发展、合作发现预设，允许保存个人方案、编辑、关闭指标和恢复预设。以下为尚未业务标定的初始默认值，用户可以修改：

| 维度 | 研究发展 | 合作发现 | 控制内容 |
| --- | ---: | ---: | --- |
| 主题相关性 | 35% | 30% | 与当前问题和技术主题的相关程度 |
| 研究路线契合 | 20% | 15% | 研究问题、方法和技术路线的契合程度 |
| 成果表现 | 20% | 15% | 适用成果标签和引用表现，各体系还可分配内部权重 |
| 证据完整度 | 15% | 15% | 归属、版本和结论是否有可核查依据 |
| 时效性 | 10% | 10% | 与用户时间目标相关的研究变化 |
| 合作互补性 | 0% | 15% | 存在明确合作需求时的能力互补与证据 |

匹配规则：

1. 先处理对象类型、学科、时间和明确关系要求等硬条件，再按权重匹配。
2. 所有权重非负、有限；零代表停用，有效层级全零拒绝。系统归一化并展示实际值，例如输入 6:4 后生效为 60%:40%。
3. 成果表现内各适用体系支持权重调整。同源指标共享父级预算，避免 JIF 和 JCR 分区重复放大同一信号；可编辑映射须保存规则版本，不改变官方原始等级。
4. 展示分项、贡献、理由、来源、样本规模和版本；跨学科／不同载体先按可比口径分组。
5. 缺失项展示权重覆盖率和可能分数区间，不填零、不逐对象静默补权重。例如 60% 的已知维度为 0.9、其余未知时，显示 54–94 区间和 60% 覆盖率，不声称总分就是 54。
6. 用户在固定证据上调整权重可预览重排；重新取证由新的显式研究动作触发。个人预设按用户隔离，已提交会话保存原配置，恢复和历史报告不受新默认值影响。

“精准匹配”以可解释、可复算和真实业务效果为目标，不预先承诺未经测量的准确率。学术指标补充背景，报告仍围绕研究问题、贡献和演进组织。

## 4. 实现顺序与完成标准

| 阶段 | 实施内容 | 完成时用户能观察到的结果 |
| --- | --- | --- |
| P1 范围与实体 | 类型／实例单选多选、学科时间、实体消歧、家族及关系口径 | 单高校、单实验室、单企业及混合对象均能表达清楚，汇总无重复 |
| P2 评价适配 | 全部体系的版本化清单与来源适配，按域分批接入，区分真实数据与缺口 | 每项评价都有来源、类别和年份，不适用与缺数据明确可见 |
| P3 匹配计算 | 硬筛选、分层权重、确定性计算、区间和解释 | 调整权重能解释结果变化，硬条件与已核事实不被改写 |
| P4 会话与界面 | API／状态／持久快照、个人预设、对象和权重面板、报告与导出 | 从选择到报告使用同一配置，历史和暂停恢复保留原版本 |
| P5 分析深度 | 样本基线、领域／路线映射、关系、成果深读、外部验证、趋势与行动及统计校验 | 能从原始证据解释研究问题、机制、演进与下一步，按目的展示真实缺口 |
| P6 业务案例 | 腾讯网络、独立高校／实验室、混合比较、非计算机案例 | 同一研究流程能适应不同对象与学科及研究目的，并说明真实验证范围 |

阶段按 P1 → P2 → P3 → P4 → P5 → P6 推进；每阶段随实现交付自己的行为证据和使用说明。P4 接入及 P5 分析深度遵循 [详细任务依赖](../openspec/changes/add-organization-research-matching/tasks.md)，内部模块和界面可分小步交付。前一阶段未完成不以演示界面冒充完整功能。

## 7. 从信息采集走向有证据的研究分析

本轮抽取的是“样本 → 分类与关系 → 机制深读 → 演进与交叉验证 → 行动”的方法，用户材料中的企业、网络技术、年份和外部报告统计不作为通用事实。高校、实验室和企业可独立或混合研究；学科问题／方法／应用层次、成果类型和时间由任务配置。布局与演进、合作资源发现、综合研究三种目的按需组合分析能力，复用已有工具、Skill 和编排，不要求新增六个 Agent。

| 分析阶段 | 输出与约束 |
| --- | --- |
| 样本界定 | 保存检索式、来源、对象别名、时间、截止日、候选／采纳／排除及去重规则；分别统计发表记录和研究家族。仅声明已覆盖范围，不冒称现实全集。按学科纳入适用成果，用户指定的来源和硬筛选保持有效。 |
| 领域及路线 | 版本化问题／方法／应用分类，按需区分核心与关联方向，保留多标签、未知与分类依据；不默认限定某些顶会或照搬计网分类。 |
| 组织及人员关系 | 保存历史署名、当前单位、地区、持续性与频次，分别表示共著、资助、正式项目、联合实验室和交流；合作伙伴所在地不冒充被研究对象的研发地点。 |
| 成果深读 | 代表成果解释问题、已有局限、机制／架构、创新、基线／实验条件、结果和边界，关联原文页码／图表；仅有摘要时说明不能确认的细节。 |
| 演进与验证 | 区分数量变化、资料覆盖变化与路线变化；项目、官网、专利、软件／数据或适用产品资料用于交叉验证。公开成果不直接代表投入、战略、成熟度或已部署，未来方向表达为有反证／替代解释和待验证信号的情景。 |
| 行动与交付 | 布局模式给出研究问题及验证路线；合作模式按需求给出候选组织及关联团队／学者、互补点、依据、待核项和下一步。缺己方需求时保留条件，不宣称精准匹配；分项优先级复用已有权重和区间。 |
