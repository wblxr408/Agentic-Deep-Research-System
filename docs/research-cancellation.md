# 任务取消、在途收据与事件出口

2026-10-23，OPT-18取消模块源码接入，未运行。新增表和canceled状态约束尚未迁移；不能将下面的控制点写作真实运行或安全验收结论。全部ORG／OPT／FLOW实现后统一端到端。

## 用户操作与状态

当前任务工作区提供“取消本次研究”。本人pending／running／paused任务可以取消；completed／failed不改为取消。请求必须带界面读取的execution_id（尚无执行时为null）及稳定request_id。数据库实际执行已变化时返回409，要求重新读取，不能用旧页面的取消操作停止新一轮执行。

取消保留资料、已有正文／草稿、来源与历史，主状态和runtime状态均为canceled。当前任务不再取得完成报告下载资格，取消前已保留的历史报告仍按原版本和权限独立读取；可以复制原配置并重新预览，创建新任务。取消不会复原用量、延长期限或继承旧审批。

界面根据done.status显示取消／暂停／完成，取消期间的步骤与分析显示最后记录，不再一律标“已完成”。状态刷新失败与取消失败分开；请求结果未确认时复用原UUID重试。已取消页面可手动刷新在途用量，未结算收据不能证明服务仍在执行或调用免费。质量与反馈仍能读取本人保留材料。

## 取消 ACI

`GET /api/v1/research/{session_id}`及`GET /api/v1/research/status/{session_id}`返回execution_id、cancellation与预算中的在途状态。后者在读取原数字视图时保留完整预算字段，不丢掉预留／未知标记。

`POST /api/v1/research/{session_id}/cancel`输入：

```json
{"request_id":"<fresh UUID, retained for transport retries>","execution_id":"<execution_id from the current owner view, or null>"}
```

返回session_id、原execution_id、status=canceled、request_id、canceled_at、transitioned、replayed及当时未结算模型数。相同owner／request_id／参数只对应一个命令结果，异参复用返回409；每任务最多128个取消命令，原命令重放不受此上限影响。已取消任务的新命令保留最初取消时间，不再产生一次取消状态事件。

本人不存在／非本人任务→404；执行版本变化、已为其他终态、请求身份冲突或命令容量→409；字段无效→422。权限及状态由可信DB事务检查，模型、Skill及事件中的文字不能自行取消任务或改变许可。

同owner取消命令串行化，当前任务行FOR UPDATE同时约束执行版本、状态、命令和待审批拒绝。状态及原快照一并标取消、清空当前批次／待审批视图，原请求和原证据不重写。临时或中断数据库错误不冒充取消成功。

## 执行信号与资源边界

`app/execution_control.py`为原run_research_workflow提供一个运行作用域。ContextVar把同一控制引用传到原LangGraph节点、worker线程和工具；本机Event是DB状态的派生信号，不是第二个根状态／预算owner。每个运行只有一个短期DB状态观察协程，结束即回收；它不执行研究、训练或模型调用，不是新增常驻服务或工程记忆监听器。其他worker从DB观察取消／主体停用／执行替换，新准入仍要核对DB，不能仅信任本机缓存。

模型在供应商请求前、流消费及非流返回时检查；可关闭的单次响应流在取消时主动关闭。非流请求和本地推理不能保证瞬时中止，仍受原请求／任务期限，返回的数据不再进入新结论。HTTP每跳、建连与读体检查信号，可用连接关闭／shutdown解除读取；命令分发和原Job／进程组清理沿同一信号。公开浏览的原网关与独立context关闭，缓存页面也不绕过取消检查；MCP在实际executor前后检查。

固定绘图子进程改为有界communicate循环，原45秒／剩余根期限不扩大，取消或超时后结束并回收已知子进程；没有允许模型执行任意脚本。图表缓存命中也检查当前执行状态。重试等待可被当前Event打断，取消不记为共享Embedding／重排服务故障。

送入固定绘图器的文字／图表数据先经过统一披露投影，复用和交付绑定也使用该表示，避免只清理HTML标签却把原访问URL画进SVG／PNG。原始证据及定位保留；图像文件不是绕过披露规则的另一出口。

本机注册表只防同一执行在本机重复进入；不宣称分布式调度共识或企业身份系统。显式关闭认证的本机开发模式继续只使用固定本地主体，默认认证、主体归属和现有权限不因此放宽。

## 准入、结算与迟到结果

同一PostgreSQL新增research_cancellations、research_model_receipts和research_tool_receipts；DDL只接入既有初始化／迁移入口，本次没有执行。模型call_id、工具operation_id及owner／任务／原execution绑定，准入在原任务行锁内落收据后才可分发；新准入拒绝已取消、已替换或主体不可用的执行。工具每次尝试使用原有界份额，当前已用及在途份额共同约束原总次数；模型按原Token预留检查全根用量和在途量，已有可信价格时同时检查参考费用预留。未定价项目仍是未知，不能据此宣称完整人民币／美元发票上限已得到保证。

结算只替换同一call_id／operation_id的在途收据，不重复加入原阶段汇总或正常工具历史。可证明尚未派发的拒绝／本地客户端配置失败释放该次预留并记录零供应商调用；已经尝试派发但缺少usage／断流，沿原保守结算，不把未知费用当零。价格来源、估算、原预留和准入期限可见；原数值账本是计量与参考费用，不是供应商发票。

取消之后或旧执行替换之后的已准入收据仍可结算：只合并预算、调用身份与观察到的工具／本地资源信息，不改当前状态、计划、正文或证据。预算、任务总量及既有数字视图使用同一合并结果，避免旧session.total_tokens覆盖新结算。旧无逐调用记录的任务按已保留审计ID和未归属余量保留计数，不伪造历史精确收据。

超时工具若结果未知，保存有界未知份额的墓碑；保留“未知”及可能费用，不生成事实。丢失worker只有准入记录时，保留未结算及原期限，不能证明仍在执行，也不能推断免费；实际供应商账单仍需独立核对。原当前执行／计划／权限校验继续拒绝迟到正文。取消终态不会被通用异常处理改为failed，也不会被迟到成功改为completed。根结束时从DB同步既有Harness镜像并清理活动标记，镜像不拥有恢复授权。

## 实时事件与重连

发布到读者前使用当前主体／任务／execution及非取消状态的DB共享行锁，并持有至事件入队；取消更新锁与其串行，避免权限检查后、入队前的竞态。终态事件不再持另一个更新锁等待发布锁，避免同一根自锁。披露投影仍先处理完整事件，再保存历史。

每个订阅者拥有100项有界队列，500项任务历史用于重连，多个页面不再消费同一个队列。捕获历史与注册订阅在同一锁内进行，历史不会再次作为实时队列重复发送。事件有进程epoch／sequence ID；同进程Last-Event-ID可续读，重启后不假装旧内存历史仍存在。超出保留窗口／慢订阅者丢失旧事件会标delivery_gap，界面重读本人保存结果；事件流不是永久事实存储。

订阅同时绑定原凭据、owner和订阅时execution；读取历史和每次发事件前再次确认。执行替换后旧连接关闭，旧执行事件不能关闭新一轮连接。客户端不依赖事件推断报告是否全部完成，完成资格仍来自当前持久化状态、完整审核和交付视图。
