## 数据与状态所有者

公开资料归档后仍由owner／任务／组控制可见性，不能把“仅本人保存”误写为内容机密。新增公开归档事件保存服务器计算的实际正文身份；当前访问快照仅在该事件与实际owner、source_id及正文版本匹配时携带`adrs-public-archive-origin-v1`依据。它不来自可编辑metadata，不授予额外读取权或模型许可；修改原文生成新source_id，不继承旧原文的公开证明。旧事件缺少正文绑定时不回填猜测，仍沿保守分类。只接既有事件／访问快照及RAG消费，无新DDL或迁移；待统一完整旅程证明。

`app/source_lifecycle.py`是普通函数及请求契约，没有新增Agent或服务。三张表分别负责：`document_source_lifecycle`当前策略与版本族；`source_access_epochs`本人可见范围版本；`source_lifecycle_events`参数绑定、修订原因、前后状态、实际结果及关联报告。事件不保存重复正文，删除原来源后事件仍保留。

同族当前项唯一，切换先在同一事务退役原项，再启用目标。`publish=false`的新修订保留为候选，不替换当前。新修订继承真实生命周期策略，索引用当前head而非初始metadata快照；处于direct的来源不因旧dense配置重新编码。需要稠密的新正文修订会按当前授权模型配置重新编码，其调用数和未知费用沿04如实保存；词项维护本身不调用模型。

全部生命周期写先取本人事务锁，再取来源锁，与上传、标签／分组修改保持同一顺序；预期revision不符409。同owner的request_id跨动作共用参数绑定，改参数重用ID拒绝。重复已提交请求返回同一次结果`replayed=true`。单条SQL30秒、锁等待3秒、显式写操作总45秒，取消和错误回滚，不另启动后台作业。

当前head切换和epoch在同事务提交。事实修订保存前驱、旧解析版本及局部范围，报告关联来自该owner任务账本的`source_document_id`，最多50条／来源并保留更多标记；旧缺账本关联显示未知。关联表示报告曾使用该来源，不表示所有结论都错误，也不自动重写报告。

## 查询与历史引用

新资料默认`task`，task_id为null时只用于本人直接定位；填入时核对真实研究会话owner。`group`要求调用实际指定同组；`owner`是本人明确允许跨任务复用，仍只返回同owner资料。owner和当前会话来自服务端执行器，模型工具不能提供可信session_id。创建时policy是初始快照，实际生效策略以生命周期表为准。

FTS、BM25和兼容精确向量都限定当前／retained／active／有效期和复用范围，BM25的N、DF使用同一范围。RAG在重排后与父级／原文开头扩展前后复核当次revision；返回证据保存实际访问策略、绑定和实际任务、分组、有效期、检查时间与revision。索引关闭后返回前复核同样拒绝原候选。

继续综合、审核或生成新报告时，会复核保留的内部证据。权限、任务、版本、有效期或数据库状态无法确认时，排除该片段及依赖它的旧分析视图，保存`evidence_access_gaps`并显示缺口；不会删掉账本原文。恢复可用后需要重新取证，不能悄悄把曾排除的旧片段重新放入分析。检查发生在候选／扩展／综合边界，不宣称能撤回已经发送给模型的数据。公开证据沿原来源准入和任务隔离。

本人读取旧报告继续消费当时独立保留的任务证据，来源修订、索引重建、Tombstone或purge不把新正文冒作旧依据。永久清理来源与删除一个研究任务是两种不同操作。

## ACI

除下表新字段，保持既有认证及实际owner约束；读操作不触发采集、模型、索引写或后台清理。

| 接口 | 输入与输出／效果 |
| --- | --- |
| POST `/api/v1/documents/sources` | 既有请求加`retention_policy`；默认`{reuse_scope:task,task_id:null}`；可选group／owner，valid_from、valid_until、purge_after为带时区日期。进入接入幂等并匹配实际生效策略；返回access_epoch |
| POST `/api/v1/documents/upload` | 加`retention_policy_json`，最多4000字符；批次固定开始时策略，单项同事务提交。本人任务不存在或归属不符422 |
| GET `/sources/{id}/lifecycle` | 本人只读同一快照：当前状态／revision／范围、解析版本、最近50个同族版本及更多标记、最近20事件、维护取舍及epoch |
| POST `/sources/{id}/versions` | request_id、expected_revision、expected_parse_version、reason、mode=replace或patch、text、format=txt／md／json、publish默认true；patch另需start/end，按原文Unicode字符、左闭右开。旧缺parse允许明确null做全文替换，原位修订拒绝。返回新source_id／前驱／族／当前状态及受影响报告 |
| POST `/sources/{id}/lifecycle/actions` | request_id、expected_revision、reason和action=tombstone／restore／activate／set_access／purge／cleanup／prune_indexes。set_access才且必须带policy；prune_indexes才且必须带过去时间before。返回实际状态、删除／清理ID、epoch、前后策略和关联报告 |
| POST `/sources/publish` | request_id、reason、1至20个唯一`{source_id,expected_revision}`；同族不能选两个；全部切换或全部回滚。只发布已有表示，不调用模型 |
| DELETE `/sources/{id}` | 旧入口改为可恢复Tombstone；重复调用已隐藏项不再修改。永久删除使用上述purge动作，不能误把普通删除当物理清理 |

Tombstone停止新召回并保留原文；restore在同族无当前项时恢复为当前，有其他当前项则仅恢复保留，用户另选activate。归档或Tombstone来源不能直接发布。purge只允许非当前且已隐藏，或非当前且达到明确可清理时间；cleanup只处理本族已达到该时间的旧版本。prune_indexes只删除截止前retired且无head引用的代际，保留原文及当前索引，清理后目标回滚返回不可用。

非本人／缺失404，旧revision／parse／修改同请求参数／无效发布与清理409；结构错误422、超限413、解析400。503或网络丢失不能推断请求一定未提交；界面保留原请求和ID，用同一请求确认结果。已明确拒绝可刷新后重新操作。持久事件先于重放返回，不因purge后的来源不存在而丢失已提交请求结果。

## 交互与部署状态

共享RetentionPolicyPanel连接文本、单文件和文件／目录批次；新资料默认仅绑定任务。资料详情可查看当前版本及策略、填写原因，选原文片段自动换算Unicode字符范围，保存全文／局部修订或候选版本；隐藏、恢复、切换、永久清理、到期旧版本及旧索引清理均显式操作。已选列表可读取1至20项的状态供审阅，再原子发布；读取不等于发布。

界面显示loading、过期冲突、结果未确认、同请求重试及实际返回结果。列表普通删除标为“隐藏（可恢复）”。没有后台进度假象；每次动作是有界请求。当前页请求身份在页内保留，刷新后应先读当前版本和事件确认状态，不承诺未保存的浏览器表单跨刷新保留。

DDL加入原初始化与迁移，不自动回填／认领旧数据，不运行部署或服务重载。旧无lifecycle资料仍可由本人管理，明确分组查询保留；无范围检索不会默认加入。首次维护可按原明确分组约定建立记录，不能将无owner行绑定当前人。
