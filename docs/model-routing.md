## 路径与配置

确定性工作继续直接执行：来源过滤、统计、结构／引用校验、内置图表、文件渲染均不增加一轮模型思考；固定种子和适用的固定计划保持原路径。需要模型时，原Planner、Analyst、Reflection、Report和绘图计划阶段从已配置主服务选择模型，不引入新Agent或新服务注册表。

当前模型设置API支持`routing`，前端高级设置可编辑并保存；环境变量可使用`LLM_ROUTING` JSON。默认关闭，继续使用已配置主模型。启用后仅使用明确配置的候选，先检查provider、阶段、JSON／流式能力、配置质量档位、public/private许可和上下文容量。候选没有通过条件时停止，不通过模型自报置信度扩大权限。质量档位是配置声明，不是能力认证或效果测评。

新根同时冻结查询解释的复杂度及深度。深度／复杂研究的分析、核对和写作采用配置档位3；简单规划及受限绘图计划可使用档位1，其余采用档位2。请求记录同时保存所需档位、格式能力和容量，便于核对选择依据；这些档位不等于真实模型得分。

同等可用候选中，存在完整配置报价及其来源时按阶段保守输入规模和4096输出Token比较估算；价格未知候选不视为免费。没有可比较报价时，优先保留合格的原主模型，否则按显式配置顺序，记录`eligible_price_unknown`。当前比较不含缓存折扣、供应商动态计价或实际账单；这类未知不补默认金额。以下仅为结构示例，模型名称、容量、价格与许可须由服务配置者按实际资源填写：

```json
{

  "candidates": [{
    "route_id": "authorized-main",
    "provider": "deepseek",
    "model": "deepseek-chat",
    "stages": ["planner", "analyst", "reflection", "report", "render"],
    "capabilities": ["json", "stream", "text"],
    "quality_tier": 3,
    "data_classes": ["public", "private"],
    "context_tokens": 128000,
    "input_usd_per_million": null,
    "output_usd_per_million": null,
    "price_source": null
  }]

```

示例不是对该型号实时上下文、能力或价格的核验。没有配置第二模型时只有原服务路径，不能声称存在便宜模型选择。Cortensor没有独立已授权配置，不自动加入或调用。

## 请求、用量和恢复边界

新根任务保存`model_routing`快照，含非秘密的端点身份、主／备模型、策略、资料类别和深度；不存密钥或请求头。模型工厂只构造原服务内的候选客户端。端点URL不支持内嵌凭据、query或fragment，不能遗漏这些部分后错误地声称同一端点。

每次实际请求前检查端点、主／备身份与路由策略是否仍匹配，变化后停止下一次请求；恢复继续使用同一快照，不能借恢复切换服务或增加预算。凭据仍由原配置工厂提供，现有服务仅支持单管理员配置语义，不宣称已实现多租户密钥代理。旧任务没有该快照时保留既有legacy工厂行为，不把新的冻结保证追认为旧任务已具备。

分析与写作在装配可选上下文前取得候选容量，并与原阶段额度共同限制消息装配；实际消息仍在可信请求边界检查容量。所有调用复用原`ModelTokenBudget`，没有第二本预算。请求记录保存真正执行的阶段／provider／model、选择原因、排除条件和报价来源；fallback客户端有自己的身份，不把备用请求记为主模型。

供应商原生Token用量与费用依据分别记录。配置报价只生成`configured_price_estimate_not_invoice`，不是账单；没有报价保持unknown，未知用量继续保守占用。路由拒绝、配置变化与容量不足在请求预占前拒绝，不把未发出的请求伪装成计费请求。研究工作区可展开实际路径，报告正文不显示这些运行字段。

## 故障回退与能力升级

服务故障回退只在尚未取得有效响应时使用现有备用配置；必须有备用独立密钥，不借用主服务密钥。私有资料默认不进入备用服务，启用路由时备用还须有满足阶段、质量、容量和资料许可的配置候选。流式报告已经输出后不会自动换服务拼接正文。备用仍复用原计量器，未知费用及未知结果分别保留。

能力处理根据实际结果触发，不使用自报置信度。分析结构输出无效／截断可在既有两次阶段尝试内选择更高配置档位；报告合同错误可在既有一次结构修订前升级；完整语义审核定位到有摘录的矛盾主张，可在既有一次内容修订前升级，随后仍须重新审核整稿。缺少原文依据只记录补证需求，实体身份不明只记录澄清需求，模型升级不替代两者。实验字段缺失继续走同根有界补读。

候选档位允许1—5。升级必须选择不同型号、更高档位且满足原阶段／格式／资料许可的已配置候选；不能临时创建服务或将别名当作新能力。较大上下文升级允许相同或更高档位，但必须容量严格增加、原根剩余额度大于旧容量；根额度已经成为限制时不升级。原文已经取得却未装入本轮分析的情况，可尝试扩大有界上下文至72000字节；这只是装配上限，不能证明语义覆盖完整。

`max_capability_upgrades`是整个根任务的累计上限，默认1、允许0—2，跨分析与报告阶段累计。决定先以`prepared`连同先前原生用量、失败输出／当前稿及审核保存到原owner／execution／plan绑定检查点，然后才允许较高模型派发。持久化失败暂停；已准备的决定保守占用升级名额，重启不自动重试。分析恢复固定已保存的阶段候选及扩展上下文，不回到廉价模型重复升级。缺少该新字段的历史快照不追溯启用能力升级。

升级后的客户端关闭服务故障自动fallback，避免更高能力请求静默降级；原服务故障分支仍独立。研究记录展示准备／拒绝原因和实际请求路径，`prepared`不是已计费调用证明。阶段写入后的旧根快照不得覆盖较新的付费用量、升级记录或修订前稿。Reflection仅在明确Token／时间预留原因时采用原保留最终审核的路径，路由失败不会因此绕过核对。
