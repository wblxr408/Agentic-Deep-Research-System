# RAG论文目录接合ACI

此页对应原架构任务4.3及3.1／5.2的资料侧前置。实现沿现有`document_sources`、来源生命周期、索引和任务快照，不增加目录数据库或缓存服务。当前仅源码完成，百篇全链与真实接受仍未完成。

任务侧现已复用原Analyst phase检查点保存`corpus_progress`，通过现有研究质量接口和“资料覆盖与统计依据”详情投影。其`items`继续表示已接受成果；新增`declared_membership`按冻结集合列出全部来源与不同作品，并接合范围和阅读状态，包含未保留、未筛选及待核项。指定来源读取和状态投影已接源码，问题所需阅读合同、自动补源／增量及最终交付约束仍待接合。

## 资料记录

沿已有`POST /api/v1/documents/sources`，在metadata中可指定：

```json
{
  "research_record": {
    "schema_version": "adrs-rag-research-record-v1",
    "work_id": "work:example",
    "kind": "abstract",
    "primary_sources": []
  }
}
```

`work_id`由已有作品身份或显式导入映射提供，不做题名模糊合并；同一作品可以关联书目、摘要、原文和不同正式版本。kind为`bibliography`、`abstract`、`fulltext`或`derived_card`。这是资料分类，不证明原件真实、模型已读全文或来源主张已核实。旧未分类资料保持未知，不自动补为fulltext。

派生卡必须带`primary_sources`，每项含本人现有的`source_id`和精确`parse_version_id`；入库在原owner事务内核对所属和版本，拒绝以另一张派生卡作为原始来源。引用历史来源不授予当前任务读取权限，也不把引用关系变成事实支持。

记录类型和作品／版本关联参与原入库去重，防止同文但不同身份或原文／派生类别被错误合并。原有解析、分块、嵌入、索引和去重机制继续承接。research_record作为来源身份的一部分，普通元数据PUT不能修改或移除；新资料／版本沿已有接入接口。此页没有实现旧JSON／TSV导入器，也没有导入旧211条资料。

## 目录枚举

`GET /api/v1/documents/sources/catalog`只读取本人资料源的有限目录字段，始终不返回原文／分块大对象。参数：

| 参数 | 合同 |
|---|---|
| group_name | 可选，本人的精确分组，最多100字符 |
| record_kind | 可选，上述四种记录类型 |
| work_id | 可选，精确作品标识，最多260字符 |
| status | 可选，active／archived |
| lifecycle_state | 可选，retained／tombstone／legacy |
| is_current | 可选，生命周期的当前版本标志；旧未知值不冒充true |
| page_size | 1—200，默认100 |
| cursor | 上页next_cursor，不透明、有界，须保持同一查询范围和page_size |

结果含资料ID、作品／记录类型、来源与解析版本、来源生命周期、索引模式／代际、当前页items和next_cursor。每页在只读repeatable-read事务中读取原owner访问代际；资料新增、撤销、版本发布或元数据改变使旧游标返回409 `catalog_snapshot_changed_restart_enumeration`。游标损坏或跨查询范围使用返回422。页序使用时间与UUID稳定排序，旧缺失时间只使用内部排序值，保留其原始时间未知状态。

每项是来源版本记录，不能把100条来源行当成100篇不同作品。`enumeration_complete`仅说明当前快照没有下一页，不证明从第一页完整处理、更不证明筛选／精读／审核完成。后续任务成员快照必须收齐所需页并按作品身份接合；当前没有自动把资料库全部资料塞进研究上下文。

目录列出本人可以管理的资料，含未索引／旧版本／归档／删除状态。列表可见不等于当前任务可以检索或读取；执行时继续沿任务／分组／owner、有效期、当前来源及索引代际复核。筛选与阅读状态属于具体任务，当前此端点只过滤来源状态，未实现跨任务通用的“已读”字段。

## 证据检索与后续深读

现有类型化检索过滤新增work_id和record_kind，SQL表达式由服务端固定，客户端值仅参数化绑定；原权限与当前代际条件仍以AND组合。所有原文证据候选路径及返回前过滤共用的current_document_clause排除derived_card。当前派生卡由目录导航，未实现其独立语义导航检索，不以空证据结果冒充无相关卡片。

实际RAG返回从当前来源访问快照取得小型分类信息，并传入Evidence.acquisition。coverage继续为retrieved_internal_chunk；即使来源分类是fulltext，也不能将只检索到一个片段改记为读完整篇或自动完成技术字段。后续原文补窗、逐篇所需层级、已读字段、来源支持和共享补证继续沿原Analyst／技术卡／phase与根产物接合。

本接口没有新模型请求、目录采集后台任务或写入。资料接入仍遵守原功能与模型配置；读取目录不触发重新切块／嵌入，任务筛选状态将独立于来源身份处理。未找到、未分类、未索引、未取得全文、未读、未审核是不同状态。

## 任务阅读与补证状态

### 指定来源的冻结与读取

现有研究请求可在`organization_research.corpus`选择`collection_mode: "rag_corpus"`并提供`rag_source_ids`；这是当前组织研究入口下的资料集合模式，尚未增加前端集合选择器。必须同时启用`use_internal_docs`并在当前工具权限交集中允许RAG。来源必须是本人当前可读、具有类型化作品身份与解析版本的书目／摘要／原文，派生卡不能充当指定原始成员。重复ID、混用种子／搜索输入、非空片段业务过滤及超出现有计划节点上限会明确拒绝。

提交时从现有资料库冻结来源ID、作品ID、类型、解析／内容版本及访问代际，并把集合身份接入原预览确认、计划版本和工具交接绑定。来源条数与不同作品数分别记录；本入口不自动导入资料、不把库中全部资料当作所选集合。当前依赖可用索引／原生命周期准入和安全的HTTP(S)原论文定位，缺少这类定位的私有材料适配仍待后续处理，不因此扩大访问权或自动联网。

原Planner直接生成每批最多两条指定来源的RAG节点，沿原LangGraph／DAG、工具收据与根限额执行。明确读取使用现有PostgreSQL保留文本，不做向量召回、重排或模型调用；普通RAG检索继续原路径。读取前后都复核当前权限／访问代际，正文须匹配冻结解析／内容版本，来源范围声明沿原合同检查。单条失效、文本缺失或超过原解析字符上限时记录`source_read_gaps`，保留同批成功项；不截断成“完整原文”，结果上限不足也不会静默漏掉成员。超长文本的定向补窗仍待接合。

明确读取的`source_reference`定位保留源文本，而非伪造已存储chunk。分类为全文且完整保留的材料只获得“原件可用”语义，不能授予模型全文已读、发表身份真实或事实审核通过。兼容工具的4000字符展示若发生截断，会同步撤销完整原件标志。

原根接纳器对同根、同来源版本／访问代际的稳定证据ID比较内容、来源、可信度和acquisition绑定；完全相同的结果只接收一次正文，记录`retained_evidence_reused`并保留首次取得时间。同ID却不同语义的结果拒绝接纳。该机制减少重复证据进入模型输入，不免除实际数据库读取／工具调用，不虚构供应商缓存命中或事实批准。访问撤销与后续综合／交付继续复用原`current_synthesis_state`复核。

本小模块源码完成，实际运行待验收；指定成员状态投影已接下节消费者，跨分析绑定复用、缺口调DAG补源、审计回流及图文交付仍由原3／4.3／5.2—5.4／6及R8承接，不据此勾选整项或宣称100篇完成。

### 全部成员与范围／阅读状态的关联

质量接口在分析尚未开始时，也从原任务冻结成员投影`declared_membership.sources`和`works`；无匹配保留证据的来源仍出现。来源条数与作品数分列，相同作品的摘要／原文不会重复计为两篇。匹配要求同集合、来源、作品、材料类型、解析／内容版本和访问代际；该投影描述保留快照，不是一次新的数据库权限验证。

原范围构建器只对当前`rag_corpus`记录已校验标题的`primary_evidence_ids`，不使用包含日期、机构等辅助依据的宽泛evidence_ids猜测作品身份。逐批提取后的有效范围判断沿原workflow保存精简关联；RAG文件名不能替代论文标题，原文开头的合法标题证据沿现有原文校验参与判断。最终纳入成果与所选作品通过精确来源引用关联，不做题名模糊合并。一个成果关联多个声明作品、或没有声明原始来源时保留`identity_gaps`。

每个作品显示纳入、另有待核、排除、待判断、身份冲突、需刷新或未筛选状态；只有当前原范围代码明确给出的日期／类型越界才记排除，缺失、未解析或读取失败不推断为排除。一件作品有多个声明来源而只对其中一条有排除依据时，不把整件作品当作已排除。来源版本不再匹配时旧判断成为待刷新，旧阅读绑定不生效时也不展示为当前完成。

字段导读状态沿同一`corpus_progress.items`按成果ID引用，不另存一套导读结果；`full_document_read`与事实支持均不由本投影授予。读取失败收据中的缺口作为`read_gap_history`展示，已有有效保留材料不会因一次历史失败被误记为从未取得。原报告`corpus.declared_membership`消费相同投影；当前可从质量高级详情和结构化结果查看，专门的成员选择／状态界面、Markdown／PDF清单装配和基于完整成员的交付裁决仍待后续接合，不以未被调用的Markdown辅助函数宣称报告已经呈现。

### 逐篇深读字段合同

新创建的组织研究冻结`reading_field_policy: adrs-question-reading-fields-v1`，不迁移未带该政策的旧根。组织研究请求新增`reading_mode`（`question_driven`默认／`all`）及可选`required_reading_fields`（原十种技术字段，最多十项），服务器合并去重后保存。显式all或必需字段要求同时选择deep_dive，否则拒绝输入，不静默忽略要求或增选模块。模式控制全部／按问题选择，尚不提供单独的“仅摘要”深度模式或前端新选择器，材料可用层级与实际已读状态继续分列。

现有两篇一批的初读同时提出`technical_cards[].reading_contract`：profile、简短reason、当前原始来源的basis，以及问题确有需要的additional_required_fields。basis仍经原请求局部passage ID展开和原文字面定位，不能用另一篇或未取得来源作为依据；错误的可选合同不抹除其他有效字段。不增加分类Agent或额外模型调用。

| 导读类型 | 默认必需字段 |
|---|---|
| empirical／unknown | mechanism、experimental_design、baselines、conditions、results |
| theoretical | mechanism、conditions（假设／适用条件）、results（来源定理／结果） |
| synthesis | method_overview、conditions（范围／方法条件）、results（综合发现） |

这些类型是有原文定位的计划判断，不是独立核证或“不适用”认证。缺少类型依据时沿unknown保守字段；所有类型均叠加用户明确要求的字段和有依据的额外需求。初读尽量提供已有材料能支持的必需字段；共享补读只处理各自缺口，reading_focus只是批次并集，不要求两篇返回完全相同的字段。已定位合同可在后续扩大需求，不能静默缩减；重建时按原phase顺序保留合同及冲突。合法重新分类而需缩减字段的显式再评估仍待原依赖／修订任务接合。

明确全部阅读的新任务直接使用全部已纳入成果；深读入口不再额外请求代表选择，landscape也不再生成无用途的全量reading_plan。其余按问题选择继续原计划与理由；缺材料或范围待核不会因此被默认为纳入。旧根保持原选择及条件补读路径。

同一合同用于逐篇required_fields／missing_fields、剩余预测和技术材料交接。综合／写作／读者输入只携带紧凑计划与原始证据ID，完整类型依据留在技术卡和原phase，不反复复制长段原文。读者审核不能强迫理论／综述填实验模板，也不能用错误profile跳过核心结论真正必要的条件、对照或指标。新报告与审核绑定字段政策，未知版本或不匹配保持未完成。未要求仍是未知而非原文不存在，字面定位仍不等于语义支持、全文已读或独立复现。

原Analyst范围识别后登记接受成员；原reading_plan／representative_reading保存选择角色和理由，未选项保留；原两篇一批与字段原文校验结果更新逐篇状态。未带新政策的旧根继续原experimental_design、baselines、conditions、results及阶段所需mechanism条件补读；其他已取得字段仍保留，不把这些字段覆盖称为全部十字段或整篇全文精读通过。

每篇保存实际材料层级、所需／已定位／缺失字段、来源ID／版本（可取得时）及原phase定位。`required_fields_located`仅指现有必要字段有已定位候选，full_document_read保持false，事实支持不会由该状态授予。没有资料或字段返回时留缺口，不据摘要推断原论文缺少内容。

缺字段沿同一个work_id记录，原两篇共享的条件补读仍使用原phase_id和机会；来源未取得全文与有全文但字段未建立分列。恢复在同一有效分析绑定内消费已保存phase结果，再重建进度，不新增补证Agent、目录权威或一套预算。补读结束仍可completed_with_gaps，不能重置原次数或当作字段已补齐。原根参数不变。

adaptive_budget在有效进度／选择合同下按未读成员和去重的待补读phase预测，避免把一次条件补读当作又完成了一批初读。预留只是估算，不批准跳过工作或扩大额度。新增／变更来源使全局分析绑定变化后的精确差量接续、按新缺口调DAG读原文、最终事实／读者缺口回流和完整未入选目录接合仍待继续实施，当前没有“新增一篇绝不重读99篇”的运行证据。

### 分批写作后的报告装配

新任务冻结`report_assembly_policy: adrs-batched-report-assembly-v1`。单次章节写作仍使用原20正文／20附录的有界结构；整份汇总单独支持每模块正文及附录数组各最多2048段，单段、引用、摘要、模块及原根预算上限不变。此资源上限不代表论文数量、写作目标或审核通过，不能通过裁剪凑合装配。没有政策的旧根继续原20段结构，未知政策拒绝。

导语汇总、无损格式投影、引用／统计渲染及后续修订均按冻结合同读取完整稿；归属编辑绑定该政策，不强制完整附录压到单批20段，但仍须逐段唯一分配并解释省略理由。完整候选继续保存在原section／report检查点中，不重建产物存储。新政策缓存的编辑响应必须已完整结束，原事实、读者和图文交付门保留。

当前全局编辑／导语输入及输出、读者整稿分区和超大材料仍待继续接合；装配可保存较多段落并不表示百篇研究、全文阅读或报告交付已通过。仅源码／调用链审阅，无测试或实际研究。

### 完整段落的有界归属编辑

新根冻结`editorial_partition_policy: adrs-editorial-paragraph-packets-v1`，要求已冻结新装配政策；未知／不匹配版本拒绝，旧根保留原整包选择。当前仍是原Report的编辑动作，不是新Agent。每包最多32个完整编辑段落、48000 UTF-8字节JSON，实际派发另经原上下文／8192输出及根预算准入。超限分裂当前分区，单段连同邻段／反馈超限时留缺口，不截段或省略成员。

局部别名绑定原模块／正文附录角色、原段落及重复出现次序，相邻段落只读并参与输入绑定；不从题名猜作品身份。每个编辑ID恰有一个主文／附录／省略去向，只读ID不得作为编辑目标。局部模块允许没有主文，整体装配仍需全部模块的实际主文。重复省略须列同包未省略的`retained_in`，无关省略须解释与问题的关系；跨包不确定重复先保留，局部计数不是语义覆盖或全局去重证明。

所有包完成后按原文顺序汇总，只移动／选择原段落，不改写事实、引用或统计占位符。原检查点保存计划、派发状态及每次原响应，最多一次格式修正且先保存机会；JSON围栏可以无损投影。缓存按完整实际消息／模型／路由／政策匹配，再校验当前映射与完整分配。缺保存回调不派发；未知派发缺结果不重发，明确未派发可继续原机会，候选不计当前复用。原根剩余预测按待审包及导语更新，不增加额度。

主图复用原section候选保存；结构修订沿原section编辑保存回调。分区不代替整稿连贯性、来源和读者审核，不授予交付许可。全局反馈目前完整保留于包，过大反馈明确缺口，按需反馈依赖、跨包排序、导语与完整读者分区继续原TODO。仅源码／调用链审阅，无测试或实测效果。

### 读者审核材料包

新根冻结`reader_material_policy: adrs-reader-owned-material-v1`，报告结构与当前审核必须一致；未知／不匹配政策保持未完成。未带政策的旧根仍用原整类材料请求。此处沿现有Report、预算客户端及原模型检查点，没有新增Agent、RAG索引、缓存服务或第二状态库。

全局读者仍接完整报告和接受作品表，同时看到技术／行动归属及默认段落布局；返回`material_contexts`，用`owner_id`和当前`paragraph_ids`补必要定义、条件或跨章引用，`*`表示共享上下文，无补充必须显式`[]`。这只导航当前稿，不授予事实支持。默认范围来自当前字段／导读合同和原始作品定位的精确证据引用、题名字面匹配及邻段；题名只定位文字，不合并作品身份。来源依赖不含被撤换字段的历史依据。

技术和行动分别按稳定owner ID分区；超限时仅分裂对应分区。单包最多8条完整记录、JSON最多60000 UTF-8字节，包含必要上下文、范围和来源依赖；不截字段、不缩小全部阅读要求。单条超大保留明确缺口，其他包仍可处理。分包中的局部段落ID绑定文本、模块／章节角色与引用，重复段有出现次序；复用原响应前按当前包绑定重验，再将锚点映射回当前报告ID。无关位置变化可以保留命中，必要上下文或来源变化使对应包失效。

仅按问题选择且该包所有技术记录均被整稿明确排除时，材料审核可以在独立判断“不丢失本问题所需知识”后返回无锚点通过；全部阅读模式不启用此例外，整稿排除本身不足以通过。其他通过仍需当前包的真实引文锚点；多个包的缺口全部保留。全局与材料复用键分开：前者绑定实际全局输入，后者绑定实际包、政策、模型和路由。当前完整计划、全部必需包及整稿均通过，才满足交付读者门。

原检查点立即保存每个全局／材料及适用的重复影响复核原响应与完成状态，付费原文不是审核批准；中断恢复重新解析并校验绑定与锚点。新政策主图先按当前报告身份选择Root检查点，再选审计快照，避免较旧快照遮住已付费原文；仍须实际输入绑定匹配才可复用。尚未重验的材料／影响候选不计完成，也清除历史命中标记。原收据携带内容单元标识；同内容已派发却无原响应时保持未完成，不自动重发。影响复核单独绑定实际全局输入、复核材料、模型及路由，必要复核的截断／未重验结果不能通过读者门。预算预测仅增加当前待审包的剩余工作下界，不扩大根额度。当前主图调用链提供逐响应检查点；兼容修订入口仍沿其原保存／恢复路径。

新根还冻结`reader_coverage_policy: adrs-packet-work-coverage-v1`，要求已冻结材料政策；报告与配置不一致或未知版本保持未完成。整稿继续完整阅读与整体选材判断，其work_coverage返回空数组；逐项去向由当前技术材料包同时输出，无技术卡的已纳入成果进入coverage包。包内`coverage_work_ids`逐项唯一返回去向／当前局部段落ID／问题相关理由，非排除项必须实际定位且主文／附录层级一致，随后重映射并和全部已纳入成果再次对齐。行动包返回空去向数组。所有包仍最多8项／60000字节，新结构请求上限4096输出，旧根沿原2048材料输出及整稿去向合同。

全部阅读时排除不能取得satisfied；缺报告位置可保留gap／修复说明。按问题选择且全包均独立判断为合理排除时才可无锚点通过，任何重要知识丢失仍是缺口。覆盖集合完整不是事实或知识完整证明；整稿、每个当前包、完整逐项集合及原审核门都有效才满足读者交付。原响应保存／复用、未知派发不重发和待审包预测直接承接，不增加一轮同材料判断。冻结语料的未纳入／未判断成员继续原范围及交付任务，不从该已纳入表反推全集已读。

全局完整输入仍有原120000 UTF-8字节上限；其分区及复杂上下文输出容量、超大单条材料、主题写作／百篇附录、完整语义依赖和审核缺口回流继续原TODO。本模块不能证明100篇交付、事实核验减免或实际降本。
