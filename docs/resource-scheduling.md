## 输入与消费者

| 输入 | 用法 | 输出消费者 |
|---|---|---|
| 已用、在途、总额和原起点 | 计算可分配余额和剩余时间 | 模型调用准入、工具限额 |
| 已完成分析阶段、选择计划和深读批次 | 估算待完成分析批次 | 分析阶段上限 |
| 当前输入及执行绑定有效的完整候选 | 将整稿生成需求改为保留一次编辑需求 | 写作预留；复用仍由原恢复路径判定 |
| 草稿段落或待写模块、当前稿已结算审核调用 | 估算声明、读者及图文审核工作 | 审核Token和时间预留 |
| 已结算且取得响应的真实调用 | 分析／写作／审核各自取用量上四分位加25%估算余量 | 阶段需求估算 |

缺少历史样本时采用显式启发式初值：分析8000、写作6000、审核6000 Token／预计批次，再加25%估算余量。这不是模型价格或精确成本。真实请求的文本上界、上下文限制、工具参数和最终质量门仍独立生效。费用仅展示已知余额；价格信息不完整时不伪造完成费用预测。

## 调度与恢复

阶段入口、请求装配时的额度读取及调用准入重新计算。已结算消费、在途请求、检查点阶段成果或当前候选变化会影响下一次决定。当前阶段允许量与未来预留之和不超过原余额；当前调用已花和预占只用于保留原计量基准，不作为新增额度。

若预计需求能够容纳，按剩余需求保留写作和审核资源，其余供当前阶段使用。若不能容纳，按必需需求分摊余额并记录预计缺口，避免下游预留占满余额导致上游完全无法推进。该安排允许继续完成可承担的必需工作，但不承诺整个报告必然完成，不自行缩小研究范围、删除重要内容或增加额度。

时间预留同样按剩余工作调整，所有阶段deadline始终锚定原根截止时间。新候选会重新计算审核需求，旧稿已用的审核批次不抵扣新稿审核。审核预留仅在原完整审核释放条件满足后停止调度，不因估算“剩余审核为零”而判定通过。

在策略4下，同一分析阶段连续两次同类服务、连接或超时失败且未取得响应，停止自动重试；未知消费继续计入账本，保留原成果和失败记录。既有尝试上限、恢复绑定、模型选择和用户控制不变。调度器本身不启动恢复、改换模型或发起研究。
