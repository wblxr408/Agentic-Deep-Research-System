# 代表成果深读契约

状态：7.5 的数据、既有 Analyst 调用、报告与预览接口已接入，**尚未运行验收**。遵守最新要求：先完成整个 TODO 的实现，再统一端到端验证；不运行逐项研究、冒烟、回归或其他门禁。

## 职责和输入

`app/organization_deep_dive.py` 提供普通数据契约和函数，不新增 Agent、模型服务、图数据库或出站权限。仅在选择 `deep_dive` 时，为现有 Analyst 加载相应结构化字段和有界原文窗口。来源仍由现有工具在来源与预算限制内取得；不会为深读偷偷下载链接。

输入 `organization_data.technical_cards`，每张卡绑定当前采纳成果 output ID。字段包括研究问题、已有方法局限、方法概览、机制／架构、创新主张、实验设计、基线、适用／复现条件、来源报告的结果、结果局限；每个提供的字段必须有字面原文位置。最多 20 张卡，每字段至多 5 处原文、每处 2400 字符，图表／公式引用至多 20 项。模型缺项或原文不支持时保持 unknown，不用生成文字补齐。

没有明确代表成果提案时，只列有界样本的前三项为待补卡，记录 `bounded_sample_fallback_not_quality_rank`，不称为质量最高或最具代表性的成果。

## 全文、摘要和定位

完整 PDF 来源须确实保留全部页和位置且未截断。HTML 须保留单一主成果的 citation 元数据、具有实质正文的方法和结果段落及参考文献标记，且未截断；只有目录或摘要不能满足判定。该判定是采集文本完整性依据，不是独立语义认证；图像、扫描内容及复杂表格仍可能缺失。

论文落地页保留明确文档链接，但不跟随。另一份已取得 PDF 只有在原出版页实际链接到它时，才能作为该成果的深读来源；不靠题名相似合并陌生论文。调用方不能把任意证据或新 URL 替换进当前快照。

摘要／元数据可支持研究问题和方法概览；其他详细字段必须引用已取得全文。字段缺全文、引用不在原文、数值不在所引段落或成果关联未成立时保持未知／待核。字段有字面引语仍不等于语义主张已验证，更不等于独立复现。

输入给模型的是带字符范围的有界窗口：优先首段、方法、实验、基线、结果和局限，复用当前上下文总预算。完整原文保留不变，模型不宣称阅读未传入的段落。摘要定位元数据只传范围，避免重复大段摘要占用上下文。

PDF 引语由真实页偏移反查页码，不能填写未覆盖页。图表／公式名称需字面出现在定位引语中；只有定位时标 `source_reference_only_not_image_acquired`，不生成伪原图或假装已取得图像。页面提供原文链接，原文引用与以后系统绘图分开。

## ACI 与交付

`GET /api/v1/research/{session_id}/technical-reading` 返回新研究保存的卡片；旧会话仅基于现存采纳成果提供未知／可用性投影，`persisted=false`，不重新调用模型或回写原报告。

`POST /api/v1/research/{session_id}/technical-reading/preview` 接受有界 technical_cards 提案，只对本人保留证据作定位与资料级别判断，不取新证据、不保存为已核事实。认证、owner 和已完成状态与关系视图共用可信读取边界；401／404／409／422 含义沿用[关系 ACI](organization-relationships.md)，原文不可用时保留缺口，不自动扩大来源。

新主流程把深读对象保存到 `organization_result.technical_reading` 及报告摘要，Markdown 追加字段及位置，界面／离线 HTML 使用原生折叠，JSON 保存完整卡片和未接受字段。它与选定模块一同装配，不给未选择深读的任务增加成果专题。
