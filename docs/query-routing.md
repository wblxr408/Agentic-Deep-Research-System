# 查询改写、通道选择与份额

对应OPT-09.1—09.9的最小路径。源码已接入，尚未运行API、搜索、模型或任何检查；统一端到端须等全部TODO实现完成。

新查询可设置`max_query_variants`（1—4，默认2）和`term_aliases`（最多16组，每组1—4个别称）。预览和创建均由原QueryOptions校验，别称组大小写归一后不得重叠，随后进入解释身份并冻结。界面按“原词 | 别称1 | 别称2”编辑。旧快照缺该配置时只使用原查询。

原查询始终第一优先；后续依次尝试明确别称及当前对象／时间补全。原词和别称可双向替换，技术标识保留词界；不增加独立模型改写或自发扩展学科词典。Planner已有的独立子问题仍是不同计划节点。显式平台前缀和完整URL不做普通改写；会改变传输渠道、超长或重复的候选不派发，留存原因。查询别称不证明作者或机构确实为同一实体。

每个实际变体在取证前经过原来源策略。限制出版商／学术索引／官网范围时只使用web传输，并对每个变体附既有域名条件，结果仍逐条准入。渠道选择仅取当前已选平台或显式平台；配置禁用、登录态及平台能力继续由ChannelService强制判断，不自动授权其他渠道。检索计划保存选中／跳过原因，不能把未执行的平台说成已覆盖。

根传下的剩余调用份额先在本批步骤间分配，再在变体和已选渠道之间分配；每次真实collect仍有原总额度和期限。Top-K取原任务结果上限与平台20项上限，超时按剩余步骤和待执行请求分配。后端故障备选也消耗该份额，不复制额度；后续步骤只按剩余份额执行。此处为确定性份额规则，没有建立未经验证的质量预测器或动态最优性承诺。

实际查询、渠道、分配份额、持续时间和结果写入工具历史与轨迹；工具面板显示实际查询并可查看完整文本。报告正文不添加这些运行字段。搜索片段仍是线索，全文读取和事实核对继续独立。

词汇查询沿原精确词／混合语言词面表示；内部稠密检索仍要求已有显式开关及兼容模型／索引。学习稀疏、配对多向量及CLIP文本查询编码函数已支持真实本地模型、固定版本和有界时限，但当前检索流程尚未把它们派发至新增通道；来源上的对应特征或索引不等于查询成功。行为查询仍没有合适的授权数据。渠道质量仅记录实际结果，未知费用保留未知。搜索工具旧多步骤入口取消额外LLM扩展，缺少冻结配置时保留原查询。

CLIP查询使用同一个模型和处理器的文本投影，记录实际模型／词表profile并验证维度、归一及输入token上限；超长查询不静默截断。学习稀疏和配对查询也使用对应文档表示的编码方法与profile，运行时由原剩余期限限制，未配置模型或失败不产生伪造向量。实际用户选择、兼容过滤、通道调用及独立失败回退由OPT-11接续，完整质量与资源成本待统一端到端。

控制点为`app/query_rewriting.py`、查询解释、根search_node和SearchAgent渠道调用；不增加Agent、依赖或状态所有者。增量沿用A2ABreak **v1.0**：A2AB-01《技能声明验证与委派准入》工程1/3/4（目录声明与真实调用分开）、A2AB-03《上下文归属与跨租户隔离》工程1—3（当前owner及冻结槽位）、A2AB-08《结构化授权请求与权限不放大》工程1—4（变体不扩大来源或渠道许可）、A2AB-10《委派环路检测与全链预算》工程1/3及T3（原根份额及期限）。其余既有11项评估继续适用；没有新增外部A2A协议。这些是待项目验证的工程建议。
