## 1. 状态与证据口径

| 状态 | 含义 | 下一步 |
|---|---|---|
| 已交付／历史证据 | 对应范围有实际记录，仍受当时输入、版本和环境限制 | 复用；只适配本次接口变化，不重做原功能 |
| 已实现待验收 | 选定源码路径与消费者已接入，当前完整业务证据未齐 | 审阅接线、部署条件及差量，在所属完整旅程取得证据 |
| 部分实现／待补差 | 已有基础，存在明确未完成范围或本次行为变化 | 只补表中列出的差量，不重新实现整个模块 |
| 待实现 | 目标已确定，尚无对应完整实现 | 进入唯一工作包，按依赖顺序开发 |
| 继续冻结 | 已明确暂缓，当前不实施、不启用、不为其等待 | 保留解除条件，不能由模型或工具发现自动解冻 |
| 外部条件未具备 | 缺少授权数据、服务配置、设备或真实使用者 | 独立列缺口，不把它算作代码待开发或故障 |
| 候选未选用 | 技术目录中的备选方法，尚非实施承诺 | 保留选型理由，不转成必须补齐的功能 |
| 历史终止／保留记录 | 原任务已达到原期限／次数或被明确停止 | 不再调度该根；通用能力的新证据不能追记成旧根成功 |

判据顺序为：当前用户范围 → 同能力的较新源码／任务及实际记录 → 旧账本／目录。`[x]`可能表示源码交付，不能统一解释为业务通过；未勾选也可能只欠验收，不能统一解释为尚无代码。运行参数和版本的冻结，与功能暂缓分别处理。

状态依据为本机保留资料与只读源码审阅，不是在线服务检查或新业务验收。若同一项后续已有更晚证据，应沿本页维护规则更新，保留旧事实。

## 7. 防遗漏、防重复和状态回写

1. **先定位一项功能的唯一归属。** 开工记录F／A编号、主W、原任务ID、实际消费者及缺口；某能力已有源码和消费者时只补差量或等待Q，不创建同名模块。
2. **实现职责只分一次。** W02审核政策、W03内容依赖、W04复用失效、W05原准入／机会、W06职责与必要接线、W08最终裁决／呈现。研究决策仍由原Planner／replan承接，W07不在当前执行链；其他工作包不复制审核或预算。
3. **共用证据而非共用结论。** 同一真实旅程可引用到多个原任务，回写时逐条列出覆盖／未覆盖及具体产物。一个合法成功不能证明所有权限、取消、并发、模型或可选通道。
4. **状态按两层维护。** 完成代码记录源码／接口及所属提交，功能保持待验收；实际Q完成才更新其具体复合任务。历史已终止根只保留失败和费用，不伪造补验成功，不让它永久占据待开发队列。
5. **一根一份实际合同。** 旧根不随部署改变控制、模型、Skill、范围或预算；实际政策回退只影响后续根，当前根保持兼容或明确暂停，不因质量调整另建运行器。
6. **旧清单作为索引和历史。** 本页负责全局排序和承接，原OpenSpec负责细项记录，专项文档负责真实结果；需要变更优先级时先改本页，不分别修改多套排序。每次实际状态变化同步本页对应行和原任务，冻结解除保存明确依据。
7. **保留本机及云端边界。** 当前有大量未提交工作，实施前核对任务分支和安全转移，再遵循项目默认云端编码偏好；保存偏好不等于当前已在云端。Windows／数据库／浏览器及PDF实际接受仍在所需主机完成，不用云端样例替代。
8. **安全控制沿既有执行点。** 复用[架构设计D11](../openspec/changes/refactor-single-research-agent/design.md#d11-安全基线与本次适用性)的A2ABreak v1.0全部11项适用性、标题、章节和控制点；本页只归并实施，不新增协议或信任边界，不宣称安全已验收。主Agent／Skill注册和结果准入对应A2AB-01，来源归属03、事件出口04、完整产物05、事务版本06、授权交集08、根预算10、租约11；02／09仍无新增远端Card／多跳身份。已有GitHub入站通知保留签名／仓库／限额绑定；A2AB-07《Webhook归属验证与受控出站》v1.0工程2／4在既有[接入ACI](task-evidence-ingestion.md)中用于实际源读取和次数，不把它混成新任务出站回调，也不以出站控制权证明不适用为由删除入站功能。
