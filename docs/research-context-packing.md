# 全文上下文与读者报告

对应 OpenSpec `add-complete-research-delivery` 4.5，以及 TODO FLOW.3/10/11/12。此次沿用现有 Analyst、Report、审核器和根预算，不增加 Agent、数据库、模型路由或框架。

## 材料如何进入模型

`app/research_context.py` 在每份保留证据中选择方法、实验、问题相关段落及身份信息。标题定位排除 PDF 会议封面；实验检索保留硬件、模型、负载、基线和 SLO 线索，避免只按论文名命中参考文献。该过程是确定性选段，不是语义阅读或事实确认。

各来源共享有限空间，预算不足时保留较少来源的实质段落，记录未进入上下文的证据 ID；不为声称覆盖所有论文而只传几个字符。引用编号始终对应原证据顺序。每段保留原始字符范围、页码、证据身份与解析版本；选段内容可以直接在原文切片中重取。全文在任务证据中保留，模型未收到的段落不算已阅读。

输入装配按 UTF-8 字节控制负载，并按可信 `request_token_bound` 对最终消息、输出空间和剩余阶段额度再次计算。它不是精确 tokenizer，也不负责结算。正式调用仍经过同一个 `ModelTokenBudget`，费用和 Token 只按既有原生用量／未知用量预占规则结算，审核预留不释放给写作。分析、报告分别保存 `analyst_context`、`report_context`，含选段、遗漏、原文取得级别及未评估的结论覆盖。

分析保留 `analysis_text` 与 `organization_data` 两个根字段，减少重复叙述和证明副本；原有结构化成果、关系、技术和行动契约仍适用。报告按剩余额度分配输出空间，整段选择分析，完整选择统计记录与来源摘录，避免从 JSON 中间截断。预算不足以携带基本输入时仍应暂停；输出截断不作为完整分析使用。

分析和写作使用`_synthesis_question`投影，只保留实际问题、冻结对象／学科／时间、目的／模块、行动需求及补充约束／自定义页，不重复注入规划阶段的权重和出站契约。原工具准入仍消费完整冻结配置。空间有限时兼顾首个全文与机构背景材料，原始引用号不重排，避免所有空间都被靠前论文占用。

## 正文与图表分别记录完整性

PDF 正文采用已有 pypdf 读取原生文本流，pdfplumber 继续负责表格及图像位置。原有按水平坐标拼接一整行会把左右两栏混为一句，已改为页面原生文本；没有原生文本时保留已有单词／OCR 路径。原生流顺序仍需实际阅读核对，不声称所有 PDF 的阅读顺序或公式正确。

正文页、字符或 OCR 截断仍使正文不完整。单页表格候选达到上限、图像候选受限另记 `structure_truncated`，不再把已保留的全部正文降为缺失全文。文字完整不等于表格、图片和公式均已取得；表格内部真实截断仍按现有保守规则处理。解析引擎及实际版本保留在研究记录。

## 报告的阅读层次

通用模块契约增加 `summary` 与每模块 `appendix`，旧的只有 `paragraphs` 的数据继续可读。主文回答研究问题、比较机制与选择条件；逐篇实验、方法和资源细节进入技术附录，取消每模块固定一至三段。篇幅由证据与问题决定，仍受有界输出限制。

主文、概要及附录共用引用编号、统计占位符校验和转义。附录不能绕过来源或统计校验，也不能注入 HTML、标题和额外模块。预设第一页保留核心判断，技术附录在界面与离线 HTML 用原生折叠；提供主文／附录 Markdown 下载及分别打印，完整 Markdown 与 JSON 继续保留全部内容。

技术对照表直接消费已定位的技术卡字段，显示问题、机制、实验条件、来源结果和引用。不从正文猜测数字，也不把不同实验的最高倍数绘为性能榜；没有定位字段时不制造对照数据。该表是内置渲染，不是已执行用户绘图 Skill。任意学科／对象仍消费同一模块和字段，专业绘图适配器另列待办。

## 最终审核的上下文

审核请求改用主张的 `excerpt_ids` 与共享摘录表，同一批次相同摘录只传一次。原始摘录、完整定位和判定仍在结果中保存；模型仅可引用本主张列出的摘录，服务器继续验证证据身份和字符位置。采用较小的两个检索窗口减少重复原文；这会影响主张的条件覆盖，必须通过真实审核观察遗漏，不能把缩短输入视为准确率提升。

审核仍是模型判定及服务器原文位置校验，不能等同人工复核。未检查的主张继续导致审核不完整暂停；不会为了完成状态删除未审项目、重置预算或把未支持项写成通过。

实际运行发现模型结构／统计绑定错误曾被替换成空章节后仍完成，现改为`ReportContractError`失败并保留原稿、验证原因和用量；历史错误报告的`delivery_complete=false`禁止正常下载。允许同一预算／截止时间内最多一轮修订：可定位的段落错误只请求被拒文本的修正，服务器锁定原段落类型和引用，再统一验证；结构本身无法解析时才修复整稿。修订不是事实审核，仍须经过最终来源判断。

## 当前验证与后续

当前变更的九项消费者行为完成对应失败到通过：多篇论文方法／实验和位置、有限额度内保留实验内容与机构联系资料、主文附录与预设核心判断及独立引用、来源字段技术对照表、长双栏 PDF 及表格结构上限、有限额度内审核全部指定主张、原生控制字符真实数据库写入及原文恢复、无效稿不完成／不交付、一次有界段落修订。当前文件曾9 passed；后续针对扩展的配置投影／机构材料和局部修订两项又先失败后通过。没有运行历史回归、冒烟或浅探针。前端 TypeScript／构建已通过；既有权重编辑器重复属性改为同义默认分支，构建仍提示主包较大。

实际研究和质量结论见专项记录；实现接入不能代替真实自动报告及用户试读。按问题拆分长分析、完整条件跨段召回、声明式自定义比较图和受信绘图 Skill 仍须继续完善。

## 安全方案适用性

沿用现有 11 项评估，本次没有新增 A2A 身份、Webhook、凭据或出站工具权限。引用 A2ABreak **v1.0**：

- **A2AB-03《上下文归属与跨租户隔离》／工程解决方案**：只消费原任务已授权证据，原 owner 读取边界不变。
- **A2AB-05《产物分块校验与断流恢复》／工程解决方案**：按完整记录装配，保留字符位置及遗漏，截断继续进入既有暂停边界。
- **A2AB-08《结构化授权请求与权限不放大》／工程解决方案**：模板是数据，概要／附录共用可信组装器，不执行来源脚本或 Skill 代码。
- **A2AB-10《委派环路检测与全链预算》／工程解决方案1、3，验收办法T3预算分支**：只在既有根派生额度中选择上下文、调用和结算；新研究各有独立账本，失败历史不覆盖。

实际当前验证仅覆盖上述数据选择、组装与预算分支。其他 01/02/04/06/07/09/11 沿用原评估，未运行相关异常竞争或跨组织攻击；这些方案为待项目验证的工程建议，不是完整安全认证。方案索引在 Basic Memory `main/engineering/security/a2abreak/a2-abreak-多-agent-安全基线与-11-项方案索引`，本轮重读 A2AB-10 全文，复用其余有效的既有评估。
