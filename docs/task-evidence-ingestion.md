## 公开来源同步（2026-10-27，源码已接入）

资料库中的“同步来源”可登记本人选择的公开 HTTPS 链接、名称和目标分组，选择仅手动或开启 15 分钟至 30 天的周期。保存本身不读取网页；手动点击“立即同步”或等启用后的下个周期才执行。暂停只停止定时，已明确发起的手动同步继续；移除同步会取消尚未提交的运行，不删除已保存资料。周期调度依赖应用进程运行，停机错过的周期合并为一次，不补发无限批次。

每次最多四次网络请求、120 秒和 8 MiB（同时受现有上传上限约束），按连接、超时和限流等类别在该额度内有限重试。只允许登记来源同源的 HTTPS 跳转，逐跳检查公网 DNS 并固定连接；不带个人平台凭据。远端返回真实 ETag／Last-Modified 时用于条件请求，304 或正文未变保留当前版本。取得新内容时经现有解析和资料生命周期创建新版本，已存报告及原引用不改写；如果原版本完整而新解析截断或缺页，则保留原版本并显示原因。PDF／DOCX保存解析后的文字及结构记录，不声称保存远端原始文件；扫描 OCR、跨源跳转和带凭据 URL 不在此适配范围。

订阅、运行和网络回执按 owner 关联；运行租约、数据库版本和提交前复查拦截重复、撤权和迟到写入。请求已派发后停止或停机不能撤回已发送的流量；回执缺失标记读取次数未确认。账号停用、目标资料归档／权限变化、源被删除或当前版本变动时不会另建替代来源。源码接入不代表实际联网或多账号验收已完成。

### GitHub 事件通知（源码已接入）

登记 `github.com/组织/仓库/...` 或 `raw.githubusercontent.com/组织/仓库/...` 来源后，可在“事件通知”中启用 GitHub push 通知。页面生成密钥，仅本次显示；将回调地址、密钥和 JSON 格式填入该仓库 Webhooks 设置，并选择 push 事件。外部平台需要能访问部署的 HTTPS 地址；本机 `localhost` 不会自行接收 GitHub 推送。服务端加密保存密钥并允许撤销；不保存事件正文，也不从事件指定新 URL 或指令。

接收端按 [GitHub 的 SHA-256 签名规范](https://docs.github.com/en/webhooks/using-webhooks/validating-webhook-deliveries)核对原始正文，并绑定正文里的仓库名称。ping 只确认端点；push 进入同一来源的有界同步。投递 ID 与签名正文分别去重：读取期间有新通知时保留待处理记录，当前运行结束后合并一次后续读取。每条通知正文上限 256 KiB，每个来源每分钟最多 30 条有效新事件；重复不新建业务运行。仓库投递或服务不可用时，手动／定时同步仍可使用。

GitHub 的签名不包含投递时间和投递 ID，因此正文去重不能证明通知新鲜。每个密钥最多保留 5,000 条、每人最多保留 20,000 条通知记录；达到上限时拒绝新事件。用户可清理 90 天前且不在运行中的记录，清理后旧的相同正文可能再次触发一次受限读取。该适配仅覆盖 GitHub 格式；真实外部投递、多实例竞争与撤销尚未验收。

## 授权 PostgreSQL 变更接入（2026-10-27，源码已接入）

资料库“同步来源 → 数据库”列出管理员分配给当前账号的端点。用户输入该源库专用账号、密码、目标分组和同步频率；凭据由服务端加密，不放在连接地址、日志或命令参数中。初始默认不启用定时；可手动同步、开启／暂停、轮换凭据或移除连接。暂停、移除和凭据轮换取消尚未提交的运行；已经入库的资料及原引用保留。每批最多 20 条事件，每条正文不超过 256 KiB，并受文档解析上限、120 秒和租约约束；连接、忙碌与超时分类有限重试，权限、证书和配置错误不盲目重试。应用停止时不执行定时；满批时启用的连接在短间隔继续读取。

该 CDC 由源库执行 [postgresql-cdc-publisher.sql](../config/postgresql-cdc-publisher.sql)：管理员将允许公开给此连接的资料映射到 `adrs_cdc.source_documents`，行级触发器在插入／更新／删除所在的源事务里写入不可变事件，`TRUNCATE` 被拒绝。应用读取尚未确认的事件箱，逐条在本库原子保存事件、资料及版本后确认源库；不扫描普通业务表、不依靠修改时间、也不以序列号高水位假设提交顺序。本地提交成功而源确认未知时，下次对账与同一事件重放复用结果；较早实体版本只记录事件，不覆盖较新资料；删除只隐藏此连接对应的来源。失败事件不确认，可在界面重试或明确跳过；跳过不会写入此次资料变更。确认过的 90 天前事件记录可由本人清理；跳过记录与资料历史不清理。每连接最多保留 20,000 条本地事件，达到上限时停止新增并显示原因。

管理员明确需要初始数据时，在源端安装触发器之后调用 `SELECT adrs_cdc.capture_snapshot();`。该操作在同一事务和表锁下为当前导出表建立快照事件；界面只有在源方快照条数与仍保留的事件数一致且本连接已确认所有快照事件时显示完成。它表明导出表快照，不代表外部世界或源业务系统的完整全集；没有快照标记则保持未知。源方必须按所有消费者的确认情况自行管理事件保留，不得在仍需要交付前清理。

部署者通过 `ADRS_CDC_ENDPOINTS` 环境变量提供 JSON 列表；每条绑定一个真实账号 UUID，格式例如：

```json
[{"id":"research-feed","label":"研究资料数据库","owner_id":"00000000-0000-0000-0000-000000000001","host":"db.example.org","port":5432,"database":"research","schema":"adrs_cdc","ca_path":"/etc/deepintel/source-ca.pem","allowed_networks":["10.20.0.0/16"]}]
```

`owner_id`、证书路径与网段须替换为部署者实际授权值。端点从部署环境读取，不接受前端自填主机、SQL 或证书路径。连接时所有解析地址都须落在配置网段，再固定地址并以服务器主机名进行 TLS 验证；不继承进程用户的 `.pgpass` 或客户端证书。底层 libpq 缺少 `sslcertmode=disable` 等必要能力时停止，不降级。源数据库管理员应为该范围建立独立 schema／数据库和专用角色，只授予该 schema 的 `USAGE`、事件／快照／确认表的 `SELECT` 及确认表的 `INSERT`；不授予复制权限、业务表写入或表所有权。多个消费者共享同一源库时，还需由源库管理员按各连接 UUID 和角色在确认表启用行级策略，约束 `consumer_id` 的读取与插入，或使用独立 schema／数据库；本应用不替代源库侧的行级授权。端点网络、目标库或安全配置变化须重新登记连接，标签变化不影响既有绑定。

源码使用现有 `psycopg2` 与 PostgreSQL，没有引入 WAL 复制槽或 Kafka。此选型用源库事务捕获显式导出表的变更，代价是源侧需要维护触发器、授权与事件保留，不等同于对任意表的 WAL 全库捕获。源数据解析、并发写入、断线确认、两个账号隔离、暂停及撤销均须待全部实现后统一真实端到端验证，当前没有连接或修改外部数据库。

## 上传与文本接入 ACI

复用 `POST /api/v1/documents/upload` 和 `POST /api/v1/documents/sources`。公开研究仍默认联网，内部资料只有用户选择启用时才参加研究，上传资料不自动改变该偏好。

上传支持JSON／MD／DOCX／PDF／TXT，沿用已有文件类型、签名、解析限制和模型配置。文件读取上限为配置的 `upload_max_bytes+1`，超限413；空名称／分组、非法分块长度／重叠量422；类型和解析错误400。每个文件独立事务，不支持类型逐项显示且不发送。当前DOCX／PDF具体解析质量由OPT-02继续改造，不能用本项宣称所有解析路径已验证。

幂等键由服务端实际owner、目标分组、实际内容摘要及解析／分块／特征／索引用途配置组成，在同一数据库事务中锁定、查询有效且生效用途相符的来源、按选择生成嵌入和插入。相同有效输入返回 `deduplicated=true` 与原 `source_id`；不会再次为已提交同组内容生成嵌入。OPT-04新增接入默认仅词汇特征，稠密需要显式选择，见[编码契约](versioned-retrieval-features.md)；OPT-05的[直接定位选择](versioned-retrieval-indexes.md)不物化检索小块。目标分组或配置／生效用途变化建立独立来源表示，不能误报该目标已存在。文件内容摘要来自实际上传字节，手动文本来自实际保留文字，属于生产版本识别；没有运行摘要比对测试。

OPT-06进一步把[保留与复用策略](evidence-lifecycle.md)、实际当前版本及任务／有效期纳入同一接入判断。新资料默认任务范围，group／owner复用须明确选择；当前策略已变化的旧来源不能按初始metadata误报复用。旧任务账本原文不因来源修订或清理而覆盖；新综合另行复核当前使用条件。这些后续代码仍待全部实现后的统一端到端。

版本／归属元数据由服务端计算，普通metadata编辑不能伪造或删除 `content_hash`、`source_version`、`owner_scope`、`chunking_version`；试图改写返回422。分组／名称编辑在事务中同步片段标签。来源内容不被名称编辑覆盖。嵌入返回条数与片段数不一致时返回502且不提交不完整来源；同键事务可能等待嵌入，后续OPT-18处理模型预算与性能账本。

## 任务账本契约

`app/evidence_ingestion.py` 只执行普通数据对账，无网络／模型／索引写入。`RuntimePersistence` 在已有会话写入事务中，先读取数据库owner及execution、核对实际session，再合并之前已保存的账本。旧执行提交返回未持久化，不能覆盖新运行。账本不接受前端自报owner，owner不一致拒绝。

账本含 `sources`、`events`、`recovery_events`、`summary`、`conflicts`。每个来源保留多个内容版本，每个唯一版本保存一次文字及页码／段落等取得元数据，事件用证据ID引用版本和字符范围。重复事件不新建版本，重复正文／元数据可复用版本并保留新的取得事件。同一证据ID换了内容或来源会中止写入，保留已存原引用，不静默覆盖。

搜索结果的 `discovery_only` 与浏览后已读覆盖分开。内部检索保存 `chunk_id`、来源资料ID、源内容版本和片段序号，覆盖仅是取得片段；不是读取整份私人文档。来源修改时间／ETag不存在时保留null，不能由接入时间冒充源更新时间。

恢复记录复用原节点／tool call／审批ID、重试次数与错误分类。后续成功、原预算内有限重试、终止待人工处理、等待原审批、预算停止、已取消分别展示。这里不新建工作或重新授权；继续研究使用现有任务恢复／审批动作。

## 只读 API 与界面

`GET /api/v1/research/{session_id}/ingestion` 查询本人任务的账本元数据，运行中也可读取并手动刷新；`include_content=true` 下载包括保留文字和版本的JSON。读取及下载每次按DB owner检查；不可访问404，账本scope冲突409。原始文字默认不在元数据响应内。

新记录返回 `persisted=true`，旧研究通过实际保存快照生成的投影返回 `persisted=false`、`origin=explicit_legacy_snapshot_projection`。旧快照投影不新增采集，不回写原报告或追认当时不存在的时间／版本。返回的 `corpus`／`declared_scope` 是本会话原有声明／流转，缺少时仍为空。

工作台的“证据接入、版本与恢复”展示版本、覆盖、引用、错误和人工处理状态，提供显式原文JSON下载。没有自动轮询任务外来源或跨任务检索。
