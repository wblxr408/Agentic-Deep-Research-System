# 分阶段原文引用交接

## 真实问题与目标

2026-10-29的b4848e8e完整旅程已取得FastServe、LoongServe、Tetris、DeepServe的原PDF及研究者简历，但第一次分析完成后只有FastServe通过成果归属。LoongServe／Tetris的作者proof被模型写为`作者1...1Peking University`，DeepServe的题名和日期proof也未对应同一实际原句；技术卡的引用混入其他作品／简历或省略号，已有校验正确拒绝，最后所有技术字段仍为空。阶段结束不证明已经形成深入研究。原失败和成本继续保留，不能把省略号当作任意匹配或降低事实核对。

新交接以当前请求已经给出的原文片段为基础：模型选择片段编号，程序保留实际文字和位置。作者编号只在主作品开头明确对应时解析，简历中的发表列表继续作为发现线索。没有新增Agent、框架、独立检索轮或额度。

本模块源码已接入，尚未由完整业务证明效果。b4848e8e最终暂停于重规划后的技术深读，275,228 Token／41工具／0在途，原停止为insufficient_context_budget；当前仍保留旧冻结合同，不能部署后重算它的raw或补齐旧字段。

## 1. 请求内的原文片段编号

- 新根冻结字段策略v4与问题种子v9；旧策略保持旧解析。完成态旧v8只能按其原精确绑定继续报告，旧暂停不自动升级。
- 普通函数在原evidence_context选择完成后，为同一批已经提供的连续原文分配请求内编号。原文只传一份；不把同一文字另复制到一套上下文。保留evidence_id、citation_id、实际字符位置、页码、来源角色及选段范围。
- 每片≤560字符，最多128片；编号不是证据身份、权限或语义支持。明确显示属于哪一已保留作品，机构页／简历等辅助来源不冒充论文原文。
- 模型proof可写`{"passage_id":"p17"}`。一次proof只能选择当前请求的一片；已有proof数组支持多片。服务端在字段模型校验前，按本次实际manifest导出原evidence_id和逐字quote。未知、过期、跨请求、越界或冲突引用留为无效，不由模型补造位置。
- 原响应、编号表及转换事件保留在研究记录。所有原字段长度、数值、全文、来源角色、归属和最终逐项审核继续执行；引用编号本身不能证明摘要被原文支持。不能以此接受省略号拼接、跨来源合句或未选原文。

## 2. 主作品的题名、日期和作者编号

- 只在同一主作品开头寻找完整连续题名。排版空白造成模型题名与打印题名不同，可在全部非空白字符和顺序一致且候选唯一时，保留真实打印题名，并保存原模型值；不把通用proof匹配改成删空格或连接单词。
- arXiv当前PDF版本头可提供其明确版本日期；必须对应本次实际取得的标识／版本。将该日期保留为当前预印本版本依据，不当作首次发布、会议录用或当前机构任职。不能用另一版本日期给当前署名计年；实际范围继续由原date_membership裁决。
- 作者与机构只从当前主开头的明确数字标记建立对应。作者名必须唯一、编号必须位于作者项，机构编号须来自明确机构行。连续`23`仅在已有机构标签能唯一解析为2／3等组合时处理；有多种解析、冲突、非对应标记或未支持格式保持未知，不按邻近机构猜归属。
- 新proof保留作者到对应机构的实际连续字串及编号依据，受原1600字符上界约束。数字不对应时，即使作者和机构在同一大段共同出现，也不能据此归属。未编号的单机构作者块与明确封面作者对沿现有受限路径，不增加作者或跨页拼接。
- 简历／个人主页保留人员、公开联系与发现线索用途，不把其发表列表反复作为主论文抽取。可进一步读取的作品仍须原主来源、日期和署名。

## 3. 技术字段和重规划交接

- 技术问题只使用本批保留作品ID，明确主文献来源和辅助来源的角色，避免用另一篇作品或简历的摘要支撑本篇实验。方法、条件、基线和结果继续受全文及数值核对。
- 完整全文已取得但本次选中作品所有核心技术字段仍为空，不能把深读标成已完成。保留具体字段缺口并沿原有有界恢复／暂停路径；不新加无上限模型回路，也不要求所有学科都有相同实验项目。
- 复用既有有效材料路径时，保留实际正文、引用编号、范围、技能、当前权限与执行身份的原绑定。反思已指出事实或字段错误的分析不能因材料相同跳过修订；本轮不扩大缓存或跨根复用。只有确有未使用线索误使有效分析失效的证据时，才单独调整绑定。
- 核心判断同样选择当前实际选段编号；旧分析只是待检验材料。正常报告继续突出问题、观察、推导、意义与选择，全部主张仍须最终审核。

## 6. 已接入的控制点与ACI

`Analyst.build_messages`在既有选段完成后调用`phase_proofs.attach_passages`，将相同可见文字拆为连续片段；最终fit_messages装配的manifest才与对应响应配对。编号、来源角色、指定成果、字符／页位置保存，提示词不再重复同一份正文。编号表最多128项，超限尾段继续以逐字原文显示。`resolve_proofs`只处理organization_data和research_judgments，限定32层／4096节点／256转换事件；冲突／未知编号留为无效对象，由原字段校验拒绝。原完整响应与转换事件在extraction中保留，选段定位不证明语义成立。

`publication_opening`仅在同一主PDF开头处理≤4行的完整打印题名；全部非空白字符及顺序一致、候选唯一才保存真实题名。arXiv版本日期须当前公开arXiv地址与PDF明确标记一致，沿原日期区间／范围检查，保留模型原值与实际版本依据。数字作者标记仅在唯一机构编号分解和对应时产生≤1600字符连续proof，名字末尾明确标记归入proof并保留原字段；歧义／错号／不支持数字格式不靠共同出现通过。无编号的既有受限路径保持。没有补人物、翻译机构或跨源拼接。

`identity_batches`排除明确简历，抽取上下文限制为当前批次及首批官网身份入口；深读限制为本批已保留作品的来源ID，过滤排序对而不重编号引用。其他问题仍可读取简历／主页作团队及行动材料。深读响应后、写入completed前调用既有技术字段校验；指定作品缺少任何有效problem／method_overview／mechanism时保留字段拒因、原响应并进入原analysis_output_incomplete有界恢复。重试只增加这些字段的实际诊断，不清次数、扩预算或把诊断写成论文事实。针对条件补读不重复要求核心字段；实验项目继续按实际学科适用。

`save_question`持久化并合并收据后，在原鉴权SSE发送session／execution／checkpoint／plan_version及七个允许的根计数。GET结果增加已保存checkpoint_seq。前端仅接收相同任务执行、更高检查点及非递减消费；额度上限仍读服务端结果，计划改变触发一次现有结果读取。根累计工具调用单列，当前计划完成数沿原流程图。没有新计时器、轮询、服务或数据库表。
