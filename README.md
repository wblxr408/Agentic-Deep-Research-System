## 项目定位

ADRS 通过搜索、浏览、按需内部资料检索和证据分析完成研究任务，同时提供可展示、可维护的 Agent Engineering 实现。核心链路是：

`用户输入 -> Planner 生成 DAG -> 搜索/浏览取证（可补充内部资料检索）-> Analyst 综合 -> Reflection 校验 -> Report 生成及最终来源审计`

公开研究默认联网。内部资料检索由用户按需启用，与联网证据共同参与分析；资料命中不会关闭搜索和浏览，也不是它们的前置条件。

## 核心思想

1. **简洁性（Simplicity）**：用完成任务所需的最小结构，按职责和权限需要划分 Agent。
2. **透明度（Transparency）**：明确展示研究计划、步骤状态、计划调整和证据依据，让用户看懂研究过程。
3. **可靠的工具接口（ACI）**：通过清楚的工具文档、参数契约、错误反馈和当前变更的行为验证，提高交互可靠性。

框架用于加快起步；进入生产时，可以减少抽象层并使用基础组件。DAG、多 Agent 和 LangGraph 都服务于研究任务。完整准则见 [ADRS 核心思想](docs/DESIGN_PRINCIPLES.md)；测试仍遵守用户已明确的禁止回归测试约束。

设计采用**统一编排、按需取证、并行分析、独立终审**。下面是目标流程，包含待改造和待新增能力；当前主应用仍以通用研究和 Markdown 报告为主。逐阶段输入输出、三张流程图、代码依据和状态清单见 [完整调研流程设计](docs/RESEARCH_WORKFLOW_DESIGN.md)。

```mermaid

    P["Planner：计划与依赖"]
    D["统一调度<br/>权限·预算·取消·状态检查"]
    U --> C --> P --> D
```

四类逻辑 Agent 可复用同一模型服务，分别使用适合当前阶段的上下文；普通程序负责授权、状态、预算、统计和渲染。搜索、浏览、检索及绘图提供操作能力，Skill 提供方法和约束，实际调用仍通过获许可的工具接口。

| 角色或执行层 | 主要责任 | Skill／工具装配 |
| --- | --- | --- |
| Planner | 拆解问题、安排依赖、提出补证和停止方案 | 研究目的、来源与规划约束；程序检查计划 |
| 取证工具层 | 发现、读取与保存原文及位置 | 搜索／受控浏览／PDF／可选内部检索；学术 Skill 按来源和部署能力适配 |
| Analyst | 分类、关系、机制深读、趋势与行动依据 | 按学科加载方法；统计和权重交给确定性代码 |
| Report＋绘图执行 | 内容块、图注、图表及模板数据 | 预设／自定义模板；可选 `scientific-data-visualization`、`scipilot-figure-skill`、`networkx` 等待接入候选 |
| Reflection＋程序 | 请求覆盖、来源支持、统计及图文一致性，返回具体缺陷 | 复用引用审计，扩展装配后审核；缺陷按类型返回相应阶段 |
| 统一调度与存储 | 权限、预算、版本、取消、幂等、恢复和用户可见状态 | 复用治理、状态与事件组件；Skill 不授予额外权限 |

[研究目的与模块](docs/organization-analysis-modules.md)已接入布局与演进、合作资源发现、综合研究及自定义模块，高校、实验室、企业可单独或混合研究；[三目的端到端记录](docs/acceptance/organization-purpose-20261021.md)保留真实模块选择、权重独立、数据库与导出及正文待核状态。以下图像模板为目标：共同定义内容、页面、图文组件、主题、交互与证据绑定；绘图方案支持报告级默认和单图覆盖。任务证据先用 JSON／数据库保存与定位，向量 RAG 和图增强按实际缺口启用。

## 开发细节

### 研究流程

1. 用户在前端输入研究主题
2. `app/api/research.py` 创建 session
3. `app/graph/compiler.py` 编译 LangGraph
4. `app/agents/planner.py` 生成 DAG
5. `search / browser` 采集公开证据；用户启用内部资料后，`rag` 补充检索，按 DAG 依赖执行
6. `analyst.py` 生成分析结论
7. `reflection.py` 判断是否需要重规划
8. `report.py` 生成 Markdown 报告并推送 SSE

以上为当前主应用链路，最终 Markdown 在 `report.py` 内另有来源审计。目标中的图像驱动交互报告、绘图与装配后终审见 [完整流程设计](docs/RESEARCH_WORKFLOW_DESIGN.md)，不以目标图替代现状说明。

### 输出长度控制

- 前端支持 `short / medium / long` 三档输出长度。
- 后端按档位控制报告生成 token 预算、搜索次数和工具结果上限。
- 目标是避免报告被截断，同时让简单问题保持低成本。

### 知识库管理

- 前端提供知识库源的新增、编辑、删除和分组管理。
- 上传文件支持 `json`、`md`、`docx`、`pdf`、`txt`。
- 新接入代码按所选策略切分并保存词汇特征；仅显式启用稠密时生成embedding，默认不加载模型。此增量尚未运行，见[特征契约](docs/versioned-retrieval-features.md)。
- 选择“仅保存与直接定位引用”时不物化关键词检索小块；可在详情显式建立词汇索引。已启用来源可关闭或回滚代际，详见[索引契约](docs/versioned-retrieval-indexes.md)。
- 研究界面的“补充检索内部资料”默认关闭，开启后可指定分组；留空检索当前用户全部资料。资料命中、为空或不可用都不决定是否联网，工具许可与预算仍然生效。
- 内部资料来自手动录入或上传。历史研究报告和引用虽已保存，但需要手动入库才能参与内部检索。
- 稠密编码模型用于选择后的表示；检索稠密及重排由服务端分别显式启用。默认词汇查询不加载它们，公开研究默认不启用内部检索。

研究请求示例：

```json
{"query":"分析新能源汽车市场的最新变化","channels":["web"],"use_internal_docs":false}
```

需要结合内部资料时提交 `"use_internal_docs": true`，可同时提交 `"rag_group": "project_a"`。旧 `allow_web_after_rag_hit` 字段被忽略；分组不会隐式启用内部资料。

### 状态与持久化

- 研究状态定义在 `app/graph/state.py`
- 会话数据写入 PostgreSQL
- 检查点优先尝试 Redis，失败后回退到内存
- `research_sessions` 保存任务主记录
- `citations` 保存引用明细
- 审批暂停状态为 `paused`；完整恢复状态写入 `session_runtime_state.state_snapshot_json`，恢复保留原查询、权限与已使用预算。
- `session_id` 只能创建新会话或确认相同的待确认请求；重复执行返回 409，其他用户的会话返回 404。
- 六项执行边界修复及验证范围见 [研究执行边界说明](docs/research-runtime-boundaries.md)。

### SSE 与前端联动

- 后端通过 `app/observability/sse_manager.py` 维护每个 session 的事件队列
- 前端通过 `frontend/src/hooks/useSSE.ts` 订阅 `/api/v1/research/stream/{session_id}`
- `ResearchDashboard` 组合展示 Agent Trace、Tool Trace 和报告内容
- 每个历史/新事件输出前以及空闲等待中重新验证原凭据和会话归属；退出、改密码、撤销令牌后关闭失效连接。

### 配置优先级

运行时配置优先级为：

`前端运行时配置 > 数据库 system_config > 环境变量`

这意味着可以在不改代码的情况下切换 LLM provider 和模型。
