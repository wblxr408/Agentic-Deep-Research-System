# Design

2026-10-24增量：四次真实长调研在原900秒或上下文准入处暂停，尚未交付完整报告。仅新建长任务使用预算策略2：240000 Token／2700秒，报告预留24000、审核预留60000及480秒，仍包含在单一根内。版本／预留写入原预算JSON，已有短／中限额不变；历史无版本根采用原根限额及原12000上限／20%公式，恢复不继承新配置。取证次数与已知费用配置上限不扩大，未知费用仍独立标识。修改配置不等于验收通过，实际记录见docs/acceptance/unified-research-20261023.md。

## Context

根图只在工具调度处检查总量，分析/反思/报告直接外发。Report在写完后才从余量扣审核预算，且流式usage被忽略；审核的跨语言查询先扣最大额度且没有真实结算。最终用量合并后未重算停止状态。现有Python/React与JSONB继续使用。

## Goals / Non-Goals

修复当前主流程模型请求的准入、预留、结算与结束状态；保留报告正文和研究记录分离。此轮不实现分布式任务队列、外部Agent内部账单观测或新增Tokenizer/数据库，不自动重新运行完整调研。

## Decisions

1. 用普通任务内TokenBudget对象包围实际chat请求；根图给各阶段派生剩余额度，不在模型提示词中执行预算。请求前按文本UTF-8字节及封装余量保守预占输入、按供应商max_tokens限制输出。该数值是保守准入值，不宣称未知供应商精确分词；实际usage优先结算，缺失/失败/断流保留预占并停止不明余额的重复消耗。
2. 初始总量预留20%给最终语义审核、20%给报告（各有上限）。前序阶段及重规划只能消费其余部分；报告不能动用审核份额。报告/前序请求超时早于最终审核截止时间，保证审核时间份额。额度不足暂停或跳过可选反思进入最后交付；不通过重新规划重置总量。
3. 主/备每个实际尝试单独准入；受控请求禁用SDK内部自动重试。流式尾部usage进入账本；结束/异常均关闭流。usage超出预占如实记录并阻止后续，不裁剪真实用量伪造守约。
4. 最终审核优先直接在已保留的原文片段做语义判断，跨语言检索作为有限补充；按可用额度缩小审核批次，不因五条批次装不下就全部跳过。预算/时间不足的未核项保持not_checked，任务转为需要处理的预算暂停，原文仍保留。
5. 根预算汇总模型各阶段账本及工具Token，避免max(model,tool)漏计；用量更新后重新计算停止原因。未知价格独立标识，不将0当作已知免费。历史84,190/60,000记录不修改。
6. 报告质量另以“判断问题→所需证据→比较维度→结论与行动”组织。样例两篇摘要不足以交付高校研究布局、年度演进或合作建议全集；后续采用明确焦点、全文与相关工作、作者/团队来源及条件比较。没有新增材料时不重复包装六页，更不添加数量图凑信息密度。

## Security applicability

采用[A2AB-10《委派环路检测与全链预算》](memory://main/engineering/security/a2abreak/solutions/a2-ab-10-委派环路检测与全链预算)/基线v1.0/“工程解决方案”1、3项及“验收办法”T3的当前预算分支。执行点为根预算派生及实际LLM请求外发。既有11项评估沿用：无新A2A主体、凭据、Webhook或跨租户存储，本次不新增其他信任边界。仅执行本次预算消费者行为，不运行其他安全/能力回归；方案是待项目验证的工程建议，不能声称全部安全验收。

## Risks / Trade-offs

- 保守预占会比真实分词更早停止 → 展示预占与真实usage差别，精确Tokenizer作为将来可选适配；保留证据并明确暂停原因。
- 不明失败可能实际未收费 → 保留预占保证后续有限消费，不将未知记0。
- 单机阶段账本不提供跨进程exactly-once → 沿用原执行身份及持久化恢复，未实施分布式计费保证。
- 正文预算更少 → 聚焦问题和精简输入，不能以少核事实或虚构报告弥补。

## Migration Plan

新增账本字段进入现有budget_state和review_status；旧计数作为下界保留。无数据库迁移。回退时保留原始研究及账本，停止状态不能被自动恢复为完成。
