# Design

## Context

当前为 React 18 + Tailwind + React Query。App 管理视图与认证；ResearchDashboard 管理预览、提交、SSE、持久任务、恢复及配置。原界面约 50 个领域组件包含实际业务功能，本次保留这些接口。四张生成背景已由用户确认，位于 outputs/frontend-design-20261025。

## Goals / Non-Goals

**Goals:** 实现完整前端视觉与操作改造，保留配置能力和真实状态，公开技术说明与实际运行分开。所有简短状态在研究工作区展示，报告正文聚焦发现与依据。

**Non-Goals:** 不扩大研究目标、资料权限、总额度和模型端点范围，不自动接管已有暂停研究或新增付费根任务。后续用户追加的分类恢复和报告修订按下方恢复设计执行；手动暂停仍使用独立原因与图检查点继续。本次改造不等同于原 ORG/FLOW 全业务验收完成。

## Decisions

1. 用 CSS 变量承载四套配色，Tailwind 原 xm/primary/xmgray 映射到变量，已有领域控件也随主题变化；使用本地字体栈中的中英文衬线展示标题和清晰正文。主题与标题语言保存在 localStorage，捕获不可写存储；跨窗口 storage 事件同步。静态首页与技术文档直接呈现，任务、资料、Skill 和设置保持原认证与 API 授权。
2. 首页全宽背景与黑色渐变蒙版独立，桌面主标题最大 144px；工作区标题最大 96px。中文按语义分行，副标题使用独立小字号；英文同样区分层级。复用本地生成图，无外部字体或图片请求。
3. 自行实现经用户选定的组件交互：Task Rows、Tool Chips、Context Cards、Action node、Trace loader、Hub diagram、Tab bar、Palette、Canvas toolbar。参考出处为 https://www.beautifului.dev/ 与 https://bencho.dev/blocks/ 对应页面。适配交互和样式，不声称复制网站源码或完整工作流引擎；不使用其侧边栏实现。
4. 不新增图框架。React 节点卡片与 SVG 连线承载真实 DAG；按 depends_on 分层，有界处理无法分层的边。原计划中的独立问题才并行。当前快照是状态权威，历史与 live 事件按身份合并，终态阻止旧 running 动画。工具节点保留原用途，界面不将每个工具升级为自治 Agent。
5. 通用原生 dialog 封装负责焦点、Escape 与返回触发元素；高级配置使用分组折叠和标签；技术原理通过 ?view=technology 在独立窗口打开。技术图为明确的原理演示，提供播放、暂停、单步与节点解释，不伪造实际调用记录。
6. 报告增加目录与引用卡片；现有审核/预算/原文等记录默认折叠，不删除证据或改变导出权限。绘图结果和来源继续使用既有 API，图表增加单独放大及 CSV 数据下载。敏感内部字段不进入默认节点摘要。
7. 本次只改变既有架构的前端投影，不新增 Agent/A2A 协议、委派或策略服务，复用既有安全基线适用评估；来源读取仍走原任务 API，节点展示只选择公开字段。技术文档明确正文数据、工具与策略职责，不放宽原边界。

8. 反馈融入角色工作区：上层自绘机器人和阶段主线，下层有边界的从属动作容器，突出一项当前动作／最近结果，历史折叠。取证工具单列工具区。按 call_id、node_id 和 phase 关联原 SSE、工具和阶段摘要；身份稳定、终态和未知状态保持。桌面保留可容纳的整体视野，手机定位角色，拖动停止跟随；原 DAG 前置依赖在详情中查看。React／SVG 沿用原栈。

## Risks / Trade-offs

用户对第10组的实际反馈：只把胶囊和方卡上下摆放仍不足以表达层级，缺少有状态的角色。第11组取代其布局细节：主连线只连接上层执行角色／阶段，下方使用有边界的工作区容纳所属动作。角色为自绘简洁机器人（用户确认采用参考风格的可变表情版本），执行／等待／恢复／暂停／失败／完成对应不同眼形、视线与有限动效；所有状态来自现有任务和SSE，不以定时器伪造执行。当前动作作为主卡片，其他真实动作收拢为历史；取证步骤单列工具区，不为了头像新增Agent。DAG前置依赖在动作详情中保留。SVG／CSS复用现有技术，图标不是官方Grok资产；减少动效时保留表情和文字并停用循环动画。

- 原计划与 SSE 版本差异：优先持久快照、保留原始记录，不以连接在线推定研究成功。
- 大图与动效：使用原生 CSS/SVG、局部缩放和 reduced-motion；不添加视频后端。
- 改造跨多个旧组件：保留业务请求及数据结构，样式变量统一；原未通过的研究案例继续保留其状态。
- 原完整 E2E 受限且用户禁止所有非 E2E 检查：不运行构建、类型、lint、导入、浅层或回归检查。真实界面操作和源码审阅分别记录；未取得的新付费端到端交付保持待完成。

## Migration Plan

### 用户追加：任务控制与实时反馈

系统停止后由确定性诊断读取已有核对问题、阶段错误、模型用量与期限，输出可读结论及处理动作，不另起诊断 Agent。用户追加的分类恢复取代最初统一一次策略：连接3次、超时2次、服务端2次、明确限流4次（均为初始请求以外的次数），结构／长度／可压缩上下文各最多2次。传输退避、原份额准入、每阶段分类计数与根恢复总上限8次共同约束；阶段总尝试最多10次，已有两次能力升级尝试计入其中。没有原文不制造证据，不擅改研究对象／权限／额度。结构错误添加纠正说明，长度与上下文错误缩减可选片段并调整输出；相同错误响应在修改后重复则停止。报告按原主张和来源分轮修订：一般问题最多2轮、有矛盾主张最多3轮，轮间未解决项不下降即停止。每轮继续重新核对 owner、execution、用户暂停、资料和实际余额；需要凭证／授权／额外额度时给出明确选择。沿用 A2AB-03／04／06／10／11 v1.0 的已有适用评估和服务端执行点。自动修改指本任务的输入、模型输出结构与报告段落，不修改部署代码、密钥或权限。

- 顶部提供运行任务“暂停”、手动暂停任务“继续研究”和可操作任务“终止”；系统停止展示具体原因。可恢复分析／报告保留原接口；不适用时提供“调整后重新开始”并打开原配置。
- 手动暂停为协作式：请求绑定 owner、session、execution；当前图步骤结束、状态保存后暂停，界面显示“暂停中”。保存下一图节点用于继续。终态自然完成与暂停竞争时不重写已完成结果，切换执行版本拒绝旧请求。
- 继续只使用保存的有效图游标；锁定检查点与执行版本，生成新 execution 并重新订阅 SSE。资料访问重新核验，已用量、模型收据和原起始期限不重置；取消与权限撤销优先。
- SSE 反馈随角色工作区的当前动作、结果和历史显示，详情保留时间、输入及相关调用；完整事件列表进入研究记录。停止画布跟随不暂停研究。此条替代早期画布下方独立面板的布局。
- 搜索节点使用具体 query/purpose；不将不同任务统一写成“发现可核查线索”。历史与 live 事件按任务及执行版本合并，暂停与失败不显示成完成。不新增自治 Agent 或 A2A 通信。
- 实际发现当前压缩中间件缓冲 SSE，流路径绕过 GZip；工作线程的图事件通过所属执行循环立即发送，仍走原授权出口。依据 A2ABreak v1.0 的 A2AB-03／04／06／10／11“工程解决方案／验收办法”，执行点、知识库引用及实际覆盖见 `docs/RESEARCH_EXECUTION_CONTROLS.md`；其余沿用原 11 项评估，没有新增 Agent 信任边界。

沿当前任务分支分模块提交推送，复制确认素材到 frontend/public/backgrounds。开发服务通过现有 Vite HMR 呈现；不部署公共站点、不运行新研究。后端源和运行修订保持既有记录。需要回退时针对本次模块提交进行正常 revert，不重置用户工作区。

### 用户追加：技术架构的拆解深度

技术文档由统一六卡片示意改为按主题定义的实际架构拓扑。默认全景解释配置与输入、Host 执行边界、Runtime 编排、工具和交付；单个 Agent 图展示上下文装配、模型决策、受校验工具请求、结果规范化、续轮／结束、检查点与事件输出。证据、RAG、Skill、路由、匹配、ACI、控制和交付各自使用明确的节点与返回分支。区域层级表达归属，连线区分数据与控制，节点详情提供具体输入、输出和本仓库实现位置。动画明确标为原理演示，支持暂停、单步及减少动效；不会作为实际任务日志或推理内容。技术图与运行图共用真实职责口径，运行图只展开已有事件、阶段和工具记录。沿用 React／SVG／CSS，不新增图形或 Agent 框架。

### 用户修正：正交路由

所有技术专题连线采用水平／垂直折线，端口垂直进入节点边缘。按节点和可见分区标题建立避让网格，使用有转弯、重叠及交叉代价的最短路；返回路径配置外侧通道。路线按专题缓存，演示沿同一路径移动；标签优先放在空闲线段，完整交接保留在节点详情。沿用SVG与本地路由函数，无新增依赖。

### 用户追加：研究配置以任务选择为入口

创建与重新研究共享一套类型化选择状态。主界面保留问题输入及少量摘要入口，编辑窗口按研究重点、范围、资料、报告及更多选择逐项展开；只在应用后提交选择，取消完整丢弃临时编辑。中文标签和预设替代逗号编码、内部ID和请求JSON；精细设置通过结构化表单表达。深度选择同步原篇幅参数，日期和学科在当前对象模式内使用唯一来源，默认权重由原服务端契约提供。选择对象类型不删除暂存的具体对象；不匹配的显式对象在应用时给出定位错误。已保存请求的未知扩展及本人参考保留，旧预览身份在新任务中移除。预算、资料权限、模型授权和实际预览契约继续由原服务端校验。视觉沿用已确认四色、字体和控件，以简洁的选择行与少量图示表达用途，不采用中国厂商的界面参考。技术图与报告优化不在本组范围。
