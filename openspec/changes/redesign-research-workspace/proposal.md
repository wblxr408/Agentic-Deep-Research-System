# Proposal

## Why

现有前端以配置表单和运行日志为中心，研究过程难以阅读，报告与运行信息混杂。用户已确定四套背景、黑色蒙版、中英文主副标题及组件参考，现要求完整实现统一的研究工作区。

## What Changes

- 四套全站配色、对应生成背景与独立黑色蒙版，保存主题选择；中英文首页标题切换。
- 多行研究输入、分组配置、明确的研究计划与历史入口，保留已有参数能力。
- 实际 DAG 流程画布融入 SSE 实时反馈；角色胶囊与动作方卡呈现具体问题、调用、返回和修订，支持缩放、平移、定位、跟随及动作详情；完整列表进入研究记录。
- 独立技术文档窗口，以可播放的分层关系图解释研究、取证、RAG、Skill、路由、执行边界及报告流程。
- 阅读区采用简洁正文、章节导航、证据卡片和图表操作；运行信息进入独立记录。
- 根据 Beautiful UI 与 Bencho 的已选非侧边栏组件自行适配交互，统一文字、焦点、状态、移动端和减少动效。

## Capabilities

### New Capabilities

- `research-workspace-presentation`：主题、标题、配置、运行图、技术文档及证据阅读的前端呈现契约。

### Modified Capabilities

用户追加任务暂停／继续入口：沿用权限及原预算，增加在图步骤检查点协作暂停和继续的契约，不修改 Agent 分工。

用户后续追加系统主动诊断与分类修复：沿用原根、原期限及资料权限，分析按实际故障类型分配不同恢复次数，先修正请求结构／上下文再请求；报告按具体主张多轮修改及重新核对，以进展和额度共同限制。动作保留在工作区与研究记录，未增加自治Agent或代码自修改权限。

## Impact

范围为 React 前端、静态素材、任务暂停／继续 API、既有图检查点、分类恢复／报告修订、SSE 投递及 README/TODO。沿用 React、Tailwind 和现有运行栈，无新增关键依赖。沿用本地单写者和当前任务分支；后台全量调研目标仍暂停。不启动新的付费调研，不新增或运行回归、构建、类型、lint、导入或浅层探针检查；记录真实界面操作和源码审阅，缺少的完整业务证据保持待完成。
