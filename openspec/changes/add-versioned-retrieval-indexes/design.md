# Design

## 2026-10-27：新增真实表示的索引交接

已有05只发布词面倒排，04现可显式产生本地SPLADE、英文词形、token／整体向量和实际图文特征，须补齐实际索引与当前head的关联。稀疏权重以token ID、真实词表／模型profile和非负权重建立有界倒排；词形单独按数据库配置身份建倒排，不能与原词面混为一谈。多向量按owner／来源／文档和配对身份保存，来源首次发布前同事务写入，后续查询先限定有效owner／head／版本，再按真实配对和维度选择候选。图文特征在本人选择原件后异步生成，后续只在当前授权来源和兼容空间内使用；编码不自动扩大资料范围。HNSW、IVF、量化和磁盘图继续按实际数据规模及最终端到端收益评估，具体候选不等同强制全部采用。

## Context

见[proposal](proposal.md)。04已有每块词项／长度和表示身份。当前启动与迁移无条件创建IVFFlat；FTS ts_rank和JSONB词项OR没有真实BM25统计。现有JSONB任务证据独立保留旧引用，适合让索引代际只影响未来查询。

## Goals / Non-Goals

**Goals:** 在现有PostgreSQL实现版本化倒排和查询范围统计、原子发布／幂等生命周期、直接定位选择及可见性，明确其余候选取舍。

**Non-Goals:** 不引入另一索引服务，不预先实施全部ANN／量化／学习稀疏／图数据库，不自动重建历史资料或删除旧物理索引，不重新运行研究或模型。

## Decisions

2026-10-23 OPT-11延续：明确chunk/source UUID、短语及词面entity选择器；新增仅元数据模式、同源当前父级兄弟块辅助候选，各路保留原始排名／分数／范围。SQL通道独立记录失败与空结果，全失败不当成功；结构扩展最多5种子一次，既有父级上下文保留matched定位。学习稀疏、token多向量、行为、多模态与社区摘要无对应模型／数据／索引时显式跳过。普通函数复用原RAG、数据库和根期限，不增加思考Agent或图服务；源码及未运行边界见docs/retrieval-candidates.md。

2026-10-23 OPT-10延续：`query_options.internal_filter`通过固定字段、类型及有界AND／OR编译成参数化SQL，与可信范围独立AND。FTS、BM25 N／DF／候选和精确向量共用条件；auto目前选择pre-filter，未部署的post／in-search及位图方法不作为可用路径。新根冻结filter_id及策略，恢复入口核对版本；最多观察10001个当前合法块并明确观察缺口，不用该上限裁剪正式候选。重排前及整批返回前复查业务条件、当前发布代际、来源权限及revision。原根剩余时间约束异步检索，同步包装结束关闭自有池且不因RuntimeError重跑。ACI及安全方案执行点见docs/metadata-filtering.md，均为源码完成、待全部实现后统一端到端。

### 1. 最小存储结构与原子发布

现有PostgreSQL新增代际、每代文档长度、词频倒排、每来源head及幂等操作五张小表。它们分别承担版本、零词项文档统计、按词查找、当前生效选择和重放绑定，不增加Agent／服务。新来源的词汇索引与正文／小块同事务提交；direct仅建直接定位head。重建在来源行锁及原parse／feature／head绑定下生成新代际，全部准备后原子换head，失败回滚仍用旧代际。结构／特征不可用不伪造，记录partial／unavailable覆盖。

### 2. 精确／词项／加权／属性／时间索引

复用UUID主键、owner／来源／group／status／时间B-Tree、FTS／JSONB GIN；倒排用owner＋term＋generation和文档长度统计。BM25在同一SQL快照的当前owner、当前组、active且lexical的head内计算N／平均长度／DF，采用固定k1=1.2、b=0.75并记录版本。只对保留词项计数，截断和无特征旧资料显式显示；FTS回退是独立词汇通道，用RRF融合，不混用不可比分数。LSR未选，当前权重来源是可解释词频／IDF，不冒称学习稀疏。

### 3. 向量选型与原过滤范围

新建默认采用精确距离，不自动建IVF；RAG将实际owner／组／active／head模式／编码profile符合的向量范围放入MATERIALIZED CTE后计算距离，避免旧全局ANN的后过滤影响召回。HNSW／Vamana、IVF、PQ／OPQ／SQ、DiskANN、token多向量暂不采用：当前缺少适当规模、可比召回和延迟／费用证据，复杂度和内存／磁盘成本不值得默认引入。已有索引不删除。规模／延迟目标真实超限、有模型／数据与可验证收益后重选，不能按名称声称已支持。

### 4. 关系及多粒度

沿03父子计划建立只读有界邻接视图，连接父块／小块及未确认实体提及；词项倒排为细粒度字面候选。无已核实体图查询需求时不引入图服务；不把字面引用、实体共现或章节父子当合作事实。时间B-Tree使用创建／版本时间，不把正文ISO日期写成发表时间索引。

### 5. 选择、生命周期与交互

IndexPolicy可选direct／lexical，默认lexical用于用户主动内部资料接入；网上任务证据继续默认直接保存不建索引。direct拒绝同时请求dense，以免无检索收益却编码；后续本人可显式建立词汇代际。GET本人index状态含生效head、代际及候选；POST生命周期包括rebuild／disable／activate，绑定request_id、预期parse／feature／head，重复payload原样重放，改变参数409。回滚只允许同源同版本保留代际。没有后台任务／自动清理；loading、错误及结果由详情组件呈现。

### 6. 限制与安全

最多4000小块／20万倒排词项，按完整小块限额标明未索引部分；SQL构建操作有语句期限，失败不发布。引用A2ABreak v1.0既有全11评估的03／06／08／10“工程解决方案／验收办法”：认证owner先于来源读取，行锁／预期版本／幂等防迟到覆盖，索引不放大资料范围，构建有界且不新增模型调用。其他项沿用无新委派／回调／流／凭据的具体评估，来源链接见[TODO](../../../docs/OPTIMIZATION_TODO.md#安全方案引用与规划状态)。全部控制待最终统一端到端，未做性能或安全通过宣称。

沿用A2AB-11的有界动作部分：同步操作总限45秒、锁等待3秒、单条SQL30秒；没有后台worker租约。网络／503结果不确定时客户端保留同一请求及预期版本重试，从已提交幂等记录确认一次业务效果，不能由单次失败推断并发原请求从未提交。具体标题、基线版本和适用章节见[安全说明](../../../docs/versioned-retrieval-indexes.md)。

## Risks / Trade-offs

OPT-13增量采用普通函数`app/candidate_fusion.py`，复用当前工具与查询解释／handoff身份，不新增检索模型或Agent。内部以chunk UUID、联网以保留版本／query的URL合并路径成员；原始排名、分数含义、方向、权重和观察独立保留。并／交集、RRF／Borda／逐路分数归一化及词面MMR受32路×100及全局100限制。限定来源先过滤再融合；当前授权复核仍在原精排和结果边界。近重复只分组，不删除引用或宣称独立支持。缺分路显式退到排名；学习式融合因没有获准标注／模型不启用。各配置、可见轨迹、安全方案章节与最终场景见[候选融合ACI](../../../docs/candidate-fusion.md)。源码完成，未运行；精排后最终来源覆盖须以实际结果为准。

- [倒排占用额外空间] → 词频不重复存正文／完整元数据，限制总词项并显示partial；性能到真实场景再测。
- [旧资料无generation] → FTS回退且明确未知，不在启动时后台重建。
- [全局ANN影响过滤召回] → 精确范围CTE，保留旧索引但默认不依赖它；未来ANN需单独租户／分区与召回评估。
- [保留代际增长] → 只在显式操作时增加，后续06生命周期设计清理；当前不自动删除可回滚依据。

## Migration Plan

新表／B-Tree／GIN加入已有初始化与迁移的可重复DDL；不删除旧表／向量／索引，不自动回填旧来源。新上传写同事务，新只读状态对旧源明确无代际；部署加载与实际迁移等全部TODO实施后统一端到端，再通过旧数据回访／新查询和生命周期实际效果确认。模型／向量维度配置不隐式改已有列。
