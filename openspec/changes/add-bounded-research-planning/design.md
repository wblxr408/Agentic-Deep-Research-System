# Design

2026-10-24 OPT-16.12a源码缺口：现有`urlsplit`查询检查未覆盖OAuth fragment与SPA hash路由中的访问参数，因而可能将这种URL当作公开搜索文本、模型上下文或可点击引用。沿现有敏感参数规则同时检查完整fragment及其`?`后的参数；正常论文页码／章节锚点保持普通语义。`id_token`和`session_token`纳入URL及统一披露；敏感片段在投影URL中移除，不改变本人原始输入、证据位置、冻结策略身份或实际准入／预算。复用已有分级与展示函数，不增加认证渠道或抽象层。源码审阅不证明已完成16.12a／U4，最后完整混合资料旅程继续待执行。

## Decisions

2026-10-24 U2实际循环修复：组织视图固定的“仅为样本／非现实全集”定位说明改作为`coverage_notes`保留，不能单独触发再次取证与整轮分析。具体未支持／冲突主张、明确未完成主张及修订焦点仍可触发有界重规划，原轮次／无增益／根额度和截止时间不变。沿用A2AB-10／《委派环路检测与全链预算》／v1.0／“工程解决方案”1、3；执行点为既有iteration_decision，不新增Agent或付费权限。U2原失败保留，新行为须完整新旅程取证，不宣称安全／能力回归通过。

1. 固定工作流可用于直接事实和明确种子；复杂问题复用Planner一次有界模型计划，结构和权限均由代码校验。依赖以depends_on与可解释条件构建，规范化边表示；循环、未知依赖、重复ID、阶段反向依赖直接拒绝。模型不能决定自己的执行权限/预算或跳过根综合审核。
2. 执行计划冻结版本和节点操作身份，工具请求/检索通道/独立子问题分别标注并行理由；并发有上限，原预算份额不复制。工具节点只传所需阶段上下文及证据引用。根聚合检查执行/计划/请求绑定、重复和过期，再接纳结果；外部不可幂等调用的未知结果须保留，不能承诺不重复计费。
3. 有状态自主循环仍由根规划/反思驱动；不把搜索/浏览/RAG都改成一轮完整思考。重规划需具体缺口/冲突、仍可执行的新行动、轮次与剩余预算；保存证据版本/方向变化及无增益轮次，不仅依据overall_confidence。既有失败回退不冒充能力升级，新的工具/模型路由细化由OPT-09接续。
4. 复用注册表固定Skill内容版本，按阶段/领域/模板生成元信息→必要指令→明确内联参考的有界上下文。能力需求不授权；多Skill的限制取交集，明确空集合不得fallback成全许可。必要约束冲突或超预算则显示可修正阻塞，不默默截断。
5. Planner、取证、综合、审核、渲染仍映射现有组件；API/graph同一根状态负责预算和提交，文件Harness不作第二调度权威。SDK本机CLI不等于共享多租户worker，若作为工具只接收有界输入/输出与根预算，不嵌套全研究循环。
6. 模型路由使用原配置服务与普通函数，不新建Agent／服务目录。显式候选先按阶段、所需格式能力、配置质量档位、资料许可和容量筛选，再比较有来源的配置报价；未知费用不能当零成本。新根冻结非秘密配置身份，每次请求前检查变化。主备客户端携带不同的路由身份并共用原计量器；备用不借主密钥，私有备用默认禁止。实际上下文在原根额度和候选容量中装配，拒绝前不伪记已派发。配置能力不等于实测质量，报价不等于账单。服务故障fallback与实际失败驱动的能力升级分别接入，详见下文及09.11b。具体字段、错误、legacy边界与最后统一场景见docs/model-routing.md。

## Risks / Trade-offs

OPT-12继续使用原pinned HTTP／解析器及浏览网关，重定向与页面资源共享原份额，读取模式和抓取年龄冻结到阶段投影。普通资料源优先原文，必要时一次有界DOM；限定来源不因渲染扩大范围。HTTP声明及本地获取时间不代替发表／事件事实。缓存只同任务且当前准入，不改旧证据。明确归档复用原source写入与生命周期owner/request_id事务，direct／dense=false，原文与来源关联保存。旧归并后的论文URL不替代请求版本身份。具体错误、控制点、未运行状态及最后统一场景见docs/external-evidence.md；认证平台／凭据URL内容分级仍待OPT-16，不宣称公网传输已证明内容公开。
能力升级采用原根累计0—2次限额（默认1），仅在实际格式／截断／上下文缺口或已审核的有据冲突时选择满足原许可的不同型号候选。分析仍最多两次阶段尝试，报告仍最多一次结构和一次语义修订；证据缺失／实体歧义分别进入补证／澄清。升级决定、已付款用量、失败输出或修订前稿先保存到owner/execution/plan绑定的原检查点，失败就暂停；已准备决定保守占名额。分析恢复固定候选，旧根快照保留更新用量及升级前稿。容量升级必须同时有更大候选与原根额度空间；关闭升级客户端的服务故障fallback，避免静默降级。具体字段和待统一E2E见docs/model-routing.md；当前只接源码。

遗留模型计划可能含文字browser/缺边→保留可见规范化/拒绝及修正原因，不静默覆盖用户来源范围。旧运行无新版本信息→明确legacy兼容，不把新校验结论追认为旧运行已通过。冻结上下文增加状态体积→原文和大目录按版本引用，传送最小阶段视图，完整主体仍在原owner账本。
