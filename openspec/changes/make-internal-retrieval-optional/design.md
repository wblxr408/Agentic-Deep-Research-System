# Design

## Context

见 proposal.md。研究 API、Send 子任务和恢复路径传递旧开关；Planner 的提示词、事实查询与回退计划也假设存在知识库。现有代码已有技能许可、owner 过滤及全链调用预算，必须继续生效。仓库存在渠道功能的未提交变更，本次在当前工作区做有界修改。

## Goals / Non-Goals

**Goals:** 请求和任务状态只用明确的内部资料选项，服务端在规划和执行边界约束它；研究证据继续交给既有分析/反思/报告链路。

**Non-Goals:** 本次不增加仅内部资料研究模式、不自动将报告入库、不更换检索算法和模型。

## Decisions

- 请求新增 `use_internal_docs=false`，保留 `rag_group`；删除旧公开 API/状态字段，Pydantic 对旧请求的额外字段采用现有忽略行为。旧字段不映射为内部资料授权，分组也不能隐式启用。前端关闭开关时提交 null 分组。
- 共享确定性来源策略用于 Planner、图初次规划和重规划。默认剔除 RAG 节点并清理关联依赖；启用时若计划缺少内部检索则增加独立的检索步骤。计划缺少搜索/浏览时补充公开搜索，然后与现有工具许可取交集。取消 RAG 到联网的默认阻塞依赖。
- 执行器清理旧计划中的未启用 RAG，工具许可与检索执行入口再检查选项；Send 显式传递 opt-in 和 owner，不能仅靠提示词控制。
- 聚合器只统计内部检索结果，不按命中修改联网节点状态。取消 `internal_first` 和 `web_search_required` 等控制语义。
- 并行预算分配中，联网等主取证工具先分配余数，内部检索作为补充最后分配；只剩一次调用时执行联网，不能让可选内部检索抢占全部预算。
- Planner 提示词描述内部资料为条件能力；事实查询和失败回退默认采用联网。使用确定性规划、调度、工具结果和前端请求行为测试作为评估契约，不用提示词字符串断言冒充模型评估。

## Risks / Trade-offs

- 联网会比旧知识库问答路径增加调用 → 沿用既有预算与用户所选渠道，不因内部命中绕过预算。
- 旧待执行状态可能带 RAG 和旧策略 → 以缺省关闭的新选项过滤未授权节点；已完成历史研究不重写或重新执行。
- 模型仍可能输出未选择的节点 → 确定性策略和执行边界拦截；测试覆盖模型偏离及合法启用。

## Migration Plan

前后端共同部署，无数据库迁移；旧联网字段被忽略。新的内部资料开关需显式开启；历史待执行计划不得靠旧策略授权读取。回退应用代码和界面即可恢复旧产品行为，保留原数据库资料与研究结果。
