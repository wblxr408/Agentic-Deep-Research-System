# Design

## Context

动机见[proposal](proposal.md)。01任务证据在session_runtime_state保存不可变文本，03–05内部来源已有解析／分块／表示及原子词项代际；当前PUT只改标签，DELETE立即物理删。06补版本族／访问状态，不另建Agent、队列或重复证据存储。

## Goals / Non-Goals

**Goals:** 当前来源生命周期、同事务增量索引、原子批量发布、默认任务隔离、有效期及旧报告关联。

**Non-Goals:** 不默认开启跨任务复用，不自动重跑历史报告，不引入后台删除守护进程、ANN重训、压缩模型或缓存服务。候选维护算法按当前已选索引决定，未采用项有重选条件。

## Decisions

### 1. 版本内容与访问状态分离

独立物理来源表示内容版本，新增lifecycle表保存family、前驱、当前标志、revision、task/group/owner复用范围、生效区间、清理截止及Tombstone。旧内容不就地修改；局部修订要求原parse_version及精确字符范围，生成新全文并走原解析／分块／特征／索引事务。新版本默认继承旧保留策略，不因修订扩大复用范围。当前family切换和批量发布最多20项，同owner advisory锁及预期revision避免迟到覆盖；所有成员同事务。

### 2. 查询可见性而非提示词约束

新来源默认task；task_id为空时仅定位，填入时核对真实研究会话owner。group只在实际选择同组时复用，owner代表用户明确本人跨任务复用。服务端执行器把DB绑定session.id传到RAG，不暴露为模型参数。三通道及BM25的N/DF同时使用生命周期条件；父级／开头扩展和返回前再次核对revision，阻止候选在等待重排时失效。旧无记录资料保留本人显式分组路径，不能在无范围检索时默认扩展。

### 3. 删除、恢复与受控清理

DELETE改为幂等Tombstone，保留原文和索引代际；restore不自动抢占同族当前项，activate需显式预期版本。purge仅允许Tombstone或有清理截止且非当前的版本；cleanup按本人显式请求处理最多20个已到期旧项。事件表不依赖被删来源FK，保留原因／操作结果；不复制正文。旧任务保留证据仍由任务owner访问。产品界面说明永久删除来源不等同删除已完成任务。

### 4. 一致性、缓存与触发

沿用PostgreSQL强一致提交，每次来源访问变更同步增加owner epoch；查询不使用跨请求候选缓存，后续缓存必须带epoch。索引重建用05已有保留特征，不重新训练；直接增加新来源为增量代际，无需全库合并。没有ANN／PQ／新缓存，当前不做重训／压缩／最终一致后台合并，规模或实测维护需求出现再重选。报告措辞、主题和权重不调用来源生命周期接口。外部新采集仍进入原任务ledger，多版本不会自动推广到跨任务资料库。

### 5. 安全及可见性

沿用A2ABreak v1.0全11项增量评估，适用A2AB-03《上下文归属与跨租户隔离》、06《并发状态版本与审批绑定》、08《结构化授权请求与权限不放大》、10《委派环路检测与全链预算》及11《中断任务租约与有界资源回收》的“工程解决方案／验收办法”：实际owner和任务、原文范围、行锁与revision／幂等、同步45秒总期限和20项上限，失败整批回滚。无新Card、Webhook、多跳委派、凭据或等待输入worker；其余沿既有不适用判断。来源和待验证边界见docs/OPTIMIZATION_TODO.md的基线索引。

## Risks / Trade-offs

- [旧版本数量增加] → 保存可见版本清单，显式截止／清理，不自动删除历史证据。
- [旧客户端DELETE语义变化] → 默认Tombstone可恢复；永久清理用明确动作并记录结果。
- [新任务资料未绑定] → 允许保存和定位，界面明确不会被其他任务检索；本人可绑定或选择复用。
- [并发撤权与在途候选] → 记录返回候选revision，返回／扩展前复核，避免把旧缓存结果当当前授权。

## Migration Plan

新增表加入已有初始化及migrate入口，不在启动时批量认领旧owner或分组。新上传写同事务lifecycle；旧记录按原来源owner和显式分组查询，首次维护保存受控记录。全部TODO实现后才加载迁移并做统一端到端，不提前运行代码、SQL或门禁。
