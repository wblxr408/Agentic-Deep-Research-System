# Proposal

## Why

OPT-01 要求将实际取证和用户资料接入变成可追溯、可恢复的数据，而现有会话只有累积证据列表，缺少统一资料版本、重复接入和失败消费视图。上传已有内容去重，但缺少用户选定文件集合／目录后的有界批次交互。

## What Changes

- 复用既有手动来源登记、渠道发现、公开检索和种子配置，新增用户显式选择文件集合／目录后的批量上传、逐项状态及失败重试。
- 在现有会话 JSONB 内维护任务证据接入账本，绑定实际 owner／session，记录归一原文引用、采集时间、来源、版本、复用和冲突；搜索线索与已读正文分别表达。
- 复用既有执行版本隔离、工具重试和预算，新增可读失败／恢复队列；重放同一接入事件不增加版本，重复正文可复用版本但保留事件出处。
- 只读查看本人账本及既有组织样本基线／覆盖，不自动索引网上证据、不跨任务检索或扩大来源权限。
- 为批量、实时、定时、事件触发、全量／增量、CDC、Webhook明确选型和未采用原因；本阶段采用请求驱动／逐项事件，不启用后台同步服务。
- 全部TODO实现后统一端到端验收，实施状态与验收状态分开。

2026-10-27：按完整清单继续补持续接入，先实现用户主动建立的公开网页／文档单源手动与定时同步、条件请求和原资料版本衔接；事件推送与数据库 CDC 独立列待实现，不能由定时轮询代称。现有任务按原范围执行，创建订阅本身不触发联网。

## Capabilities

### New Capabilities

- `task-evidence-ingestion`：任务范围内资料发现、版本化接入、重复消费、失败恢复及接入账本。

### Modified Capabilities

无。项目主规范暂无条目；沿用既有已实施变更的 owner／渠道／预算及组织样本契约。

## Impact

修改现有运行快照持久化、研究只读 API、资料管理界面与上传幂等边界；新增普通账本函数和只读呈现组件。复用 PostgreSQL JSONB、现有上传 API 和源策略，不新增 Agent、数据库服务、常驻同步器或自动对外通知。详细选型与任务由本变更承载，完整目标仍是OPT-01至18及ORG，不缩为本变更。
