# Design

## Context

动机见 [proposal.md](proposal.md)。`RuntimePersistence.persist_runtime_snapshot` 已在 execution fencing 事务中写会话 JSONB；`collected_evidence` 保留原文，`node_outcomes` 保留失败，组织 corpus 已有检索／来源／候选流转。上传有内容摘要去重，但检索范围只有owner且检查与插入分离；DocumentManager只提供单文件。

## Goals / Non-Goals

**Goals:** 为OPT-01.1–01.7建立有界、可恢复、当前主体可消费的资料接入，不重复建设编排、证据库或向量服务。

**Non-Goals:** 不默认采集服务器目录，不新增后台同步器、不把网上正文全部转入永久RAG，不以接入账本证明成果事实或全集。定时／CDC／Webhook是待有实际来源与订阅语义后重新选型的候选，不伪称已连接。

## Decisions

### 1. 任务证据账本复用JSONB

普通函数从实际证据和NodeOutcome生成版本、来源及失败状态。每次运行快照在原SQL事务内复核数据库owner／execution，并合并已保存账本；任务相同但执行变化可以追加合法新事件，旧执行先被fence拒绝。内容按来源与覆盖／格式／解析元数据形成版本，版本保留文字；原文引用指向版本与证据事件，幂等消费不重复复制正文。未观测到来源修改时间时不猜增量窗口。

备选独立数据库表、向量库或消息总线增加迁移和一致性负担，本阶段不采用。原始网络字节当前未统一保留，账本明确保存取得后的归一文字，不扩大“原始资料”承诺。

### 2. 有界批量上传复用原API

前端持有用户选择的File集合和相对目录名，逐项调用既有上传接口，最多20项、串行处理，展示未支持／失败／已提交和复用。停止仅停止下一项；已发出的请求可能提交，因此重试依赖事务幂等。上传在实际owner／分组／内容摘要键上取得事务锁，锁内再次查询有效来源再接入。文件大小和参数在读取、嵌入前检查。目录名只作展示或上传文件名元数据，绝不作为服务端路径。

2026-10-24恢复契约补全：前端原来只保存文件状态，停止后修改分组／用途仍跳过旧配置成功项，却把失败项送入新配置。页面批次现绑定首次实际派发的完整接入请求配置，恢复前精确比较；改变目标、OCR、分块、编码、索引或保存范围／有效期则可见拒绝。显式重列整批只重置支持文件状态，保留所有服务器来源，之后另点开始才按当前配置接入。选择另一文件集合会建立新批次。使用同步ref阻止React状态提交前的重复点击，不依赖按钮disabled作为唯一派发闸口；不新增服务端状态库或另一套权限，原数据库幂等仍权威。未运行本次检查或验收。

### 3. 接入与捕获选型

采用用户请求驱动的单次／批次采集、研究工具返回事件、快照重放增量对账。来源登记复用渠道／种子／手动文本，发现复用现有检索。没有持续更新源或用户配置的周期，故不启动定时同步；没有事务日志访问或事件签名／重放协议，故不启用CDC／Webhook。未来接入需另按真实来源能力设计游标、撤权和幂等协议。此决定覆盖候选比较，不把不适用工具堆进任务。

### 4. 恢复队列是已有任务状态视图

失败来源复用节点结果和工具调用标识展示；重试只通过原恢复流程，在原权限、审批与预算内执行。终止结果进入待人工处理视图，后续成功标记已恢复，历史失败仍可追溯；不新增独立自动消费死信的worker。

### 5. 沿用安全评估

复用组织研究变更及TODO中A2ABreak v1.0全11项适用性评估，无新Agent／A2A。增量执行点为A2AB-03《上下文归属与跨租户隔离》的数据库owner绑定、A2AB-06《并发状态版本与审批绑定》的事务锁与旧执行拒绝、A2AB-08《结构化授权请求与权限不放大》的显式文件选择和既有恢复动作、A2AB-10《委派环路检测与全链预算》的已有预算。引用各方案“工程解决方案／验收办法”章节，具体来源见 [TODO引用](../../../docs/OPTIMIZATION_TODO.md#安全方案引用与规划状态)。其他项没有新增协议／传输／授权行为，沿用既有控制，终验需核实而非宣称官方修复。

## Risks / Trade-offs

- [多版本JSONB增大] → 每个唯一版本只保存一次文字，事件只传引用，不建立嵌入；后续OPT-06生命周期继续管理。
- [嵌入期间同键事务锁等待] → 只串行化同owner／分组／内容；单文件受现有大小与执行超时，避免重复业务写入。
- [停止批次时当前请求已提交] → 状态显示该项真实响应，停止后不发下一项；重新上传仍幂等。
- [旧资料缺元数据] → 显式旧快照投影，缺时间／版本保持未知，不能当新取证。

## Migration Plan

新增JSONB字段随下一次合法持久化建立，不改旧报告或要求迁移。前端继续调用原上传API；回滚界面后单文件请求可继续。全部TODO实现后统一端到端验收，不在本变更先运行代码、模型或门禁。

## 6. 持续接入增量（2026-10-27）

完整目标要求补齐定时与增量采集。新增本人显式配置的单个公开 HTTPS 来源；默认关闭定时，只有选择启用才按间隔在应用运行时调度，也提供本人手动立即同步。允许的网络范围为登记 URL 的同源跳转，复用固定解析／连接的公开网络检查，不携带个人平台凭据。来源只写入本人选择的资料分组，沿现有来源生命周期与索引准入创建或追加版本；历史引用与报告不改写。停止、撤销、来源失效及账号禁用必须在实际写入前再次检查。

一次读取具备独立次数、超时和字节上限；ETag／Last-Modified 仅来自远端真实响应，条件请求返回 304 才认作未变；缺少或不可信时按正文版本比较。传输失败保留旧版本，不能把抓取时间当源修改时间。订阅和单次运行以 owner、版本、运行令牌及数据库事务关联；多实例使用数据库租约和 `SKIP LOCKED`，超过租期、删除订阅或停用定时后的定时迟到结果不得写入，已经提交的版本以请求 ID 幂等。仅切换定时状态时，已明确发起的手动同步继续执行。并发与计划错过不补发无限批次。运行历史记录状态、错误类别、取得时间和来源版本，不保存访问密钥或任意路径。

界面沿资料库风格支持登记、查看、立即同步、调整频率、启停与删除订阅，展示下一次同步、当前状态和最近结果。自动发现与目录上传继续沿用原有入口，不因订阅授予服务器目录访问。此增量不宣称数据库日志 CDC 或签名 Webhook 已完成，后续各自绑定真实来源权限与协议。

增量沿用 A2ABreak v1.0 已有评估：A2AB-03《上下文归属与跨租户隔离》工程1—3在订阅、运行和源版本按 owner 强制绑定；A2AB-05《产物分块校验与断流恢复》工程1—4以有界读取、来源版本及未完成失败记录确保断流不覆盖；A2AB-06《并发状态版本与审批绑定》工程1／3以订阅版本、租约、写入前复核与幂等控制竞争；A2AB-08《结构化授权请求与权限不放大》工程1—4只接受用户配置的同源公开读取；A2AB-10《委派环路检测与全链预算》工程1／3控制每次读取次数、字节和时限。以上是待项目实际验证的方案，不是已验证的安全保证。未新增 Agent 或跨组织委派，其他项沿用既有评估。

## 7. 签名事件触发（2026-10-27）

先接 GitHub 仓库 Webhook：本人对一条已登记的公开来源启用事件触发后，系统提供该来源专属端点和用户生成的密钥；密钥加密保存、可撤销，服务端不从事件正文读取额外 URL、命令或授权。GitHub 按原始请求体计算 `X-Hub-Signature-256`，服务端验签后只接受 push；ping 仅确认连接。参考 [GitHub 验签](https://docs.github.com/en/webhooks/using-webhooks/validating-webhook-deliveries)及[投递规范](https://docs.github.com/en/webhooks/webhook-events-and-payloads)。消息体和接收时间不冒充来源正文与修改时间。

保留 GitHub 投递 ID，同时按密钥代次和签名正文摘要去重；GitHub 签名覆盖正文而不是投递 ID，不能仅依未签名的 ID 防重放。相同正文在该密钥代次内合并；设置事件速率和入站大小限制。若通知发生在该来源读取期间，保留一个待处理批次，当前读取完成后再执行一次；多条待处理通知合并但各有回执，不因并发写入丢失最后一次变化。多实例沿现有 owner／租约／事务协调，重复投递不重复产生业务写入。删除订阅或撤销事件授权将取消未提交的关联运行，用户停用账号后不能提交结果；只切换定时间隔不取消显式事件来源。

GitHub 不提供被签名的投递时间，单靠去重不能证明消息新鲜；此方案的签名、持久正文去重及每来源速率限制不等同于时间戳式完整防重放。GitHub 服务停止或通知丢失时依靠既有手动／定时同步，其他提供方格式和真实 CDC 分开实现。应用需要对 GitHub 可访问的 HTTPS 地址；局域网本地地址本身不会收到外部投递。

适用 A2ABreak v1.0，按各条“工程解决方案／验收办法”落点如下：A2AB-03《上下文归属与跨租户隔离》工程1—3约束端点、密钥及源；A2AB-05《产物分块校验与断流恢复》工程1—4借鉴完整正文验签，本次是单次请求而非分块产物；A2AB-06《并发状态版本与审批绑定》工程1／3约束撤销、幂等及并发；[A2AB-07《Webhook归属验证与受控出站》](C:/Users/wblxr/basic-memory/engineering/security/a2abreak/solutions/A2AB-07%20Webhook归属验证与受控出站.md)工程2／4约束后续同源读取和限额。本次 webhook 是 GitHub 向应用的入站通知，应用不向用户指定回调地址投递任务数据，因此 A2AB-07 工程1／3关于出站回调端点控制权证明不直接适用；入站使用仓库专属密钥、签名正文及仓库身份绑定。A2AB-08《结构化授权请求与权限不放大》工程1—4约束事件仅触发已登记来源；A2AB-10《委派环路检测与全链预算》工程1／3借鉴速率和后续读取额度；[A2AB-11《中断任务租约与有界资源回收》](C:/Users/wblxr/basic-memory/engineering/security/a2abreak/solutions/A2AB-11%20中断任务租约与有界资源回收.md)工程1／2／4约束持久期限、租约到期和迟到写入。事件正文不参与工具或 URL 选择。A2AB-01／02／04／09分别因无新增技能声明、Agent Card、SSE出口和多跳凭据而沿用既有评估。上述控制是待真实验证的工程建议，不是对项目的安全认证。
