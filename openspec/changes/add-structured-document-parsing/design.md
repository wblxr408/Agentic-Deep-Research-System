# Design

## Context

现状及动机见[proposal](proposal.md)。PDF公开取证使用有界pypdf子进程，上传直接抽纯文本；HTML保留出版商citation元数据及正文，必须继续保留该历史署名修复。OPT-01已有任务版本账本和资料事务幂等，可承载解析数据，不另建存储或Agent。

## Goals / Non-Goals

**Goals:** 在既有采集权限内生成有界正文、结构与原位置，支持原生／可选OCR、显式视觉模型解析、表格／图表理解、可选清洗与语义重复候选和人工审核。

**Non-Goals:** 不自动用模型结果改写原文，不自动跟随图片URL，不把图注当已识别图像内容，不把相似度当成果归并依据。模型需本人明确发起，输出为绑定原解析版本的派生观察或建议，未完成时保留缺口；不声称模型输出已核实。

## Decisions

### 1. 统一普通解析数据而非引入解析Agent

新增普通模块输出版本、text、blocks、pages、tables、figures、quality和deduplication。每块保留raw_text和归一变换，源定位使用页坐标、DOCX XML次序、JSON Pointer或文本字符区间；边界及不具备定位的降级明确返回。归一仅处理换行和不可显示控制字符，乱码用替代字符并记录，不删除数学符号或猜修文本。

### 2. PDF结构用pdfplumber，pypdf作明确降级

现有pypdf保留为无布局降级；pdfplumber提供文字坐标、表格单元格和页面图像指针，增加一个依赖解决具体布局缺口。PDF解析继续在既有有限子进程中运行。默认不删除重复页眉，只标重复候选，避免删掉事实。公开读取最多80页／160k字符，私人上传使用配置页数上限；不同上限进入解析profile。官方依据：[pdfplumber](https://github.com/jsvine/pdfplumber)。

### 3. 扫描页OCR显式启用

用户上传选择OCR且服务端配置允许后，原生无文本页才调用本机Tesseract，限制页数、像素与进程时间，记录词框／识别分数及未知。OCR耗时计入解析耗时，不开新模型回路。没有程序／语言包、渲染失败或到时保留页级缺口。CLI参数使用独立argv，临时图像只保存在服务端创建的临时目录，不接受用户命令或本地路径。语法依据：[Tesseract官方说明](https://tesseract-ocr.github.io/tessdoc/Command-Line-Usage.html)。

### 4. DOCX与HTML保留显式结构

DOCX读取有界OOXML，修复ZIP签名、保留段落／表格次序、gridSpan／vMerge以及真实图片关系，不解压到用户指定路径，不跟随外部关系。JSON用Pointer，Markdown保留标题／代码／表格边界。HTML在已有实际取得正文上建立字面定位的结构附注，继续保留出版商元数据；图像alt是来源自述，模型描述未执行。

### 5. 稳定版本与审核

上传metadata保存解析profile、原文结构和质量，幂等键加入解析版本／配置，避免新配置被旧索引误报已处理。解析详情与人工标记沿现有owner API和JSONB，不改原文字。近似重复限制候选对数，标记待复核，不自动删除；本人可选两段文字进行语义比较，结果独立保存，不自动归并。

### 6. 安全和验证

人工结构审核与普通来源metadata更新在同一来源行锁下串行，保护审核历史不被旧编辑覆盖；request_id绑定解析版本与参数，重放不重复追加。此增量采用A2AB-06《并发状态版本与审批绑定》v1.0“工程解决方案／验收办法”，实际并发／重放仍待最后验收。

沿用原A2ABreak v1.0全11项适用性评估。本增量采用A2AB-03《上下文归属与跨租户隔离》的详情／审核owner过滤，A2AB-07《Webhook归属验证与受控出站》的图片URL不跟随，A2AB-08《结构化授权请求与权限不放大》的显式OCR及服务端程序配置，A2AB-10《委派环路检测与全链预算》的进程／页数／像素限制，引用“工程解决方案／验收办法”，具体方案见[TODO](../../../docs/OPTIMIZATION_TODO.md#安全方案引用与规划状态)。无新Agent/A2A、委派、SSE或Webhook，其他项沿用原评估。全部实施后统一端到端，当前不运行任何检查。

## Risks / Trade-offs

- [扫描页识别或表格布局有误] → 保存原位置与质量，等待人工审核，不声称数值已经核实。
- [解析依赖或OCR不可用] → 结构能力降级与缺口可见；原生文字可保留，不假装OCR成功。
- [恶意ZIP或复杂PDF耗资源] → 已知输入大小、解压总量、页数、表格／图像上限及有限进程。
- [位置经过清洗发生变化] → 保留原始块文字、归一规则和规范文本偏移，不以修改后的文本位置冒充原文件字节。

## Migration Plan

新增解析数据进入现有来源metadata与任务acquisition，新profile生成独立来源表示，旧资料不追写。只读详情对旧资料标记未保留结构，可重新显式上传；原报告及任务版本不被覆盖。依赖部署与真实流程验证留到全部实现后的统一阶段。

## 7. 按完整 TODO 补齐模型辅助解析（2026-10-27）

02.1／02.2／02.4：用户在本人资料的解析详情中主动选择 PDF 页面或 DOCX 内嵌图片，并重新选择匹配该来源原始字节版本的文件。服务端在有限子进程渲染所选页面／读取同包图片，只发送选择的图像和有限定位上下文给本人已配置的兼容模型；不跟随外链、不继承其他账号模型或密钥。限制文件、像素、图像字节、次数、输出长度和期限；真实响应须记录使用量，缺失或超出时显示未知／超出，不能把估计当实际。图像文字、版面、图表、图注关系和模型不确定项记录为关联源版本与页码／图像的派生观察，与原生/OCR原文并列，不能伪装为原图已验证数值。初版的多模态输出先供资料查看与后续特征阶段消费，不直接混入原始证据。

02.5／02.6：规则去噪只建立可回溯候选，模型修复与语义比较由本人选择具体块发起、受独立预算约束；响应只生成引用原块和版本的建议，不直接覆盖原文或删除资料。只有用户明确应用修订时才走既有来源版本和引用保留流程；语义相似不等于可自动合并不同来源。

每次操作按本人、来源、解析版本、实际输入与请求 ID 绑定；重复提交不产生第二次模型业务结果，配置／来源变化、撤权、取消或截止后结果不能写入。模型提示不赋予源内容工具或指令权限，严禁把文档内指令作为操作；API报错不输出图片、全文或密钥。保留选定源版本、页／图像或文字区间、模型输出、请求状态与用量，不存上传图像或重复存储比较原文，不将旧解析或旧报告追写。新增能力先标源码完成，真实模型／图像／人工交互全部实现后统一端到端验证。
