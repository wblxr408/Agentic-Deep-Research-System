# Design

## Context

现有认证使用 PostgreSQL 会话、`auth_principals`、密码版本撤销和 owner 约束。个人模型设置使用项目 Fernet 密钥加密；渠道配置由本人的 `ChannelStore` 管理，现有 CLI 凭宿主登录态且仅管理员可用。参见 proposal 及 `docs/MULTI_USER_WORKSPACES.md`。

## Goals / Non-Goals

**Goals:** 维持个人默认隔离，以显式邀请和原拥有者分享组成可撤回的只读空间；邮箱恢复和外部连接在相同用户边界内工作。新增代码只使用现有 Python／PostgreSQL／React 与标准库。

**Non-Goals:** 不让空间成员代用拥有者凭据或改变其研究，第一版不接入无法可靠隔离个人授权的宿主 CLI；不假称 GitHub 以外的平台已经支持授权。没有配置邮件服务时不启用发信，也不以自动浏览器取代真人试读。

## Decisions

1. **账号验证。** 为账号保存已验证邮箱与有限期挑战的哈希，旧邮箱在新邮箱验证前保持有效；邮箱唯一性在事务内约束。使用部署配置的固定 SMTP／TLS 与固定应用地址，单次 code 通过用户输入消费，不从请求 Host 拼接链接，不记录明文 code 或 SMTP 密码。重置请求统一响应，限制来源和目标速率；原子消费挑战、修改密码和提升 session_version，撤销原会话及 API token。发送失败不声称已送达；新挑战替换旧挑战，失效／重复不能改变账号。选择 SMTP 标准库而非绑定单一服务；部署者需提供真实服务。
2. **协作。** 新增空间、成员邀请、显式资源分享三类关系；成员只能看主动分享的本人报告／原文，单独读取时重新验证成员、拥有者、分享和资源当前状态。报告只读，私有引用不自动开放，资源分享被撤回或成员移除后后续请求拒绝。空间只提供目录和授权代理，不把 owner_id 改成共享账号；消息留在应用内，不主动发送邀请邮件。避免把成员身份当作管理员或扩大原私有资源 API 权限。
3. **个人外部连接。** 复用加密存储但不把密钥写入个人配置响应／日志／研究记录，采用固定平台适配器。首个适配器为现有 GitHub 官方 API：仅其固定 HTTPS 主机使用 Authorization，禁止凭据跨域重定向，认证获取的结果至少标为内部／私有并经过现有数据治理。连接选择必须由用户显式启用；普通用户不会读取宿主 CLI 或其他账号凭据，撤销立即影响新请求。未来平台需要各自适配，不能把凭据插入任意 URL 或 shell。
4. **界面与故障。** 账号页面提供邮箱／空间／连接管理，登录页提供找回。清晰显示待验证、已连接、未配置或失败；不展示任何密钥。保留现有语言和四主题。所有源码完成前不运行测试或业务，最后按用户要求统一真实端到端并区分需用户提供的 SMTP、GitHub 授权及真人反馈。

## Risks / Trade-offs

- [邮件配置、送达与风险控制依赖实际环境] → 明确服务配置状态；只在实际用户发起时发送，统一端到端记录真实送达与故障，未配置不能宣称找回可用。
- [共享引用失效或成员变更] → 每次读取重核当前成员和源状态；不缓存可继续使用的私有直链。
- [外部私有资料流向不合适的模型] → 授权结果最低标记为内部／私有，按原数据治理和根预算派发，拒绝不满足条件的模型与出站。
- [历史账号迁移] → 使用可空附加表和幂等迁移，不删除旧数据或要求注册重做；回滚前停止新共享和恢复操作，保留原用户与已有会话语义。

## Security basis

复用 A2ABreak v1.0 已有评估，适用 **A2AB-03《上下文归属与跨租户隔离》工程1—3**（资源／成员／凭据本人边界）、**A2AB-06《并发状态版本与审批绑定》工程1／3**（挑战一次消费与会员／共享变更的事务）、**A2AB-07《Webhook归属验证与受控出站》工程1—4**（固定 GitHub 主机与逐跳限制，不新增Webhook）、**A2AB-08《结构化授权请求与权限不放大》工程1—4**（只读分享与调用许可不扩大）及 **A2AB-10《委派环路检测与全链预算》工程1／3**（外部采集沿原任务额度）。其余方案沿原评估，本变更不新增跨组织 Agent 委派、Agent Card、事件频道或代理身份。方案是待项目验证的工程建议，不能宣称安全验收通过。
