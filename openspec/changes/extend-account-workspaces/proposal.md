# Proposal

## Why

现有账号仅支持用户名和密码，遗忘密码后缺少自助恢复；个人资料和研究虽已隔离，但无法按成员明确共享，外部平台只能使用宿主管理员登录态。TODO 的 AUTH.9 要求在保持原有个人边界的基础上补齐这些能力。

## What Changes

- 提供可选邮箱绑定与一次性验证、通过已验证邮箱重置密码；沿用现有注册，不强制历史账号更改。
- 提供成员邀请／接受与共享空间；成员主动分享自己的研究报告或资料，按空间成员权限读取，撤回和退出立即终止后续访问。
- 提供本人独立的外部平台授权与撤销；先接入已存在的 GitHub 官方只读 API，其他平台清楚显示尚未接入，凭据不得复用宿主或泄露给其他用户。
- 前端在账号页面接入相应操作，中英文及现有主题风格一致；使用受控邮件服务配置，不在仓库保存凭据。
- 源码完成后与其余 TODO 一并执行真实端到端；真人主观体验只能由实际使用者反馈。

## Capabilities

### New Capabilities

- `account-recovery`: 个人邮箱绑定验证、恢复及安全撤销。
- `shared-workspaces`: 显式成员关系、个人资源分享与撤回。
- `personal-platform-access`: 本人外部平台授权、受限使用和撤销。

### Modified Capabilities

无；主规格库目前为空，既有多用户 OpenSpec 作为实现依据。

## Impact

扩展认证数据库、服务端身份和账号界面，新增成员／分享与凭据存储。邮件发送依赖部署者配置的 SMTP 服务；GitHub 接入复用固定 HTTP 来源与根取证预算。个人研究、资料及密钥默认仍由本人管理，管理员不自动获得私有数据权限。
