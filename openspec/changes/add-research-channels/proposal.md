# Proposal

## Why

现有研究采集主要依赖 DuckDuckGo 与通用浏览器，无法稳定使用社交、视频、招聘等平台的信息，也缺少统一的渠道维护记录。借鉴 Agent-Reach 的渠道与有序后端模式，补齐研究上游并把结果纳入现有证据链。

## What Changes

- 注册 16 个渠道，提供结构化搜索、链接读取、RSS 和字幕/转录适配。
- 提供按渠道配置的首选/备选后端、实际内容结果验收、错误分类、有限降级和运行记录。
- 支持研究请求选择渠道，平台前缀或 URL 自动路由；保留通用搜索兼容路径。
- 提供已认证的渠道配置与内容采集 API，按当前用户隔离配置及采集历史。
- 将平台来源、后端与采集时间写入研究证据及工具轨迹；提供维护文档和使用入口。

## Capabilities

### New Capabilities

- `research-channels`: 渠道覆盖、只读采集、有序后端降级、配置维护和证据接入。

### Modified Capabilities

无已有规格。

## Impact

新增 app/channels 与 app/api/channels；修改 SearchAgent、BrowserAgent、研究 API、图节点与前端渠道选择。上游 CLI 由操作员配置，请求处理不安装工具或复制宿主凭据。后续用户已授权本地安装器补齐必要工具、配置 Exa、修复网页搜索/B站/小宇宙并进行真实测试账号采集；平台登录单独由操作员完成。
