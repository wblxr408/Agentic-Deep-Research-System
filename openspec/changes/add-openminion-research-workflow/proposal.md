# Proposal

## Why

当前研究链由 LangGraph 与直接模型客户端驱动，缺少 OpenMinion 实际模型／工具交互证据；Reflection 截断证据开头，最终报告也没有引用支持检查。参赛任务需要沿用组织研究定位，交付可复现、可核查的实际运行。

## What Changes

- 新增本地命令行组织研究入口，单个 OpenMinion Agent 调用已有公开搜索和受控读取，生成证据、报告、执行轨迹及核验结果。
- 明确组织类型、具体对象、主题、时间范围与计划；支持高校、科研实验室、企业的单个或多个对象，不将已有26项跨学科权重规划冒称已实现。
- 增加可单选／多选的来源范围：出版商／会议论文集、DBLP、arXiv、Google Scholar、组织官网。域名清单与实际生效配置随结果保存；搜索结果、初始读取和每次重定向均受范围限制，Scholar仅提供发现线索。
- 按待核验主张在全部证据正文中选择带位置的片段，检查最终报告引用标识、原文引语及模型判定；模型置信度与人工复核状态分开。
- 补齐有界PDF正文、页码偏移、HTML论文链接和同轮正文复用，解决真实任务只能读到摘要、无法检查后部实验限制的问题。
- 提供固定 SDK 版本、依赖安装与复现说明、真实模型运行产物和 SDK 建设性反馈；评估 Cortensor provider 的实际契约与未获访问部分。

## Capabilities

### New Capabilities

- `sdk-organization-research`: 有界 SDK 组织研究任务、工具及产物契约。
- `claim-source-verification`: 主张导向证据选取、最终引用支持检查与人工状态分离。

### Modified Capabilities

无；主规范清单为空，复用现有出站和渠道边界。

## Impact

新增可选 SDK 依赖、app 下研究模块和 scripts 入口；修改 Reflection／Report 的证据消费及核验输出。保留现有应用部署路径，命令行流程不使用跨用户内部资料。新增行为采用最小 TDD 与真实模型任务验证，不执行回归测试。
