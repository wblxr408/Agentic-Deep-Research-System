# Design

## Context

见 proposal.md。现有 SearchAgent.execute_search 可按渠道调用现有采集服务，HttpReader 已实现 HTTPS、DNS 地址锁定、重定向逐跳检查与大小限制。SDK 官方源码 0.1.7 公开 Agent、tool、APIRuntime；runtime 支持独立 home/data、工具 allowlist、每轮步数和工具预算。Reflection 仅取前15条×400字符，Report 同样取前缀，缺最终审计。

## Goals / Non-Goals

**Goals:** 交付完整可复现 SDK 组织研究、真实模型／采集证据、主张原文核验与 Cortensor 适配评估。

**Non-Goals:** 不把另一变更的26项跨学科权重任务标记已实现；本地 CLI 不开放 HTTP 服务、内部知识库、A2A 委派或外部回调。

## Decisions

1. 新增独立 CLI 和薄适配模块，复用公开渠道及 HttpReader。一个 SDK Agent 自行搜索／读取；之后以同一SDK执行无工具的证据综合和核验阶段，使用独立session。真实r5的采集草稿未带引文，格式转换无法补证；r6又在重复检索中耗尽上下文，因此明确分离受限采集与证据综合，用真实原文重新建立引文，而非给错误草稿补外壳。不增加A2A委派链。已有 LangGraph 功能继续使用共享主张核验模块。
2. 每轮使用独立临时 home/data，禁用长期记忆、daemon、MCP、内置可写工具及遥测；Agent 显式只允许注册 search/read 两工具。允许本地用户配置模型端点，公开页面读取仍只经受控出站。
3. 输入使用结构化组织类型、名称、主题、起止年；报告产物包含范围、静态研究计划、实际调用轨迹、证据及审计。复杂实体消歧和评价加权仍由既有组织规划拥有，不能通过提示词声称完整实现。
4. 共享主张核验模块先分句／引用提取，再从所有证据选择相关窗口。引用主张只能对所引证据判定支持；无引文仅给候选，仍标缺引用。模型返回 claim_id、判定、来源标识、精确引语、理由、置信度；可信代码核对引语及位置，不将原文包含等同语义支持。最终输出同时保存机器审计和人工 not_reviewed。预算不足显式未核，不默认为支持。
5. Reflection 使用主张相关片段，Report 在最终文本生成后审计并追加核验摘要，流式片段是草稿，最终结果以完成产物和审计为准。SDK 工作流复用同一核验契约。
6. 依赖作为可选 requirements-openminion.txt 固定0.1.7。普通 OpenAI兼容／Anthropic配置复用现有设置；Cortensor 走 SDK 原生 provider，单独要求其端点／key／session。无权限时记录未实测，不伪造门户或网络推理。
7. 来源配置 `source_scope.groups` 支持 publishers、dblp、arxiv、google_scholar、official 单选／多选；缺省为前四类，显式空选择拒绝。official 必须同时提供 `official_domains`，域名由任务发起者配置，不根据机构名或搜索摘要推定官网归属。出版商／论文集采用版本化、可见的起始域名清单，不能宣称覆盖全部出版商；`publisher_domains` 可显式补充或替换。域名仅接受精确主机及其子域，拒绝URL、通配符、公网后缀及模糊后缀匹配。
8. 普通来源查询附加所选域名条件，同时过滤返回结果；该条件只改善召回，可信代码才执行准入。HttpReader每跳在DNS解析和连接前执行同一范围判定；种子、工具读取和响应终点再核对。模型或网页无法修改范围。Scholar只返回线索，不读取正文或分配引用；DBLP读取仅标注元数据用途，arXiv标注预印本，技术事实仍须正文支持。不会自动绕过登录、验证码或付费墙。配置快照保存清单版本、实际域名及来源用途。CLI接入本轮完成，网页选择面板仍由组织规划后续实现。
9. 为解决真实论文取证失败，原文读取支持PDF：复用已有pypdf依赖，解析放在受CommandRunner时限、输出上限和进程回收管理的子进程；不执行PDF脚本，不绕过授权。单文件下载上限32MiB、研究读取累计64MiB、解析最多80页、正文保留160000字符，保存页码偏移与截断状态；扫描件无文字明确报错。真实InvisiFlow正式版约26MB，原4MiB预算仍无法容纳，故按实际文档上调到32MiB，仍保留下载、解析、字符和总时限。HTML返回范围内论文链接。同一运行重复读取相同来源复用保留正文，可按不同focus取片段，仍计算工具次数。
10. 主张提取忽略Markdown表头、代码块和citation_notes元信息，保留实质表格行；保护vs.等常见缩写，避免割裂一个带引用的技术比较。不会因模型高置信或存在引用而跳过整条主张的语义核对。
11. 一次read_source可读取HTML及其首个范围内非slides PDF，各自有独立证据与引用标识；最多额外读取这一份关联文档，计入同一字节与时限预算，linked_paper轨迹明确结果。重复页面复用已保留的两个来源，失败关联不无限重试。向模型只返回相关页码和紧凑片段，完整页码及正文仍保存供审计。综合阶段接收有界来源清单、主张片段和采集失败，而非仅接收可能无引文的草稿；最终只审计综合后的文本，采集／综合run标识与统计分开。

12. 真实r8暴露综合装配仍可能耗尽SDK决策预算；当前来源正文／相关片段合计24000字符、草稿1500字符、主张窗口12000字符，完整原文不因此删改。数字引用[1]与[citation:1]按相同证据序号核验，SDK输出规范化显示且保留模型原文；局部选取的片段必须重标为全轮引用编号，避免第二来源被错误绑定第一来源。采集状态在综合前保存，异常正文单独保存，不覆盖采集草稿。
13. 真实r9暴露中文主张与英文论文的词面匹配不足、复合主张跨段落条件缺失。核验先为中文待核主张生成有界英文检索词（最多10项／批、600字符／项），再在已引来源全文选择最多3个相关窗口；查询不是事实或权限，不允许扩大引用来源。翻译失败回退原主张，仍记录失败和预算，不默认为支持。
14. 初审出现待核项时，在同一根时限内至多执行一次无工具证据修订，保留initial_report/initial_audit及plan_adjustments原因和状态；修订必须保留原对象、日期及研究问题／方法／结果条件／后续验证范围，缺证则partial，不能靠删除必要内容过关。修订后重新审计实际最终正文，不复用旧审计。不设无限反思循环。

15. 真实r10仍混合多项结论和范围元信息，故综合输出改为带organization/work/facet/statement/citation_ids的原子研究事实，以及questions/gaps/missing_requirements；程序生成Markdown和范围，不要求模型写整篇版式。每项工作必须覆盖发表归属、问题、方法、成果，缺失组织／必需维度／问题／有效引用则coverage_missing非空。终审只核验明确标记的研究事实；范围由真实请求和采集记录生成，问题和取证缺口明确标为建议／模型说明，不冒称已验证。completed要求范围覆盖满足、所有研究事实通过终审、真实采集及根预算条件同时成立，不能再用“至少一项支持”替代完整交付。保留旧输出形态的内部兼容消费，不据此降低新SDK结构契约。
16. r11的最后一项引语仅有PDF换行差异。代码先精确匹配，再仅归一化空白并映射回保留原文偏移；保存quote_match和source_quote，不改变词、数字、单位或标点。语义判定仍由模型给出，空白匹配不是支持证明。同轮模型擅自把未要求的全量普查列为必需项，故模型missing_requirements仅保存为model_missing_requirements建议；完成条件由真实请求、组织、四类事实维度、问题和有效引用的代码检查拥有，不能由模型扩张验收范围。
17. r12因综合输出7个问题超schema上限而终止；SDK0.1.7的output_type仅在返回后校验，不自动传schema或重试。当前综合／修订消息显式附阶段契约，各阶段仅当AgentOutputValidationError且剩余超过15秒时可进行一次无工具格式修复，附schema及失败原文，要求保留事实和引用。原文与恢复状态保存，修复结果仍通过覆盖及语义核验；二次失败终止，不重采集。失败调用的统计无法从SDK异常取得，不能宣称成功返回的统计包含失败调用成本。
18. r13发现重复长标题可能挤掉后部限制窗口，改用来源内窗口逆频率对常见词降权，仍仅检索已引来源和保留偏移。核验请求短、连续、保留断词的原文引语，不为匹配方便删除原文连字符；语义判定只检查实际主张，正确的定理下界不必复述未声称的上界。原文包含与语义支持仍是不同判断，真实失败目标及整轮运行分别记录。
19. 整篇SDK复核暴露instructions的字段契约未稳定传入，当前同时在调用消息显式给出核验任务及JSON形状。冻结报告A／B因results/verdict形状失败，C有效输出12/14；增加多窗口的未覆盖条件优先和最多400字符后文后，D为14/14，保留原采集partial身份，不声称新采集或重复稳定性。最终审计仍检查原文偏移及每项语义，不凭有效JSON判真。
20. r14修订仍超SDK决策预算，故修订仅携带prior_findings和来源元数据，问题合计最多12000字符、每项至多3个片段，保留遗漏片段数及问题标识；不重复全份来源包及渲染报告。冻结失败输入的真实目标B得到有效结构及完整必需维度，5957输入tokens／1117输出tokens。完整原文留在evidence；最终审计不因输入缩减而减少覆盖要求。
21. r15仍因SDK散文输出和引语转写错误为11/14，故当前核验模型选择本主张已提供的excerpt_id，由代码附原文及偏移。未知编号、跨来源编号即使附正确旧式引语也拒绝；旧式quote继续保守匹配。该锚点仅证明定位，语义支持仍由模型检查全部条件，人工状态独立。此为A2AB-08权限不放大在来源引用消费处的增量边界。SDK结构异常在根预算内最多重试一次无工具JSON，保留失败原文与恢复状态，二次失败待核。当前片段消费3项RED后3passed1.14秒；格式恢复2项RED后2passed7.13秒。最后一次原命令曾因Windows进程初始化失败而未执行，未计作通过。

### Security baseline assessment

本次采用 A2ABreak v1.0 本地实验方案，不宣称 A2A 官方修复。方案引用均为 Basic Memory main 的工程解决方案／验收办法章节。

| ID / 标题 | 本次执行点和验证范围 |
| --- | --- |
| A2AB-01 技能声明验证与委派准入 | 不载入外部 skill，不委派；工具由可信代码固定登记 |
| A2AB-02 Agent Card可信密钥与身份绑定 | 无远端 Agent Card，不适用 |
| A2AB-03 上下文归属与跨租户隔离 | 每次临时目录和新 session，公开资料专用；不连接内部用户数据 |
| A2AB-04 长连接撤权与事件出口鉴权 | CLI 无 SSE 或对外长连接；既有 API 不新增共享出口 |
| A2AB-05 产物分块校验与断流恢复 | CLI 完成后写结果，失败保留失败状态，无分块恢复协议 |
| A2AB-06 并发状态版本与审批绑定 | 每次独立结果目录，不恢复运行，不共享审批状态 |
| A2AB-07 Webhook归属验证与受控出站 | 复用 HttpReader，只读 HTTPS、锁定公共地址、逐跳检查；新增所选来源域名在每跳连接前准入；无 webhook |

| A2AB-09 多跳主体溯源与凭据防转用 | 无多跳凭据转发，模型密钥只交配置的模型端点 |
| A2AB-10 委派环路检测与全链预算 | 无委派环路；SDK步数、工具次数、截止时间与读取大小同时受限 |

## Risks / Trade-offs

- SDK依赖较多且仍在迭代 → 可选固定版本，记录实际安装与兼容问题。
- 语义支持是模型判定 → 精确引语与偏移可查、人工状态独立，不声称真值保证。
- 搜索失败或网页缺正文 → 输出可用证据及缺口，失败状态不冒充完整任务。
- 大量主张超预算 → 明确核验范围与遗漏，保留完整引用索引。

## Migration Plan

先固定行为用例观察RED，再实现共享核验和SDK工具运行，完成真实模型任务及SDK反馈。可选安装不改变现有部署依赖；退出新入口即可回退。只运行当前变更最小行为用例及相关规范／构建检查，不执行回归。
