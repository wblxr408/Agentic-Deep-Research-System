## Purpose

允许独立研究者注册并使用各自的研究工作区，保持账号角色、个人资料、研究产物和运行配置在请求、后台执行与界面上的一致归属，同时提供有限且明确的管理员管理能力。

## ADDED Requirements

### Requirement: 普通用户注册

系统 SHALL 在初始化完成且注册开放时允许用户名/密码注册，注册身份 MUST 为普通用户，拒绝客户端指定角色和归属。用户名大小写统一，重复账号返回 409；密码长度及字节限制在服务端实施。

#### Scenario: 新用户进入个人工作区
- **WHEN** 新用户名提交有效密码
- **THEN** 返回 201、建立会话、身份为 user，个人资源列表为空。

#### Scenario: 拒绝注册提权与关闭期间注册
- **WHEN** 注册请求包含 admin 角色或注册已关闭
- **THEN** 分别返回 422 或 403，不创建账号。

### Requirement: 管理员与普通用户分权

系统 SHALL 仅允许管理员列出账号、启停其他账号、修改其他账号角色及调整注册开关；普通用户直调管理 API MUST 返回 403。系统 MUST 保留至少一个活动管理员，账号权限变化后撤销原有会话及 token。

#### Scenario: 普通用户无法管理账号
- **WHEN** 普通用户请求管理账号或注册策略
- **THEN** 返回 403，数据不发生变化。

#### Scenario: 禁用账号
- **WHEN** 管理员禁用其他账号
- **THEN** 该账号现有会话失效，重新登录被拒绝，其已有资料保留。

### Requirement: 个人资源隔离

系统 MUST 从当前会话决定 owner，研究任务及流、报告及图表、引用和保留原文、资料/分块、模板、权重预设、Skill、渠道和备份均保持按 owner 授权。管理员身份 MUST NOT 自动绕过私有资源归属。

#### Scenario: 猜测其他用户的资源标识
- **WHEN** 用户或管理员请求另一个用户的任务、资料、报告或 Skill 标识
- **THEN** 返回 404，列表与导出不包含该资源。

#### Scenario: 不同用户使用相同 Skill 标识
- **WHEN** 两个用户分别保存相同 slug 的 Skill
- **THEN** 各自成功且读取/修改只影响自己的版本。

### Requirement: 模型配置执行隔离

系统 MUST 将每个用户保存的模型及路由配置应用于该用户的请求和后台研究，不允许另一用户修改/重置配置改变当前任务的配置上下文。新用户 MUST NOT 读取或调用管理员的环境凭据。

#### Scenario: 并行配置与重新登录
- **WHEN** 用户 A、B 保存不同模型配置并交错请求或退出重登
- **THEN** 两人的配置及实际调用上下文各自保持一致。

### Requirement: 注册与账号界面

界面 SHALL 提供明确的登录/注册入口、当前用户名及角色、退出登录及管理员管理入口，沿用现有主题；普通用户不显示管理入口。退出及身份变化 MUST 清空前一身份的私有缓存和显示状态。

#### Scenario: 同一浏览器切换账号
- **WHEN** 用户退出后以另一个账号登录
- **THEN** 旧任务、报告、资料、草稿及配置不再显示，新账号获得自己的工作区。

#### Scenario: 跨标签与迟到响应
- **WHEN** 一个标签退出或切换账号，而另一标签仍有旧账号请求在途
- **THEN** 标签同步当前认证，迟到的旧请求不恢复旧身份、不覆盖新账号缓存。

#### Scenario: 弱网与认证恢复
- **WHEN** 认证请求断网或超时后恢复连接
- **THEN** 私有内容在身份未确认时保持隐藏，用户可重新连接并只看到当前账号内容。

### Requirement: 保留旧部署

增量升级 MUST 保留原管理员身份、已有会话和资源归属；幂等升级 MUST NOT 将后续注册用户提升为管理员。

#### Scenario: 旧单管理员部署升级
- **WHEN** 现有部署应用新版本且再次初始化架构
- **THEN** 原账号仍为管理员、已有资源归属不变，新用户仍为普通用户。
