# Design

## Context

认证使用 PostgreSQL 持久会话及版本撤销，首次创建账号绑定历史无 owner 数据。研究/资料/备份/模板/权重/渠道/Skill 已有 owner 查询。缺口是单管理员假设、全局模型缓存、Skill slug 全局唯一，以及前端没有账号切换和缓存清理。

## Goals / Non-Goals

**Goals:** 注册后立即进入个人工作区；普通用户与管理员权限在服务端区分；数据库归属延伸到后台执行和浏览器显示；原账号、会话与数据保留。

**Non-Goals:** 本次不增加企业共享空间、OAuth、邮箱服务或管理员读取他人研究的入口；原研究质量优化继续暂停。

## Decisions

1. 继续使用现有不可伪造的会话 Cookie/API token。role 为 `user`/`admin`，每次请求从数据库读取；注册请求拒绝 role/owner 等额外字段。首次初始化与注册共用事务锁，初始化前注册返回 409；注册账号永远为 user。
2. 新增幂等增量 SQL：旧部署最早账号成为 admin，其余旧账号为 user；新注册显式 user。仅 NULL 历史角色参与迁移，不在重启时提升已存在普通账号。已有资源 owner 不修改，历史孤立数据仅归原管理员。
3. 注册开关存在数据库，管理员可调整；部署环境还能全局关闭。管理员只能管理账号状态和角色；保留最后一个活动管理员，禁止修改自己的权限。禁用/改角色撤销已有会话/token，活动流继续使用原授权核验。
4. 模型配置保持每用户数据库记录，取消跨用户全局缓存。请求和后台研究显式加载 owner 的配置至 ContextVar；线程继承上下文。环境模型仅供管理员/显式本机模式使用，新用户不继承管理员密钥；未配置时研究启动返回可理解的错误。失败不回退到别人的配置。
5. 普通 API 始终按自己的 owner 授权，即使请求者为 admin。列表不返回他人记录，猜测他人的 UUID 返回 404。Skill slug 唯一约束改为 `(owner_id, slug)`，渠道状态继续使用 owner UUID 文件。使用部署级 CLI／浏览器登录态的渠道命令仅管理员可调用；该检查放在渠道适配入口，普通资料解析仍可使用通用受控子进程。
6. 前端增加相同风格的注册页与账号菜单、个人/管理页。退出和身份变化清空查询缓存及挂载的私有组件，移除 URL 任务标识；跨标签退出通知触发重新认证。只存不含凭证的退出通知，密钥不进入 localStorage。

权限设计参考 [OWASP Authorization](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html) 的默认拒绝、每请求授权与资源归属核验；注册节流参考 [OWASP Authentication](https://cheatsheetseries.owasp.org/cheatsheets/Authentication_Cheat_Sheet.html)。本次不改变 Agent/A2A 架构。

## Migration Plan

部署前保留现有数据库与配置；增量迁移在事务中运行，两个入口使用同一 SQL。先迁移身份角色及 owner 命名空间，再部署 API 与前端；新版本读取原 Cookie，无需重置管理员。角色迁移只执行一次。回退应先关闭注册、停止新增账号，再回退到兼容多用户数据的版本，不能回滚为原来的全局配置执行。

## Risks / Trade-offs

- [配置需要每请求/后台加载] → 优先保证用户绑定，暂不增加多进程缓存失效协议。
- [开放注册有资源消耗] → 注册与初始化节流，普通用户使用自备模型配置；管理员可关闭注册。
- [无邮件服务] → 账号采用用户名/密码，界面不提供不可用的找回密码入口。
- [既有测试限制] → 仅进行本次多用户功能真实服务端到端操作，不运行回归、构建或探针；实际覆盖与缺口单独记录。
