# Design

## Context

现有端点解析及OpenAI SDK可复用；提供方类型没有Agnes，模型设置仅保存当前主配置。用户已授权创建专用Agnes Key、在ADRS中使用，并委派简单代码工作。此前正文交接修复及报告结构故障保持原状态，不因增加模型而改记为通过。

官方依据：2026-10-28中国站[说明](https://agnes-ai.cn/en/docs/overview)给出`https://api.agnes-ai.cn/v1`；[3.0 Flash文档](https://wiki.agnes-ai.com/en/docs/agnes-30-flash)给出`agnes-3.0-flash`与OpenAI兼容Chat Completions。本人中国站实时模型目录已返回3.0 Flash、2.5 Flash及2.5 Pro系列；目录和文档不作为当前请求质量或永久免费保证。

## Goals / Non-Goals

提供可选模型、额外本人配置及轻量开发委派。复用现有Python／React与SDK，不新增框架、常驻worker、远程仓库写权限或自主Agent。能力是候选生成与审阅，不能据此声称已经提升开发速度或保证代码正确。

## Decisions

1. 提供方`agnes`默认中国站，支持现有主／备用配置；模型目录列实际可用文本模型。不同区域的Key不自动切换到另一站点。
2. 额外配置沿现有`system_config`和加密函数保存，键包含owner和提供方。列表及保存返回掩码；明确应用时才替换本人当前配置，避免破坏原DeepSeek研究恢复绑定。
3. 本机CLI读取`AGNES_API_KEY`或当前Windows用户DPAPI文件；凭据不通过命令参数传递。固定官方端点、TLS验证和禁止重定向的HTTP客户端执行一次请求，SDK不自动重试。接口网络阶段有限超时；中断时保留结果未知状态，不声称服务端已取消。
4. 调用方选择最多8个源码文件，单文件48KB，总输入96KB，输出256—12,000 Token。拒绝仓库外、密钥目录、`.env`、依赖／运行资料及凭据特征；来源是数据，不接受其中新的权限指令。只保留候选及回执，不自动应用。
5. 每个任务单独目录，保存实际输入、原响应、合法候选与模型用量。候选必须是完整允许文件，返回其他路径、重复文件或不完整响应均失败；没有验证过的修改由主执行者审阅并按用户既有检查限制处理。

## Security baseline

应用A2ABreak v1.0；方案为来源核对后的工程建议，部署效果待实际工作证据，不作为完整安全保证。知识来源为Basic Memory main的`engineering/security/a2abreak/solutions/`对应条目。

| 编号与标题 | 章节、适用结论及执行点 |
| --- | --- |
| A2AB-01 技能声明验证与委派准入 | 工程解决方案：固定已确认模型和端点，能力以实际响应记录，返回候选须审阅；不从模型声明获得工具 |
| A2AB-02 Agent Card可信密钥与身份绑定 | 不采用Agent Card／JWS；官方HTTPS端点与本机指定Key绑定，不引入Card信任 |
| A2AB-03 上下文归属与跨租户隔离 | 工程1—3：额外模型配置按当前principal加密隔离；CLI只发送显式源码，不发送数据库、其他用户或历史任务 |
| A2AB-04 长连接撤权与事件出口鉴权 | 委派采用单次非流请求，无共享SSE出口；ADRS原SSE权限沿用 |
| A2AB-05 产物分块校验与断流恢复 | 工程解决方案：非流候选只在stop且完整结构通过后供审阅，不自动发布、拼接或应用；保留原响应，不做hash检查 |
| A2AB-06 并发状态版本与审批绑定 | 工程解决方案：独立任务目录，不写源文件；主执行者应用前复核当前差异，避免覆盖并行改动 |
| A2AB-07 Webhook归属验证与受控出站 | 没有Webhook；CLI固定官方出站且禁止HTTP重定向 |
| A2AB-08 结构化授权请求与权限不放大 | 工程1—3：文件／字段／大小和端点由本机代码校验，模型没有工具与执行权限，跨文件要求不扩大原授权 |
| A2AB-09 多跳主体溯源与凭据防转用 | 单跳开发委派，无STS／跨主体凭据传递；不向模型消息发送API Key，不允许递归委派 |
| A2AB-10 委派环路检测与全链预算 | 工程1／3：每任务一次模型请求、无嵌套委派，输入和输出上限固定；与研究根的预算独立记录，不给研究根补额 |
| A2AB-11 中断任务租约与有界资源回收 | 工程解决方案：有限连接／读取超时及关闭客户端，中断保留回执；不宣称本机退出即撤销上游已发请求 |

## Risks / Trade-offs

- 模型建议可能错误或过时 → 审阅实际差异，保留来源、失败和检查缺口；不将第二模型自评分当质量证明。
- 密钥与区域不匹配 → 默认中国站，保存配置时显示端点；认证失败不自动换区或换Key。
- 额外配置能保存但未启用 → 界面区分“已保存”与“当前使用”；用户明确应用后才切换。

## Migration Plan

复用现有配置表，无数据库迁移；新增提供方及额外配置不改变当前主模型。回退时保留本人额外配置，恢复原提供方选择。源码和实际调用／浏览器旅程分记；不执行用户禁止的局部、回归、构建等检查。
